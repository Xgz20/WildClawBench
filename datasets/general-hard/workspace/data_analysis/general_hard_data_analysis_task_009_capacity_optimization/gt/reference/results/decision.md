# 单周期供货计划交接

本分配满足当前全部路线、最小批量、最低服务、工厂件数/工时、共享物料和预算硬约束。无法满足全部65件需求。依次固定高、中、低优先级最小缺口0、7、22后，最低费用为4813.55元，预算余量186.45元；计划交付36件。

```text
priority1_unmet: 0

production_cost: 3528.10
transport_cost: 562.15
setup_cost: 393.30
activation_cost: 330.00
total_cost: 4813.55
budget: 5000.00
budget_slack: 186.45

```

高优先级22件全部交付。中优先级交付14件，S06缺3、S08缺4；其余中优先级满足。低优先级四种商品共22件暂未安排。工作簿保留36条路线，0量路线及禁止路线仍列明，避免隐藏遗漏。

## 全需求不可行与缺口界

工厂总件数上限17+16+15=48，小于需求65，单凭该界已知至少缺17件。更强的物料界由两条共享物料约束相加得到：M1供应41、M2供应31，配方中每件成品的两种物料消耗系数之和均为2。因此交付量至多floor((41+31)/2)=36，至少缺29件。这是按给定配方的约束加权，不把某一种物料单位直接当作成品件数。

```text
certificate_kind: combined_material
full_demand_units: 65
combined_supply_units: 72
min_material_coefficient_per_item: 2
finished_units_upper_bound: 36
minimum_total_unmet_bound: 29
source_file: capacity.xlsx
source_locator: 共享物料 M1/M2；单件耗料 S01-S12
```

当前可行方案达到36件，说明这个总件数界可以达到。高优先级缺口的下界为0且已达到；高优先级固定交付22件后，中优先级至多交付36-22=14件，所以21件中至少缺7件，当前也已达到。前两级已占全部36件可用界，低优先级全部22件缺口随之确定。不能在相同总缺口下改为少交高优先级、更多交低优先级，再把更低费用称为更优。

## 条件最低费用和资源取舍

费用阶段在固定(0,7,22)缺口向量后求最小值。作者参考分别采用36整数数量+36开线二元+3工厂二元的HiGHS模型，以及完整枚举每SKU合法整数分配选项再做二元选择的CBC模型；两条独立建模路径四阶段一致。费用原始可行值及最优界均对应481355分，按源整数分复算全部费用。完整求解日志保留在作者验收材料；这不是实际工厂执行或经营收益证明。

三厂各收一次启动费110、130、90元，合计330元；路线开线费只在正生产时收取，合计393.30元，运输562.15元，变动生产3528.10元。不能按12个SKU重复收工厂启动费，也不能漏掉开线/运输费。最小批量按启用门槛核对，合法整数4可满足最小批量3，并不强制是3的倍数。

A厂使用12件/16工时，B厂14件/15工时，C厂10件/17工时。B、C工时分别达到15、17上限；M1和M2分别用满41、31份供应。部分工厂仍有件数或工时余量，但共享物料及路线/批量约束共同限制补货；预算有186.45元余量也不解除这些硬约束。不能把不同工厂的闲置资源混用，或给每厂重复分配整份共享库存。

来源为demand.csv的S01-S12、capacity.xlsx的工厂A/B/C、路线全部plant_id×sku_id、共享物料M1/M2与24条配方，以及costs.csv的36条路线费用。constraints.md规定优先级、最低服务、预算和费用计数方式，未引入外包、加班、税费、跨期库存或未提供资源。

分配方案的蓝色units是当前整数决策，费用/资源/缺口和检查由它联动。修改数量会显示新的核算和违规，但不会自动再次求最优；业务约束改变后须重新求解并复核全部字典序目标。原四份输入只读，产物均在results；本次仅为合成计划，没有真实下单、通知、付款或生产指令。
