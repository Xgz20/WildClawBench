# Windows Harness 母盘与 wgui 接入

以用户指定的客户端为被测对象。交付覆盖其请求的母盘、wgui 代码和分层验收回执。用户只要求方案、母盘或驱动时，沿所需阶段实施。

## 确定输入和实际基线

- 确认产品名、运行形态和模式，以及评测用的模型或档位。安装包、版本、支持的 Windows 架构和认证方式优先从已批准制品及产品资料中核实。目标客户端名称是开展调查的起点。
- 对接 AgentCube 或 wgui 时，先读本机 `~/Tool/AStudioEval/context/source-map.md`，再读评测框架的 `docs/guides/agentcube-source-navigation.md`。从用户指定的基线模板或当前维护方配置查到实际命名空间、镜像 digest、WAA 修订和构建主机。源码地图用于定位代码。
- 根据目标找到官方或公司已批准的安装源、产品认证入口和一个可验证的最小任务。只有缺失信息会阻止当前阶段时才询问，例如无法读取基线、必须由用户操作 SSO，或尚无可用的运行时凭据配置。回复中使用脱敏证据。

## 选择实施阶段

1. **母盘可行性和制作**。从基线只读派生工作盘，在 Windows 交互用户下验证目标客户端。固化后以全新实例复验安装状态、启动行为和 wgui 健康。读取 [母盘制作](references/golden-image.md)。
2. **wgui 接入**。在 Windows 实机或验证 VM 观察产品 UI 和原生轨迹，沿已安装客户端实现可验证的配置、工作区绑定、发题、终态与采集。按目标 checkout 的契约接通正常命令入口。读取 [wgui 适配与实机验证](references/wgui-adapter.md)。
3. **镜像、模板和平台**。按用户授权的环境发布镜像和新模板，核验实际启动的实例。若请求评测平台接入，另外验证平台的 Harness 能力、执行器、模板绑定、单题封存和回收。读取 [发布和验收](references/agentcube-validation.md)。批次执行可调用已提供的 `execute-sandbox-e2e`。

源码变更优先使用独立工作树和功能分支。历史批次按其冻结执行器和镜像身份读取。创建沙箱或发题结果不明时，先核对原批次、会话和远端作业的持久化记录，再判断是否能安全恢复。

## 交付

报告实际达到的阶段。列出基线与新母盘的标识、客户端版本、wgui 改动和测试证据。已发布时补充镜像 digest 和模板标识。已跑真实用例时附批次与会话身份、产物、原生证据、备份摘要和释放结果。注明恢复过的阶段、证据缺口，以及确实需要用户执行的操作和当前停点。
