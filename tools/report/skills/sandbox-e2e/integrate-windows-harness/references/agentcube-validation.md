# AIO 发布、模板绑定和验收

## 发布镜像与 AgentCube 模板

1. 依照目标 WAA 的 `docs/Aio-Image-Guide.md` 构建。先验证本地镜像的启动、wgui 代码、母盘与元数据，再向用户指定或项目已配置的仓库发布新标签。若同一镜像已发布，校验已知 digest 并复用制品。
2. 在 `waa-agentcube` 查 `README.md`、`templates/README.md`、`createWindowsCR_private_auth_a.py` 和基线模板记录。确认 AgentCube 节点能拉取的镜像引用，固定 `tag@sha256:digest`。公司内库与消费仓库通过同步分发时，核验消费侧 digest 或实际模板拉起和内容证据。使用当前脚本支持的 `--print-spec` 预览并核对名称、命名空间、资源和镜像。AIO 省略宿主盘挂载参数；挂载式镜像依托实际宿主存储。
3. 按授权向目标命名空间用新名称注册，记录 API 回执、模板 YAML、WAA 完整提交和镜像 digest。当前仓库支持用 `--register-only` 注册，用 `--skip-register` 启动已有模板验收。若同名模板已存在，核对其绑定和回执。已知绑定一致时直接复用，版本变化走新模板并保留历史绑定。
4. 从新模板实际创建一个会话。查询会话模板身份，核对运行中的镜像或控制代码摘要、Windows 客户端版本和端到端通道。只回收本次会话并确认释放。母盘重启、本地 AIO 冒烟、模板注册成功、AgentCube 会话可用分别记录。

## 连接实际评测环境

按用户指定的本地、测试或生产入口核对能力接口、执行器修订和当前模板状态。若已有 ChatGPT 或其他目标 Harness 的驱动能力，发布对应能力条目和独立模板绑定，加载运行时网关配置及认证。缺少驱动或平台接口时，按相应仓库的正式发布入口处理，并核对活动作业和冻结发行路径。平台新批次可用的 Harness 能力、AgentCube 会话模板和仓库镜像分别验证。

通过实际评测入口提交一个有清楚输出的冻结用例，预检时锁定 Harness、namespace、模板、digest、模型、档位和执行器修订。记录批次、attempt、会话和远端 job，沿原批次观察。至少验收以下结果：

- 真实客户端接收正确的任务并生成预期文件，原生会话和终态与本次任务相符。
- 运行后进程完成收口，工作区及轨迹封存，原始备份通过摘要校验。
- AgentCube 确认释放同一会话。若范围含平台导出或对象存储归档，下载平台产生的 ZIP，并核对归档对象、下载件和包内原始备份的摘要。
- 发生故障时区分发题、执行、采集、回收、导出和归档。原任务已经完成时沿原执行恢复。导出读取器需修复时，用冻结原件回放，保留原执行器身份及失败记录，并通过受支持的恢复入口重做导出。

只在需要平台验收时提交用例。最终给出已完成哪一层、对应回执和用户需要操作的实际环节。一个通过的样本可验证链路；并发和全数据集覆盖按相应请求另外验收。
