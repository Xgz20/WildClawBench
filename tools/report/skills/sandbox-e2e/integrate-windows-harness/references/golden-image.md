# 从现有 Windows 母盘派生新 Harness

## 找到实际运行资产

在 WindowsAgentArena 的构建 checkout 阅读 `docs/Golden-Image-Guide.md`、`docs/Aio-Image-Guide.md` 及对应的构建脚本。结合模板台账、镜像 manifest 和实际配置选定制品。检查构建宿主可用的 KVM、存储空间、读取权限及专用 staging 目录。

确认基线是 AIO 内置母盘还是挂载式方案。AIO 通常包含 `/storage/golden.qcow2` 和 `/storage/meta-template`。挂载式方案由模板指定实际宿主存储。派生时沿用对应的 Windows build、区域设置、固件模式、磁盘尺寸和元数据文件集合，具体以基线和当前打包契约为准。校验基线 SHA-256，记录基线模板、镜像 digest 和构建输入。

## 安装和封存

1. 从基线只读创建一次性可写 overlay 或隔离副本。为构建和验证实例使用不同的容器名、端口和状态目录。按当前 WAA 指南复制该实例需要写入的固件和启动元数据。
2. 用批准的 MSI、EXE、MSIX、Store 或公司安装介质完成安装。固定版本并记录安装包摘要，按产品要求检查签名、依赖和许可。用运行 wgui 的 Windows 交互用户实测启动入口。对于 MSIX/Store 包，分别核对机器预配、该用户的包注册及启动标识。安装在管理员会话里成功时，仍需复验测评用户可启动。
3. 把一次性安装和每会话认证分开。API 密钥、访问令牌及会话配置通过受保护的运行时通道注入。需要 SSO、MFA、Store 许可或人工接受条款时，使用已授权的验证实例，记录用户需要完成的具体画面和验收信号。依赖预置认证状态的方案须先确认其授权范围、克隆隔离和轮换方式。
4. 退出应用并优雅关闭 Windows，等待 QEMU 退出后再固化磁盘。按实际方案 flatten overlay 或转为独立 qcow2。用 `qemu-img info` 核对格式、尺寸和 backing，运行 `qemu-img check`，需要确认内容等价时对关停后的盘做 `qemu-img compare`。固化输出设为只读，计算盘和元数据摘要，保留基线到回执。
5. 从固化资产启动一个新的可写实例，确认 Windows 能正常开机，交互用户仍能启动该版本，wgui 健康且能收发见证文件。用该实例核对首次启动、重启和默认的工作区行为。回收临时实例并记录结果。

## 判断哪些层需要更新

新增客户端、升级盘内软件、增加 Windows guest 的依赖或改动启动环境时，更新母盘。复用现有母盘前核对依赖和启动方式仍匹配。wgui 纯源码更新通常可只重建容器代码层。当前 WAA 常把源码分别放在容器侧 `/wgui` 和 Windows 共享侧 `/shared/wgui`，两份都要核对，最终以选定镜像的布局为准。

构建上下文按 WAA 指南使用允许列表，包含所需母盘、元数据和代码。将安装临时文件、日志、认证输入和运行产物留在 staging。打包回执记录母盘 SHA-256、客户端版本、控制层提交和实际镜像 digest。
