# wgui 产品适配与实机验证

## 从实机观察到代码

在目标 WAA checkout 查看 `docs/wgui/automation-debugging/SKILL.md`，按需读它的 UIA 回读、状态清理、探针和轨迹参考。以实际客户端版本和 Windows 交互会话为准。先手动或用只读探针记录应用身份、模式切换、工作区选择、权限和模型控件、提示词回读、任务终态与日志落点。保留关键 stage 的截图、UIA 树或脱敏日志，区分本机和云端冷启动差异。

沿当前仓库实现，优先复用产品驱动、Windows UIA、工作区传输和轨迹验证的公共逻辑。检查入口及上下游调用关系。

- `src/win-arena-container/wgui/guest/products/` 和 `guest/products/registry.py` 提供产品驱动及注册。
- `controller/contracts/models.py` 和 `controller/cli/main.py` 定义请求结构及 `vm health`、`task run`、`task collect` 等入口。修改协议字段或枚举时检查 schema 导出、能力声明和 guest 转发。以目标 checkout 的版本为准。
- 如需评测平台，沿评测框架 `src/e2e` 中的产品分发、能力目录、轨迹解析和结果导出实现检查新增 Harness 是否贯通。

## 验收驱动动作

1. **启动和配置**。按包身份、安装路径或进程身份确认目标窗口。在发题前回读实际登录状态、模式、模型、推理档位和权限，范围以请求支持的配置为准。只对观察过的首次引导或可恢复页做有限次数恢复。冷启动和原生弹窗各自设上限，并受任务的总截止时间约束。Windows 目录框可能是独立顶层窗口，使用真实 owner、进程及控件标识限定匹配。
2. **工作区与发送**。通过真实客户端进入新会话，核对选中的路径就是本次工作区。发送前回读提示词，保证关联到正确的任务输入。评测请求从客户端 UI 发出。产品 CLI 或 API 可用于经授权的安装、认证和诊断。记录发题前后的证据。显示状态、网络错误或超时导致接受结果不明时，先查原作业和原生会话。
3. **终态和原生证据**。在发题前记候选轨迹基线，按原生会话、turn、工作目录、提示词、实际模型和匹配的终态绑定。对转义只允许可由冻结提示词确定性生成且实机验证的表示，保留原始字节及摘要。避免用窗口静止、固定睡眠或最后一条回答作为唯一完成信号。按评分准入规则核对证据的完整性。
4. **采集、导出与停止**。检查真实 `RunReport`、最终答复、原生轨迹、产物和失败诊断能经正常 collect 返回。用实际新轨迹验证标准结果导出，特别是解析终态后的时间戳字段。活动文件读取需要合适的共享模式并校验大小和摘要。按本次应用或工作目录绑定进程归属，观察静默后的状态，再发布可封存产物。收集或回收失败时通过平台支持的原批次恢复入口继续。

## 按风险选测试

针对改动覆盖请求校验、选择器歧义、已知产品阶段、提示词原生表示、终态归属和导出。随后在该母盘的独立 Windows 实例通过 wgui 正常入口跑一个会生成文件的任务。云端或平台验收至少复测一条真实用例，并用实际运行的代码摘要核对版本。用 mock 得到的通过结果记作本地契约测试。

ChatGPT 的接入曾出现云端冷启动引导、归属于主窗口的顶层目录框、原生 Markdown 转义和桌面版原生时间戳格式差异。其他 Harness 应依据各自实机证据确定选择器、解析器和恢复条件。
