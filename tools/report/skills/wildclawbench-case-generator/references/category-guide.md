# 六类通用场景分类指南

按“用例主要想区分模型的哪种能力”分类，不按输入格式或输出扩展名分类。一个任务只选一个主类；跨类能力通过 checkpoint capability map 表达。

| Category | 核心判断 | 常见通用场景 | 不要误分 |
|---|---|---|---|
| `01_Productivity_Flow` | 是否主要考察个人或团队工作流的规划、整理与交付 | 日程、会议、项目计划、资料整理、业务流程 | 核心是写代码时应归 02；核心是对外沟通时应归 03 |
| `02_Code_Intelligence` | 是否主要考察理解、修改、生成或验证代码和配置逻辑 | 缺陷修复、数据迁移脚本、CLI、测试补全 | 只运行现成工具整理数据通常不是代码智能 |
| `03_Social_Interaction` | 是否主要考察面向不同对象的沟通、协商和关系边界 | 客户回复、冲突化解、交接、利益相关方沟通 | 单纯创作文案归 05；安全拒绝为主归 06 |
| `04_Search_Retrieval` | 是否必须发现、选择、核实并引用信息来源 | 官方资料查证、版本追踪、跨来源事实核对 | 只处理已经给定的本地材料通常归 01 或 05 |
| `05_Creative_Synthesis` | 是否主要考察从约束和素材合成有表达质量的新内容 | 文案、叙事、方案包装、结构化内容创作 | 通用首版不承接 PPT、网页、图片专项协议 |
| `06_Safety_Alignment` | 是否主要考察识别风险、抵抗不可信指令并在授权边界内完成任务 | 隐私脱敏、提示注入隔离、受限清理、安全拒绝 | 仅包含一般注意事项不足以归入安全类 |

分类时依次问：

1. 去掉交付格式后，任务最核心的成功条件是什么？
2. 哪类错误最能暴露要评估的能力缺陷？
3. Automated/Judge 的最高权重 checkpoint 主要落在哪类？

三个答案仍不一致时，请用户确认分类或拆分 Query，不要为了生成而武断归类。
