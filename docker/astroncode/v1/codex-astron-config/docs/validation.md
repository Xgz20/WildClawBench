# 验证边界

当前配置包含 Spark-X2 Flash、Spark X2 Agent、Kimi K2.7 Code、GLM-5.2 和 DeepSeek-V4-Pro 的最小模型metadata。

## 已保留

- `shell_type = "unified_exec"`：四个已发布模型均使用实际 MaaS 请求完成过“运行失败脚本、修改文件、复跑通过”的编码任务。
- `truncation_policy`：模型metadata结构要求；此前用超过 10,000 字节的命令输出验证过截断提示。
- `context_window` 与 `max_context_window`：按模型公开上限填写，用于 Codex 上下文预算。它们是容量声明，不是本分支声称已压力测试的功能。
- Kimi K2.7 Code 的 `input_modalities` 包含 `image`：已用实际图片附件请求验证。其他三个模型只声明 `text`。

## 已关闭

推理档位、推理摘要、详细度、技能说明、并行工具调用、原图细节、搜索工具、轻量 Responses 请求格式、代码模式和多代理版本均保持关闭或不设置。

这些字段在其他模型的请求抓取或任务中可以出现，但当前没有形成稳定、可反证收益，不进入最小配置。

`apply_patch_tool_type` 也不设置。四个模型在没有该工具时仍能通过 `unified_exec` 完成实际文件修复。

Spark X2 Agent 尚未发布。本目录只根据已确认的文本输入和 262,144 上下文窗口建立最小条目；测试环境的真实文本请求已成功返回。发布后仍必须补做真实编码任务和工具调用回归，才可以将其列入已验证编码模型。

## 不作出的结论

当前没有证明 `unified_exec` 比 `shell_command` 更适合所有任务：两者在简单修复任务中均通过。这里选择 `unified_exec`，是因为它与当前 Codex 的 Shell 工具形态一致，且已完成端到端编码验证。

## 新字段的验证标准

不能以模型的自然语言回复作为能力已生效的唯一证据。新增字段至少要有以下两类证据：

1. 请求对照：通过本地代理或测试服务器分别运行“字段开启”和“字段关闭”的配置，确认请求体、工具列表或会话metadata出现预期差异。
2. 行为对照：测试服务器返回对应的结构化工具调用，或真实 MaaS 任务产生可检查的副作用，例如文件被修改、子代理线程被创建、工具调用事件被记录。关闭字段后，这个事件或副作用必须消失或被拒绝。

推理摘要只能验证请求参数和返回的摘要事件，不能证明模型内部使用了多少推理。并行工具调用必须同时验证请求中的并行许可和多个工具调用的实际调度。搜索、图片细节和补丁工具也必须看到对应的结构化调用或输出，不能只看模型说“已经使用”。
