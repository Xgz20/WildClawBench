# 游戏属性加点模拟器

## Prompt

请在 /tmp_workspace 下创建项目。如果启动网站时遇到端口冲突，请自行选择其他可用端口。

我想做一个游戏属性加点模拟器——网页版，做好后要能嵌入到我的 WordPress 站点里。加点规则就按角色扮演类游戏的常见玩法来设计即可。

## Expected Behavior

Agent 应生成可运行的属性加点模拟器页面：用户可以把点数分配到不同属性上，加点受总点数和各属性上下限约束并有实时校验；配置可以保存和再次载入；属性变化对角色能力的影响有可视化呈现。代码形态应便于嵌入 WordPress 站点使用。

### Criterion 1: 加点核心系统完整性 (key: c01_stat_allocation_core, weight: 0.1)

采证方式：页面操作为主，代码为辅。

采证动作：进入页面，给若干属性加点/减点，观察剩余点数是否实时变化；尝试把某一属性加到超过上限、把总点数用超，记录系统的拦截与提示。

评分锚点：审查代码是否实现完整的加点系统，允许用户在不同属性间分配点数。检查是否包含各属性的最小/最大值约束、总点数上限和实时校验。核心分配逻辑缺失计 0 分；实现基础分配但缺约束计 5 分；系统完整处理分配规则并带有正确校验计 10 分。

### Criterion 2: WordPress 集成设计 (key: c02_wordpress_integration, weight: 0.1)

采证方式：代码为主。

评分锚点：评估代码能否按要求正确嵌入 WordPress。检查是否有 WordPress 兼容的初始化方式（如使用 wp_enqueue_script）、避免冲突的命名空间隔离、以及适配 WordPress 主题的响应式设计。缺少 WordPress 钩子扣 5 分；未处理主题兼容性扣 3 分；未遵循 WordPress 编码规范扣 2 分。

### Criterion 3: 配置保存与载入机制 (key: c03_save_load, weight: 0.1)

采证方式：页面操作为主，代码为辅。

采证动作：完成一次加点后保存配置，刷新页面或重新进入后载入，核对属性值是否还原；如有导出/导入功能，导出后再导入验证一致性。

评分锚点：检查用户能否保存加点配置并在之后载入。审查方案是否恰当使用 localStorage、是否包含导出/导入功能、数据能否持久保留。保存已实现但载入不可靠扣 5 分；没有导出/导入功能扣 3 分；完全没有持久化机制计 0 分。

### Criterion 4: 属性效果可视化反馈 (key: c04_visual_feedback, weight: 0.1)

采证方式：页面操作 + 截图。

采证动作：调整某个属性的点数，观察图表/派生数值等可视化是否随之更新，截图记录调整前后的可视化对比。

评分锚点：评估模拟器是否以可视化方式呈现属性变化对角色能力或游戏参数的影响，如图表、曲线、派生属性计算或其他可视化辅助。可视化反馈全面且有多种呈现方式计 10 分；有基础反馈计 5 分；完全没有可视化呈现计 0 分。

### Criterion 5: 代码鲁棒性 (key: c05_robustness, weight: 0.1)

采证方式：代码为主。

采证动作（辅助）：在数值输入框中输入负数、超大数、非数字字符，快速连点加/减按钮，观察是否报错或状态错乱。

评分锚点：评估代码能否处理常见异常（非法输入、脚本加载失败、浏览器兼容性问题等）并提供友好提示或恢复机制。鲁棒性强、能有效处理这些边界情况计 10 分；鲁棒性一般计 5 分；完全未处理异常计 0 分。

### Criterion 6: 创新功能 (key: c06_innovation, weight: 0.1)

采证方式：页面操作 + 代码。

评分锚点：检查是否包含提升体验的惊喜功能（如：1. 针对不同流派的加点预设方案 2. 多套配置的对比模式 3. 基于属性的角色预览）。每实现一项实用创新加 3 分，上限 10 分。

### Criterion 7: 冗余功能检查 (key: c07_redundancy, weight: 0.1)

采证方式：代码为主。

评分锚点：严查三类冗余：1. 同类功能重复实现（如多套重置属性的方式并存）2. 与加点无关的功能模块（如内置聊天系统）3. 影响性能的花哨特效（如过量动画）。每处冗余扣 3 分；冗余代码干扰核心功能直接计 0 分。

### Criterion 8: 工程质量 (key: c08_engineering, weight: 0.1)

采证方式：代码。

评分锚点：审查模块化设计（如 UI/逻辑/数据分层）、恰当的设计模式使用与可维护结构。发现全局状态污染扣 5 分；代码重复率过高（超过 30%）扣 5 分；组件缺乏清晰组织扣 5 分。满分 10 分。

### Criterion 9: 界面视觉专业性 (key: c09_visual_design, weight: 0.1)

采证方式：截图。

采证动作：桌面 1440×900 截整页图（加点主界面与可视化区域）。

评分锚点：评估整体设计是否符合现代设计原则：1）配色和谐（主色不超过 3 种）2）布局间距合理（元素间距遵循 8px 倍数原则）3）专业字体体系（正文不小于 14px、行高超过 1.5 倍）。每处视觉拥挤扣 3 分；刺眼配色扣 5 分；图文排版混乱扣 5 分。满分 10 分。

### Criterion 10: 动态交互流畅性 (key: c10_interaction_fluency, weight: 0.1)

采证方式：页面操作。

采证动作：连续调整属性点数 5 次以上，记录反馈是否即时、数值变化动画是否顺滑；观察不可用操作（点数用尽后继续加点）是否有清晰的状态提示。

评分锚点：判断动效是否符合人类感知特性：1）调整属性时反馈即时 2）属性变化有平滑的过渡动画 3）可用/不可用操作有清晰的视觉提示。每处操作无反馈扣 5 分；调整属性时动画卡顿扣 3 分；UI 状态表达混乱扣 5 分。满分 10 分。
