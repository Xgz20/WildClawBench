# 社交媒体动态页

## Prompt

请在 /tmp_workspace 下创建项目。如果启动网站时遇到端口冲突，请自行选择其他可用端口。

我想做一个社交媒体动态页（Feed）：用户可以发布新动态，也能刷到好友的动态。动态可以包含文字、图片和视频，支持点赞和评论。新发布的动态要自动出现在信息流顶部。

如果涉及外部接口或用户数据（图片、视频、音频等），请用模拟数据代替。

## Expected Behavior

Agent 应生成可运行的社交动态页：有发布表单可发出含文字／图片／视频的新动态，新动态自动出现在信息流顶部；信息流以卡片形式展示各条动态，点赞即时更新数量与状态，评论可发表并展示时间与用户信息。媒体内容使用模拟数据。

### Criterion 1: 信息流 UI 完整性 (key: c01_feed_ui, weight: 0.1)

采证方式：页面观察 + 截图，代码为辅。

采证动作：打开页面截取整体信息流，核对发布表单、动态卡片、点赞按钮、评论区、可滚动信息流容器是否齐全，文字／图片／视频三类内容是否都能正常展示。

评分锚点：审查动态页的 HTML/CSS 结构，确认能以响应式布局正确展示含文字、图片、视频的动态；检查核心 UI 组件是否齐全：发布表单、动态卡片、点赞按钮、评论区、可滚动的信息流容器。核心 UI 元素缺失计 0 分；有基础布局但欠打磨计 5 分；完整实现且间距、响应式与视觉层次到位计 10 分。

### Criterion 2: 发布动态功能 (key: c02_post_creation, weight: 0.1)

采证方式：页面操作为主，代码为辅。

采证动作：分别发布一条纯文字动态和一条带图片／视频（模拟）的动态，记录表单校验、预览、加载与成功反馈；再提交一次空内容，观察错误提示。

评分锚点：验证用户能否发布含文字、图片、视频的新动态；检查表单校验、媒体上传处理（或模拟实现）、预览能力和提交处理；实现应包含错误状态、加载指示和成功反馈。缺少媒体上传处理扣 5 分；校验不完整扣 3 分。发布流程直觉顺畅、覆盖全部要求的内容类型得满分。

### Criterion 3: 信息流数据管理与展示 (key: c03_feed_data_logic, weight: 0.1)

采证方式：页面操作 + 代码。

采证动作：发布一条新动态后立即观察信息流顶部是否自动出现该动态；核对动态排序是否按时间正确排列；刷新页面观察初次加载是否有加载状态。

评分锚点：评估动态的获取、存储与展示逻辑：数据结构、状态管理方式和渲染优化是否合理；新动态应自动出现在信息流顶部；如实现了分页或无限滚动一并审查。新动态未自动出现在顶部扣 5 分；动态排序错误扣 3 分；信息流初次加载没有加载状态扣 3 分。渲染高效、数据流清晰得满分。

### Criterion 4: 点赞与评论功能 (key: c04_social_interactions, weight: 0.1)

采证方式：页面操作为主。

采证动作：对一条动态点赞再取消，记录数量与按钮状态是否即时变化；发表一条评论，核对是否即时展示、是否带时间与用户信息，截图留证。

评分锚点：检查点赞是否即时更新数量与视觉状态（乐观 UI），失败时是否有相应的错误处理；评论系统应支持发表新评论、展示已有评论（带时间戳和用户信息），并可支持嵌套回复。点赞数不即时更新扣 5 分；评论提交无视觉反馈扣 3 分；评论展示缺少关键信息扣 5 分。两项功能完整实现且体验考虑周全得满分。

### Criterion 5: 代码鲁棒性 (key: c05_robustness, weight: 0.1)

采证方式：代码为主。

采证动作（辅助）：提交超长文本、快速连点点赞按钮 10 次，观察是否报错或状态错乱。

评分锚点：评估代码能否处理常见异常情况（如发布时网络故障、非法输入数据、媒体加载失败等）并提供友好的错误提示或恢复机制。鲁棒性强、能有效处理这些边界情况计 10 分；鲁棒性一般计 5 分；完全未处理异常计 0 分。

### Criterion 6: 创新功能 (key: c06_innovation, weight: 0.1)

采证方式：页面操作 + 代码。

评分锚点：检查是否包含提升体验的惊喜功能（如：1. 动态内容情感分析 2. 智能内容推荐 3. 点赞之外更丰富的互动表情 4. 无障碍功能）。每实现一项实用创新加 3 分，上限 10 分。

### Criterion 7: 冗余功能检查 (key: c07_redundancy, weight: 0.1)

采证方式：代码为主。

评分锚点：严查三类冗余：1. 同类功能重复实现（如多套发布动态的入口）2. 与社交信息流无关的功能模块（如内置计算器）3. 影响性能的花哨特效（如滚动时的过度动画）。每发现一处冗余扣 3 分；若冗余代码干扰了核心功能，直接计 0 分。

### Criterion 8: 工程质量 (key: c08_engineering, weight: 0.1)

采证方式：代码。

评分锚点：审查模块化设计（如 UI 组件、状态管理、接口服务分离）、组件复用性、构建流程与目录结构。存在全局状态污染或未使用设计模式扣 5 分；代码重复率过高（超过 30%）扣 5 分；构建流程未自动化或目录结构混乱扣 5 分。满分 10 分。

### Criterion 9: 界面视觉专业性 (key: c09_visual_design, weight: 0.1)

采证方式：截图。

采证动作：桌面 1440×900 截整页图（信息流 + 发布表单）。

评分锚点：评估整体设计是否符合现代设计原则：1）配色和谐（主色不超过 3 种）2）布局间距合理（元素间距遵循 8px 倍数原则）3）专业字体体系（正文字号不小于 14px、行高超过 1.5 倍）。每处视觉拥挤扣 3 分；刺眼配色扣 5 分；图文排版混乱扣 5 分。满分 10 分。

### Criterion 10: 动态交互流畅性 (key: c10_interaction_fluency, weight: 0.1)

采证方式：页面操作。

采证动作：执行点赞、评论各 3 次并连续滚动信息流，记录反馈延迟、滚动流畅度与媒体加载时的占位表现。

评分锚点：判断动效是否符合人类感知特性：1）点赞／评论反馈延迟不超过 100ms 2）过渡动画时长控制在 300-500ms 3）发布动态时有清晰的视觉焦点引导。每处操作无反馈扣 5 分；滚动卡顿扣 3 分；媒体加载迟缓且无占位提示扣 5 分。满分 10 分。
