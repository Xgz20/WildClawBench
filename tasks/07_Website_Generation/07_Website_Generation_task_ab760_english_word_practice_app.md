# 小学英语单词记忆练习

## Prompt

请在 /tmp_workspace 下创建项目。如果启动网站时遇到端口冲突，请自行选择其他可用端口。

我想要一个能在浏览器里运行的程序，帮小学生背英语单词。教材用的是陕旅版（三年级起点）。程序要能按年级和学期做测试，题型包括：看中文提示选英文单词的选择题，以及给出中文意思后让学生输入/拼写英文单词。

## Expected Behavior

Agent 应生成可在浏览器运行的背单词应用：内置按年级（三至六年级）和学期组织的词库，用户可选择年级/学期后开始测试；提供中译英选择题和拼写输入两种题型，答题后有对错反馈和成绩统计；界面风格适合小学生使用。

### Criterion 1: 词库与年级分类体系 (key: c01_word_database, weight: 0.1)

采证方式：页面操作 + 代码。

采证动作：在页面上切换不同年级/学期，确认词库随之变化；结合代码检查词库数据结构（中文释义、发音、难度等字段）与年级/学期筛选逻辑。

评分锚点：审查代码是否包含面向陕旅版教材（三至六年级、每年级两学期）的完整词库，词汇存储的数据结构设计是否合理（含中文释义、发音、难度等级）；检查年级/学期筛选机制是否实现准确。没有结构化词库计 0 分；只有基础单词列表、缺乏合理分类计 5 分；实现了完整的年级-学期层级且陕旅版词汇准确计 10 分。

### Criterion 2: 双测试模式功能完备性 (key: c02_testing_modes, weight: 0.1)

采证方式：页面操作为主，代码为辅。

采证动作：分别进入选择题模式和拼写输入模式各答 3 题（含故意答错），记录选项是否随机、判定是否正确、反馈是否准确。

评分锚点：评估两种测试模式是否都实现到位：1）看中文提示选英文单词的选择题 2）根据中文意思输入英文单词的拼写模式。检查答案校验逻辑、选项随机化和计分机制。只实现一种模式扣 5 分；答案校验不完整扣 3 分。满分要求两种模式都流畅可用且反馈准确。

### Criterion 3: 学习进度追踪与分析 (key: c03_progress_tracking, weight: 0.1)

采证方式：页面操作 + 代码。

采证动作：完成一轮测试后查看成绩/进度页面，刷新页面确认学习记录是否保留（localStorage 等）；结合代码确认薄弱词识别与学习建议逻辑。

评分锚点：检查系统是否追踪学生表现，包括答对/答错记录、各年级学习进度、薄弱单词识别和学习建议；评估是否使用本地存储或会话管理保存学习历史。没有进度追踪扣 5 分；只有基础计分、缺乏详细分析扣 3 分。完整实现应包含成绩看板和自适应难度调整。

### Criterion 4: 适龄学习功能与游戏化设计 (key: c04_gamification, weight: 0.1)

采证方式：页面操作为主。

采证动作：答对/答错各一次，记录鼓励性反馈；查看是否有成就徽章、连对计数、奖励等入口并逐一触发。

评分锚点：评估应用是否包含适合小学生的功能，如鼓励性的反馈语、成就徽章、连对计数或简单的奖励系统；检查难度递进是否适合低龄学习者、是否提供提示或学习辅助。界面纯功能性、完全没有考虑教育心理计 0 分；有基础的鼓励功能计 5 分；全面的游戏化设计有效提升学习动力计 10 分。

### Criterion 5: 代码鲁棒性 (key: c05_robustness, weight: 0.1)

采证方式：代码为主。

采证动作（辅助）：在拼写模式提交空输入和特殊字符，观察是否有清晰的错误提示。

评分锚点：评估代码能否处理常见问题，如空输入、拼写模式中的特殊字符、浏览器兼容性问题、数据加载失败和用户误操作；应用应提供清晰的错误提示并平滑降级。鲁棒性强、能有效处理这些边界情况计 10 分；鲁棒性一般计 5 分；完全未处理异常计 0 分。

### Criterion 6: 创新教育功能 (key: c06_innovation, weight: 0.1)

采证方式：页面操作 + 代码。

评分锚点：检查是否包含提升学习效果的创意功能（如：1. 单词发音播放 2. 单词联想配图 3. 间隔重复算法 4. 家长/教师进度报告 5. 离线可用能力）。每实现一项实用创新加 2-3 分，上限 10 分。功能必须真正可用，不能只是摆设。

### Criterion 7: 冗余或不适龄功能检查 (key: c07_redundancy, weight: 0.1)

采证方式：代码为主。

评分锚点：严查三类问题：1）同类功能重复实现（如多套计分系统）2）不适合小学生的功能（如复杂的统计图表、高级设置）3）干扰学习专注度的元素（如过量动画、无关小游戏）。每发现一处冗余扣 3 分；核心学习功能被多余功能拖累直接计 0 分。

### Criterion 8: 工程质量与可维护性 (key: c08_engineering, weight: 0.1)

采证方式：代码。

评分锚点：审查数据管理、UI 组件与测试逻辑的模块化分离；检查代码组织是否得当、变量命名是否合理、新增词库是否易于扩展。发现全局状态污染或没有清晰的关注点分离扣 5 分；代码重复率超过 30% 扣 5 分；代码不易于扩展新功能扣 3 分。满分要求代码整洁、结构良好。

### Criterion 9: 儿童友好的界面设计 (key: c09_child_friendly_design, weight: 0.1)

采证方式：截图。

采证动作：桌面 1440×900 截整页图（选择界面 + 答题界面），核对字号、按钮尺寸与配色。

评分锚点：评估视觉设计是否适合小学生：1）明快活泼但不过分刺激的配色 2）大而易读的字体（面向儿童不小于 16px）3）视觉层级清晰、导航直观 4）交互元素间距充足（触控目标不小于 44px）。每处界面杂乱元素扣 3 分；对比度差或可读性问题扣 5 分；导航令儿童难以理解扣 5 分。

### Criterion 10: 交互流畅性与即时教育反馈 (key: c10_interaction_feedback, weight: 0.1)

采证方式：页面操作。

采证动作：连续答题 5 次（含对与错），记录反馈延迟、题目切换过渡和对错的视觉标识。

评分锚点：判断交互体验是否达到教育软件标准：1）答题对错即时反馈（响应时间不超过 200ms）2）题目间切换过渡平滑、无突兀效果 3）对错有清晰的视觉标识 4）有适合儿童的鼓励性动画和音效。反馈延迟打断学习节奏扣 5 分；用户操作缺少视觉确认扣 3 分；交互让儿童难以理解或难以完成扣 5 分。
