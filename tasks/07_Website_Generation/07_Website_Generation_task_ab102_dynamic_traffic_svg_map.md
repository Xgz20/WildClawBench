# 动态交通信息 SVG 地图

## Prompt

请在 /tmp_workspace 下创建项目。如果启动网站时遇到端口冲突，请自行选择其他可用端口。

我想用 SVG 代码做一个能展示交通信息的动态地图：地图上有道路，能直观看出各路段的交通状况，并且是动态的、可以随数据变化更新。请保证代码可以直接运行演示。

## Expected Behavior

Agent 应生成可在浏览器中打开的 SVG 交通地图页面：地图包含结构化的道路网络，各路段以颜色或动效表达交通状况（如畅通/缓行/拥堵），并配有图例说明；交通数据能通过 JavaScript 动态更新，无需刷新页面；地图支持基本的交互（缩放、悬停查看路段详情等）。

### Criterion 1: SVG 地图结构 (key: c01_svg_structure, weight: 0.1)

采证方式：代码为主，页面观察为辅。

采证动作：打开页面确认地图正常渲染，结合代码检查 SVG 的 viewBox、尺寸设置、道路 path 元素与分组分层结构。

评分锚点：评估代码是否创建了结构良好的 SVG，包含合适的 viewBox、尺寸设置与组织方式；检查道路是否用了合适的 path 元素、相关元素是否分组、图层是否合理。没有 SVG 结构计 0 分；有基础结构但存在问题计 5 分；SVG 结构遵循最佳实践、组织良好计 10 分。

### Criterion 2: 交通信息可视化 (key: c02_traffic_visualization, weight: 0.1)

采证方式：页面观察为主，代码为辅。

采证动作：观察地图不少于 10 秒，记录各路段的颜色编码（绿/黄/红等）与车流动效；确认页面是否有图例或指示说明可视化含义，截图记录。

评分锚点：审查代码是否通过颜色编码（如绿/黄/红表示交通等级）、车流移动的动画效果或其他视觉指示实现了交通可视化；检查是否有恰当的图例或指示说明。可视化只是静态的扣 5 分；视觉隐喻令人困惑扣 3 分。满分 10 分。

### Criterion 3: 实时更新的数据绑定机制 (key: c03_data_binding, weight: 0.1)

采证方式：页面观察 + 代码。

采证动作：观察页面交通状态是否随时间自动变化（不刷新页面）；结合代码确认是否存在事件监听、数据获取机制（fetch API 或 WebSocket 等）和数据驱动的属性更新逻辑。

评分锚点：评估代码是否包含能根据变化的交通数据更新 SVG 元素的 JavaScript 函数；检查事件监听器、数据获取机制（如 fetch API 或 WebSocket）和数据驱动的属性更新。更新需要刷新页面扣 5 分；更新机制存在明显延迟（超过 2 秒）扣 3 分。满分 10 分。

### Criterion 4: 地图交互性 (key: c04_interactivity, weight: 0.1)

采证方式：页面操作为主。

采证动作：依次尝试缩放、平移、点击道路查看详情、悬停查看附加信息、按交通状况筛选等交互，逐项记录哪些可用及其反馈。

评分锚点：检查实现是否包含交互功能，如缩放、平移、点击道路查看详情、悬停显示附加信息、按不同交通状况筛选等。实现了多种直观的交互计 10 分；只有基础交互计 5 分；地图完全静态计 0 分。

### Criterion 5: 代码鲁棒性 (key: c05_robustness, weight: 0.1)

采证方式：代码为主。

评分锚点：评估代码能否处理常见异常情况（如数据缺失、数据格式错误、浏览器兼容性问题等）并提供兜底或错误处理。鲁棒性强的代码应在特性不受支持或数据不可用时平滑降级，计 10 分；鲁棒性一般计 5 分；完全未处理异常计 0 分。

### Criterion 6: 创新功能 (key: c06_innovation, weight: 0.1)

采证方式：页面操作 + 代码。

评分锚点：检查是否包含提升体验的惊喜功能（如：1. 影响交通的天气图层 2. 随一天中不同时段变化的视觉效果 3. 展示拥堵随时间变化规律的热力图）。每实现一项实用创新加 3 分，上限 10 分。

### Criterion 7: 冗余功能检查 (key: c07_redundancy, weight: 0.1)

采证方式：代码为主。

评分锚点：严查三类冗余：1. 同类可视化逻辑重复实现 2. 与交通可视化无关的功能模块（如不必要的动画）3. 影响性能的复杂特效（如拖慢渲染的过量滤镜或渐变）。每发现一处冗余扣 3 分；冗余代码干扰核心功能直接计 0 分。

### Criterion 8: 工程质量 (key: c08_engineering, weight: 0.1)

采证方式：代码。

评分锚点：审查模块化设计（SVG 生成、数据处理、交互逻辑分离）、代码复用性和可维护性。过度使用全局变量扣 5 分；代码重复率过高（超过 30%）扣 5 分；展示层与业务逻辑没有清晰分离扣 5 分。满分 10 分。

### Criterion 9: 界面视觉专业性 (key: c09_visual_design, weight: 0.1)

采证方式：截图。

采证动作：桌面 1440×900 截整页图，重点检查地图配色、主次道路层级和标签可读性。

评分锚点：评估地图视觉设计是否遵循制图学原则：1）地图要素与交通指示的配色合适 2）视觉层级得当，主干道比次要道路更突出 3）标签清晰易读、字体选择合适。地图元素对比度差扣 3 分；交通指示难以区分扣 5 分；标签杂乱或相互重叠扣 5 分。满分 10 分。

### Criterion 10: 动态交互流畅性 (key: c10_interaction_fluency, weight: 0.1)

采证方式：页面操作。

采证动作：连续执行缩放/悬停等交互各 3 次，观察动画是否卡顿、交互反馈是否及时、数据更新时界面是否冻结。

评分锚点：判断 SVG 动画与过渡是否做了性能优化且视觉舒适：1）车流动画顺滑无卡顿 2）交互反馈在 100ms 内响应 3）更新渲染高效、不冻结界面。动画造成性能问题扣 5 分；数据变化后视觉更新延迟扣 3 分；动画节奏卡顿或不一致扣 5 分。满分 10 分。
