# 密码生成与管理工具

## Prompt

请在 /tmp_workspace 下创建项目。如果启动网站时遇到端口冲突，请自行选择其他可用端口。

我想做一个密码生成与管理工具：可以自己设定密码长度，勾选要包含哪些字符类型（比如字母、数字、特殊符号），然后生成符合要求的随机密码。

生成的密码要能保存在本地，保存下来的密码还可以编辑和删除。

## Expected Behavior

Agent 应生成可运行的密码工具页面：用户设定长度、勾选字符类型后点击生成，得到符合条件的随机密码；密码可保存到本地并在列表中展示，列表条目支持编辑和删除，刷新页面后数据仍在。

### Criterion 1: 密码生成功能完整性 (key: c01_generation_core, weight: 0.1)

采证方式：页面操作为主，代码为辅。

采证动作：设定长度为 16 并勾选全部字符类型生成一次，检查结果长度与字符构成；再取消勾选全部类型、把长度设为 0 或负数，记录是否有校验拦截和提示。

评分锚点：审查代码是否准确实现核心的密码生成能力并支持自定义选项：长度选择、字符类型包含（大写字母、小写字母、数字、特殊符号）。核心功能缺失计 0 分；只有基础生成、选项不全计 5 分；所有自定义选项都完整实现且带有妥当的校验（如最小长度检查、至少勾选一种字符类型）计 10 分。

### Criterion 2: 密码强度评估 (key: c02_strength_evaluation, weight: 0.1)

采证方式：页面操作 + 代码。

采证动作：分别生成一个 6 位纯数字密码和一个 20 位混合密码，记录强度指示（颜色条／文字描述）是否随之变化，以及弱密码是否给出具体的改进建议；结合代码确认强度算法的依据。

评分锚点：检查代码是否包含基于行业标准的密码强度评估（信息熵计算、字符多样性分析、常见模式检测）。只用简单的长度判断扣 3 分；完全没有评估扣 5 分。满分要求提供可视化的强度指示（颜色条或文字描述）以及针对弱密码的具体改进建议。

### Criterion 3: 密码存储与管理系统 (key: c03_storage_management, weight: 0.1)

采证方式：页面操作为主，代码为辅。

采证动作：保存一条密码，检查列表是否出现该条目及其附带信息（网站／服务名、用户名、创建时间）；对该条目执行一次编辑和一次删除；刷新页面确认数据持久化；结合代码确认存储方式与是否做了加密。

评分锚点：评估密码的保存、编辑、删除功能的实现情况。检查密码是否连同关联信息一起存储（网站／服务名称、用户名、创建日期）。缺少任一核心增删改查操作扣 5 分；密码明文存储、未加密扣 3 分。满分要求有妥当的数据持久化（localStorage、IndexedDB 或 File API）并带数据完整性校验。

### Criterion 4: 剪贴板交互安全性 (key: c04_clipboard_security, weight: 0.1)

采证方式：页面操作为主，代码为辅。

采证动作：点击复制按钮，记录是否出现复制成功的提示；结合代码确认是否有超时自动清空剪贴板的逻辑及其时长。

评分锚点：检查工具是否提供便捷的一键复制到剪贴板功能，并配有相应的安全措施。评估剪贴板内容是否会在超时后自动清空，复制成功是否有视觉反馈。缺少复制功能扣 5 分；没有反馈扣 3 分；没有自动清空的安全机制扣 3 分。

### Criterion 5: 代码鲁棒性 (key: c05_robustness, weight: 0.1)

采证方式：代码为主。

采证动作（辅助）：在长度输入框填入非法值（空、字母、超大数字）并连点生成按钮 10 次，观察是否报错或状态错乱。

评分锚点：评估代码能否处理常见异常情况（如非法输入、存储访问失败、并发操作）并提供友好的错误提示或恢复机制。鲁棒性强计 10 分，一般计 5 分，完全未处理异常计 0 分。

### Criterion 6: 创新功能 (key: c06_innovation, weight: 0.1)

采证方式：页面操作 + 代码。

评分锚点：检查代码是否包含提升体验的惊喜功能（如：1. 密码历史记录 2. 密码过期提醒 3. 接入泄露检测 API 4. 主密码保护）。每实现一项实用创新加 3 分，上限 10 分。

### Criterion 7: 冗余功能检查 (key: c07_redundancy, weight: 0.1)

采证方式：代码为主。

评分锚点：严查三类冗余：1. 同类功能重复实现（如多套存储机制同时生效）2. 与密码管理无关的功能模块（如内置日历）3. 影响性能的花哨特效（如过量动画）。每处冗余扣 3 分；冗余代码干扰核心功能直接计 0 分。

### Criterion 8: 工程质量 (key: c08_engineering, weight: 0.1)

采证方式：代码。

评分锚点：审查模块化设计（如 UI／逻辑／存储分层）、输入校验的严密程度、代码复用性。全局状态污染或未用设计模式扣 5 分；代码重复率过高（超过 30%）扣 5 分；复杂逻辑或安全考量处没有注释说明扣 5 分。满分 10 分。

### Criterion 9: 界面视觉专业性 (key: c09_visual_design, weight: 0.1)

采证方式：截图。

采证动作：桌面 1440×900 截整页图，覆盖生成区与已保存密码列表。

评分锚点：评估整体设计是否符合现代设计原则：1）配色和谐（主色不超过 3 种）2）布局间距合理（元素间距遵循 8px 倍数原则）3）专业字体体系（正文不小于 14px、行高不低于 1.5 倍）。每处视觉拥挤扣 3 分；刺眼配色扣 5 分；图文排版混乱扣 5 分。满分 10 分。

### Criterion 10: 动态交互流畅性 (key: c10_interaction_fluency, weight: 0.1)

采证方式：页面操作。

采证动作：连续操作生成、复制、保存、删除各 3 次，并拖动长度滑块快速来回滑动，记录反馈延迟、过渡动画时长与是否出现视觉残影。

评分锚点：判断动效是否符合人类感知特性：1）点击反馈延迟不超过 100ms 2）过渡动画时长控制在 300~500ms 3）视觉焦点引导清晰。每处操作无反馈扣 5 分；快速滑动时出现视觉残影扣 3 分；关键功能按钮难以找到扣 5 分。满分 10 分。
