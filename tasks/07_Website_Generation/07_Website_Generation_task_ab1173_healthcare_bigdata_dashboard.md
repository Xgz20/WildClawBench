# 医疗大数据看板

## Prompt

请在 /tmp_workspace 下创建项目。如果启动网站时遇到端口冲突，请自行选择其他可用端口。

我想用 Vue 和 ECharts 做一个医疗大数据看板，用关键指标卡、折线图、柱状图、饼图等多种形式做可视化展示。

需要展示的数据包括：门急诊人次、住院人次、手术例数、医疗业务收入、出院患者手术占比、三四级手术量、床位使用率、门诊次均药费、住院次均药费、平均住院日、院本部与分院的门急诊人次等。

页面的布局和排版请好好打磨一下。

## Expected Behavior

Agent 应生成一个可运行的 Vue + ECharts 医疗大数据看板页面：顶部或显著位置有关键指标卡，页面内包含折线图、柱状图、饼图等多种图表，覆盖题面列出的各项医疗指标，并配有符合医疗场景的模拟数据。图表可正常渲染、鼠标悬停可看到明细，整体布局分区清晰、在不同屏幕尺寸下都能正常阅读。

### Criterion 1: Vue 架构与组件化 (key: c01_vue_architecture, weight: 0.1)

采证方式：代码为主，页面为辅。

采证动作：查看项目源码目录结构与组件划分，确认页面能正常启动并渲染。

评分锚点：审查代码是否正确使用 Vue 3 组合式 API 或 Vue 2 选项式 API，组件结构是否合理。检查看板是否做了合理的组件拆分（页头、侧边栏、图表容器、数据面板）。确认是否正确使用 Vue 响应式系统做数据绑定与状态管理（Vuex/Pinia）。缺少基本 Vue 结构计 0 分；只有基础组件、没有像样的数据流计 5 分；完整用好 Vue 生态并实现响应式数据管理计 10 分。

### Criterion 2: ECharts 图表对医疗指标的覆盖度 (key: c02_chart_coverage, weight: 0.1)

采证方式：页面操作为主，代码为辅。

采证动作：逐屏浏览看板，清点实际渲染出的图表类型（折线图／柱状图／饼图／指标卡）与对应指标名称，逐项核对题面列出的指标是否都有展示，记录缺失项。

评分锚点：评估题面要求的图表类型是否都已实现：折线图（趋势类，如人次随时间变化）、柱状图（对比类数据）、饼图（占比类数据，如手术类型构成）以及关键指标卡。检查图表是否覆盖全部要求的医疗数据：门急诊人次、住院人次、手术例数、医疗业务收入、床位使用率、次均药费、平均住院日等。缺失超过 3 项要求的指标扣 5 分；每缺一种图表类型扣 3 分。满分要求 10 项以上医疗指标都得到恰当的可视化呈现。

### Criterion 3: 数据结构与模拟数据的真实感 (key: c03_data_realism, weight: 0.1)

采证方式：代码为主，页面为辅。

采证动作：查看模拟数据定义处，抽查各指标的数值范围与量纲是否合理；若页面有刷新／切换时间范围的入口，触发一次并观察图表是否随数据更新。

评分锚点：检查数据结构是否准确反映真实医疗数据的形态，数据类型、取值范围、字段间关系是否合理。核实模拟数据的取值是否贴近现实（例如床位使用率 70-95%、平均住院日 3-15 天、手术占比 15-40%）。评估数据更新机制，以及图表是否会随数据变化而响应。数据结构过于简化扣 5 分；模拟数据取值不合常理扣 3 分；没有任何数据更新机制扣 5 分。完整实现应包含时间序列数据和合理的数据关联关系。

### Criterion 4: 看板布局与响应式设计 (key: c04_layout_responsive, weight: 0.1)

采证方式：截图 + 页面操作。

采证动作：分别在 1440×900、768 宽（平板）、375 宽（手机）三种视口下截图，观察分区是否错乱、图表是否跟随容器重新调整尺寸、文字与图例是否仍可读。

评分锚点：评估看板是否采用专业的栅格布局体系（12 栅格或 CSS Grid）并设置了合理的响应式断点。检查布局在不同屏幕尺寸（桌面、平板、手机）下是否都能自适应，同时保持图表可读性。确认是否恰当使用 Vue 布局组件与 CSS 框架。移动端布局错乱扣 5 分；图表尺寸不能正确自适应扣 3 分；完全没做响应式扣 5 分。满分要求多端体验无缝衔接。

### Criterion 5: 代码鲁棒性 (key: c05_robustness, weight: 0.1)

采证方式：代码为主。

采证动作（辅助）：快速连续切换图表筛选项／时间范围 10 次，观察控制台是否报错、图表是否出现空白或状态错乱。

评分锚点：评估代码能否处理常见异常情况（接口失败、数据集为空、图表渲染出错、浏览器兼容问题），并给出友好提示或兜底机制。检查是否有恰当的 try-catch、加载态和降级处理。鲁棒性强的代码应能应对数据加载失败、图表初始化异常，并给用户有意义的反馈。完整实现计 10 分，有基本错误处理计 5 分，完全没有异常处理计 0 分。

### Criterion 6: 创新功能 (key: c06_innovation, weight: 0.1)

采证方式：页面操作 + 代码。

评分锚点：检查代码是否包含超出基本要求的有价值功能（例如：1. 指标可下钻查看明细 2. 基于 WebSocket 的实时数据刷新 3. 报表导出 4. 高级筛选与日期区间选择 5. 对比分析工具 6. 关键指标的告警阈值）。每实现一项实用的创新功能加 2 分（上限 10 分）。功能必须贴合医疗场景并带来实际价值。

### Criterion 7: 冗余功能检查 (key: c07_redundancy, weight: 0.1)

采证方式：代码为主。

评分锚点：严查三类冗余：1. 重复的图表实现（如多个功能相近的折线图组件）2. 没有实际价值的多余 UI 库或插件 3. 过度设计、拖慢看板性能的动画或特效 4. 重复的数据处理逻辑。每发现一处冗余扣 3 分；如果冗余代码或过多依赖已经影响到看板核心功能，直接计 0 分。

### Criterion 8: 工程质量 (key: c08_engineering, weight: 0.1)

采证方式：代码。

评分锚点：审查 Vue 组件的组织方式、关注点分离是否清晰（组件／服务／工具函数）、代码组织与构建配置。检查生命周期钩子、计算属性、侦听器的使用是否得当。评估代码的复用性与可维护性。组件拆分不合理或 props/events 使用不当扣 5 分；没有做构建优化（如代码分割）扣 3 分；编码规范前后不一致扣 5 分。满分要求达到专业水准的 Vue 架构。

### Criterion 9: 界面视觉的专业度 (key: c09_visual_design, weight: 0.1)

采证方式：截图。

采证动作：桌面 1440×900 截整页图（看板首屏 + 向下滚动后的完整内容），重点观察配色、分区、间距与字号。

评分锚点：评估设计是否符合医疗看板的惯例：1）配色贴合医疗场景（蓝色、绿色、干净的白），除告警外避免使用刺激性颜色 2）信息层级清晰、分区分明 3）间距统一，遵循 8px 栅格 4）字体专业（数据标签不小于 14px，对比度满足无障碍要求）5）整体干净、克制，符合医务人员的使用观感。每有一处视觉拥挤的区块扣 3 分；配色不当扣 5 分；信息层级混乱扣 5 分。

### Criterion 10: 交互流畅性与医疗工作流适配 (key: c10_interaction_fluency, weight: 0.1)

采证方式：页面操作。

采证动作：对折线图、柱状图、饼图各悬停 3 次，记录 tooltip 是否出现及延迟；切换时间周期或数据视图 3 次，记录过渡动画时长与加载态表现；确认关键指标是否在少量点击内就能查到。

评分锚点：判断交互是否为医务人员的使用场景做了优化：1）图表悬停在 100ms 内展示详细医疗数据 2）不同时间周期或数据视图之间切换过渡平滑（300-500ms）3）所有可交互元素都有清晰的视觉反馈 4）导航直观，支撑快速的数据分析流程 5）数据量大的操作有恰当的加载态。每有一处交互无响应扣 5 分；导航逻辑令人困惑扣 3 分；关键数据难以快速触达扣 5 分。
