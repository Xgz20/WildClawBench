# 在线文件预览系统

## Prompt

请在 /tmp_workspace 下创建项目。如果启动网站时遇到端口冲突，请自行选择其他可用端口。

我想做一个文件预览系统：点击某个文件后，能直接在线预览常见格式的文件，比如图片、PDF、文本文件等。

请保证代码能跑起来，可以直接演示效果。

## Expected Behavior

Agent 应生成可运行的文件预览页面：能通过拖拽或文件选择把本地文件加入列表，点击列表中的文件即可在预览区看到内容。图片、PDF、文本等不同格式分别用合适的方式渲染，遇到不支持的格式或读取失败时给出明确提示，不会白屏或卡死。

## LLM Judge Rubric

说明：

- 每个 Criterion 只能使用 `0.0 ~ 1.0`、步长 `0.1`（对应原 checklist 的 0~10 分，下文锚点以 0~10 分表述）。
- 锚点中的"扣 N 分"从 10 分起扣，扣完为止；"加 N 分"从 0 分起加，上限 10 分。
- 每个 Criterion 标注 `采证方式`，如适用附 `采证动作`；评分必须引用证据（截图文件名／代码位置／观察记录）。

- 满分锚点是质量天花板而非需求底线（如 Criterion 4 的智能缓存），Prompt 未明示的能力做不到时表现为得分低，不判零。

### Criterion 1: 文件类型识别与分发 (key: c01_file_type_detection, weight: 0.1)

采证方式：页面操作为主，代码为辅。

采证动作：依次加载一张图片（PNG 或 JPG）、一个文本文件（TXT 或 MD）、一个 PDF，逐个点击预览并记录渲染结果；结合代码确认 MIME 类型判定与各格式处理器的对应关系。

评分锚点：评估代码能否正确识别不同文件类型（MIME 类型）并调用对应的预览处理器。检查是否至少支持图片（JPG、PNG、GIF、SVG）、文档（PDF、TXT、MD），以及是否支持视频／音频。仅支持基础图片预览计 3 分；覆盖文档格式计 7 分；实现完整的 MIME 类型识别并为每种格式配备专用处理器计 10 分。

### Criterion 2: 文件上传／选择的易用性与健壮性 (key: c02_file_input, weight: 0.1)

采证方式：页面操作为主，代码为辅。

采证动作：分别用文件选择框和拖拽两种方式加入文件（拖拽可用 DataTransfer 模拟 drop 事件），观察是否有上传进度提示；尝试加入一个超大文件，记录是否有体积校验提示。

评分锚点：检查代码是否同时提供拖拽上传与传统文件选择两种方式，是否有文件体积校验、上传过程中的进度提示以及输入内容的清洗处理。只做了基础文件选择、没有拖拽扣 3 分；缺少文件体积校验扣 2 分；缺少上传进度提示扣 2 分。满分 10 分。

### Criterion 3: 预览渲染引擎 (key: c03_render_engine, weight: 0.1)

采证方式：代码为主，页面观察为辅。

采证动作：预览一个体积较大的文件和一个内容损坏／截断的文件，记录页面表现；结合代码确认各类型分别用了什么渲染手段。

评分锚点：评估代码是否针对不同文件类型采用了合适的渲染方式（图片用 canvas、PDF 用 PDF.js、代码文件做语法高亮等）。仅依赖浏览器原生能力、没有专门渲染处理扣 5 分；渲染未处理大文件或内容损坏这类边界情况扣 3 分。渲染体系完整、针对各格式做了专门优化计 10 分。

### Criterion 4: 缓存机制 (key: c04_caching, weight: 0.1)

采证方式：代码为主。

采证动作（辅助）：在两个文件之间来回切换预览各 2 次，观察第二次打开是否明显更快、是否重新解析。

评分锚点：检查代码是否实现了文件缓存策略，避免重复处理已经看过的文件。关注是否利用了客户端存储（IndexedDB、localStorage）以及是否有合理的缓存失效机制。仅依赖浏览器自身缓存计 5 分；自行实现客户端缓存计 8 分；实现了考虑文件体积与访问频次的智能缓存计 10 分。

### Criterion 5: 代码鲁棒性 (key: c05_robustness, weight: 0.1)

采证方式：代码为主。

采证动作（辅助）：加载一个后缀被改过的伪造文件和一个不支持的格式，观察是否给出友好提示而不是白屏或报错中断。

评分锚点：评估代码能否处理常见异常（文件损坏、格式不支持、加载失败等）并给出友好提示或兜底方案。鲁棒性强计 10 分，一般计 5 分，完全未处理异常计 0 分。

### Criterion 6: 创新功能 (key: c06_innovation, weight: 0.1)

采证方式：页面操作 + 代码。

评分锚点：检查是否包含提升体验的惊喜功能（如：1. 在预览内容里搜索文字 2. 对文档／图片做标注 3. 多个文件并排对比）。每实现一项实用创新加 3 分，上限 10 分。

### Criterion 7: 冗余功能检查 (key: c07_redundancy, weight: 0.1)

采证方式：代码为主。

评分锚点：严查三类冗余：1. 同类预览功能重复实现 2. 与文件预览无关的功能模块 3. 影响性能的花哨特效（如切换文件时不必要的动画）。每处冗余扣 3 分；核心功能被冗余代码干扰直接计 0 分。

### Criterion 8: 工程质量 (key: c08_engineering, weight: 0.1)

采证方式：代码。

评分锚点：审查模块化设计（文件处理／UI／渲染逻辑是否分离）、错误处理写法和代码复用性。存在全局状态污染或未使用设计模式扣 5 分；代码重复率过高（超过 30%）扣 5 分；错误处理不充分或前后不一致扣 5 分。满分 10 分。

### Criterion 9: 界面视觉专业性 (key: c09_visual_design, weight: 0.1)

采证方式：截图。

采证动作：桌面 1440×900 分别截取图片预览态与文本／PDF 预览态的整页图。

评分锚点：评估整体设计是否符合现代设计原则：1）配色和谐（主色不超过 3 种）2）预览区与操作控件的布局间距合理 3）文件元信息与界面元素使用专业的字体体系。每处视觉拥挤扣 3 分；刺眼配色扣 5 分；预览容器响应式表现差扣 5 分。满分 10 分。

### Criterion 10: 动态交互流畅性 (key: c10_interaction_fluency, weight: 0.1)

采证方式：页面操作。

采证动作：在不同类型的文件之间连续切换预览 3 次，记录加载耗时与过渡表现；对图片和文档试用缩放、滚动、翻页控件。

评分锚点：判断文件预览交互是否符合用户预期：1）常规文件的预览在 500ms 内加载完成 2）不同文件预览之间切换过渡自然 3）文档与图片的缩放、滚动、翻页控件直观易用。预览加载超过 2 秒且无任何反馈扣 5 分；不同类型文件切换时过渡生硬扣 3 分；导航控件不直观扣 5 分。满分 10 分。
