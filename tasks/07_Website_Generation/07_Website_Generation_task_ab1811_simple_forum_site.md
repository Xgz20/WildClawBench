# 简易论坛网站

## Prompt

请在 /tmp_workspace 下创建项目。如果启动网站时遇到端口冲突，请自行选择其他可用端口。

帮我写一个简易论坛的 HTML 页面。

代码要能直接跑起来看到效果。

## Expected Behavior

Agent 应生成可运行的论坛页面：能浏览帖子列表、发布新帖、进入帖子详情并回复，回复呈现层级关系；帖子按板块或分类组织，用户身份状态在页面上可见，数据在刷新后仍能保留。非法或空输入有校验提示。

- 每个 Criterion 标注 `采证方式`，如适用附 `采证动作`；评分必须引用证据（截图文件名／代码位置／观察记录）。

### Criterion 1: 论坛核心功能完整性 (key: c01_forum_core, weight: 0.1)

采证方式：页面操作为主，代码为辅。

采证动作：发一条新帖并确认它出现在列表中，进入详情回复一条，再对该回复继续回复，观察是否呈现嵌套层级；查看是否有登录入口和用户主页。

评分锚点：审查代码是否通过 HTML/JavaScript 准确实现论坛的必备功能，包括发帖、回复的层级结构、用户认证和内容展示层次。缺少基础增删改查计 0 分；仅实现基础的发帖／回复计 5 分；完整实现包含嵌套回复、帖子分类和用户主页的论坛流程计 10 分。

### Criterion 2: 数据持久化与状态管理 (key: c02_persistence_state, weight: 0.1)

采证方式：页面操作 + 代码。

采证动作：发帖后刷新页面确认内容仍在；登录后刷新确认登录态是否保持；结合代码确认存储方式（localStorage/sessionStorage 或后端）。

评分锚点：检查实现是否包含恰当的数据存储机制（localStorage/sessionStorage 或后端集成）、用户会话管理和内容实时更新。缺少数据持久化扣 5 分；用户登录状态跨会话不保持扣 3 分。满分要求数据流与状态同步顺畅无缝。

### Criterion 3: 导航与内容组织 (key: c03_navigation_structure, weight: 0.1)

采证方式：页面操作为主。

采证动作：在板块／分类间切换，使用搜索或筛选查找帖子，翻到第二页，记录面包屑导航与排序、标签功能是否可用。

评分锚点：评估论坛结构是否包含合理的分类、搜索功能、大批内容的分页和面包屑导航。内容层次扁平、没有分类扣 5 分；缺少搜索／筛选能力扣 3 分。完整实现应包含帖子排序、话题标签和直观的导航方式。

### Criterion 4: 用户互动与管理工具 (key: c04_interaction_moderation, weight: 0.1)

采证方式：页面操作 + 代码。

采证动作：对一条帖子点赞／投票，编辑并删除自己的帖子，查找举报或管理入口；结合代码确认用户角色与权限的实现。

评分锚点：检查代码是否包含用户互动功能，如投票／评分体系、用户声望、帖子编辑／删除能力和基础的版主管理工具。未实现用户角色与权限扣 5 分；缺少内容审核功能扣 3 分。满分要求形成完整的用户互动生态。

### Criterion 5: 代码鲁棒性 (key: c05_robustness, weight: 0.1)

采证方式：代码为主。

采证动作（辅助）：提交空内容的帖子，以及在正文里输入 `<script>alert(1)</script>` 提交，观察是否被拦截或转义。

评分锚点：评估代码能否处理常见异常情况（空输入、XSS 攻击、防灌水、非法用户操作等）并给出友好提示或恢复机制。鲁棒性强的代码应包含输入校验、内容净化和妥善的错误处理，计 10 分。鲁棒性一般计 5 分，完全未处理异常计 0 分。

### Criterion 6: 创新功能 (key: c06_innovation, weight: 0.1)

采证方式：页面操作 + 代码。

评分锚点：检查是否包含提升论坛体验的惊喜功能（如：1. 实时"正在输入"提示 2. 支持多媒体的富文本编辑器 3. 主题订阅通知 4. 深色／浅色主题切换 5. 带筛选的高级搜索）。每实现一项实用创新加 3 分，上限 10 分。

### Criterion 7: 冗余功能检查 (key: c07_redundancy, weight: 0.1)

采证方式：代码为主。

评分锚点：严查三类冗余：1. 同类功能重复实现（如多个发帖表单并存）2. 与论坛功能无关的模块（如内置小游戏或无关组件）3. 影响易用性的过量动画。每处冗余扣 3 分；冗余代码干扰论坛核心功能直接计 0 分。

### Criterion 8: 工程质量 (key: c08_engineering, weight: 0.1)

采证方式：代码。

评分锚点：审查模块化设计（论坛逻辑／展示／数据层分离）、HTML 语义化结构和代码组织的可维护性。HTML 结构缺乏语义化或无障碍属性扣 5 分；CSS/JS 代码重复率过高（超过 30%）扣 5 分；未采用组件化架构扣 5 分。满分要求代码整洁、易维护、可扩展。

### Criterion 9: 界面设计专业性 (key: c09_visual_design, weight: 0.1)

采证方式：截图。

采证动作：桌面 1440×900 截整页图（帖子列表页 + 帖子详情页），再切到 375px 宽视口截图确认移动端适配。

评分锚点：评估设计是否遵循现代论坛的界面原则：1）内容层次清晰、排版得当（字号不小于 14px、行距合适）2）配色统一且利于阅读 3）间距与对齐遵循栅格原则 4）移动端自适应。内容可读性差扣 3 分；视觉风格不统一扣 5 分；布局不自适应扣 5 分。满分 10 分。

### Criterion 10: 用户交互流畅性 (key: c10_interaction_fluency, weight: 0.1)

采证方式：页面操作。

采证动作：发帖、投票、切换板块各 3 次，记录反馈延迟与过渡效果；用 Tab 键遍历主要交互元素，确认键盘导航是否可用。

评分锚点：判断论坛交互是否提供优秀的用户体验：1）用户操作（发帖、投票等）有即时反馈，延迟不超过 100ms 2）版块之间切换过渡流畅 3）新内容、用户状态和可交互元素有清晰的视觉标识 4）支持键盘导航。每处交互缺少恰当反馈扣 5 分；导航流程令人困惑扣 3 分；无障碍性差扣 5 分。满分 10 分。
