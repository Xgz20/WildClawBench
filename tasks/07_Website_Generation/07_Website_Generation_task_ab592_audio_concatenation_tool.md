# 在线音频拼接工具

## Prompt

请在 /tmp_workspace 下创建项目。如果启动网站时遇到端口冲突，请自行选择其他可用端口。

我想做一个在线音频拼接工具：支持上传多段音频片段，用户可以在界面上自由调整音频的拼接顺序，并导出合成后的音频。

## Expected Behavior

Agent 应生成可运行的音频拼接工具页面：用户能一次上传多个音频文件，上传后的片段以列表或轨道形式展示（含文件名、时长等信息），可通过拖拽调整拼接顺序，支持试听预览，并能将拼接结果导出下载。异常文件应有友好提示。

### Criterion 1: 音频上传与格式处理 (key: c01_audio_upload, weight: 0.1)

采证方式：页面操作为主，代码为辅。

采证动作：准备 2-3 个音频文件（可用 ffmpeg 现场生成），通过上传入口一次选择多个文件上传，观察是否全部成功加载；再上传一个非音频文件，观察是否有格式校验提示；结合代码确认支持的格式与限制逻辑。

评分锚点：审查代码是否通过 HTML5 File API 准确实现多文件音频上传，是否支持常见音频格式（MP3、WAV、AAC、OGG），并检查是否包含音频格式校验、文件大小限制与格式转换能力。核心上传功能未实现计 0 分；仅支持基础的单文件上传计 5 分；完整实现带校验的多格式批量上传计 10 分。

### Criterion 2: 音频拼接引擎 (key: c02_concat_engine, weight: 0.1)

采证方式：代码为主，页面操作为辅。

采证动作（辅助）：上传两段音频后点击试听/预览，听拼接衔接处是否有断层或爆音；结合代码确认 Web Audio API 的 buffer 管理与拼接实现。

评分锚点：检查是否正确使用 Web Audio API 或类似技术实现音频拼接，包括音频 buffer 管理、无缝衔接与实时试听预览；评估拼接是否保持音质、无失真。拼接处存在间隙或爆音扣 5 分；缺少实时试听预览扣 3 分。满分 10 分。

### Criterion 3: 拖拽排序界面 (key: c03_drag_reorder, weight: 0.1)

采证方式：页面操作为主，代码为辅。

采证动作：上传多段音频后，拖拽其中一段调整顺序，记录拖拽过程中的视觉反馈（占位提示、放置区标识、动画）与排序结果；核对每段片段是否显示波形、时长、文件名。若拖拽模拟失效，按代码实现情况认定。

评分锚点：评估界面是否提供直观的拖拽排序功能，包括拖拽过程中的视觉反馈、放置区标识与平滑的过渡动画；检查界面是否清晰展示音频波形、时长与文件名。拖拽不可用或体验笨拙扣 5 分；视觉反馈差扣 3 分。满分 10 分。

### Criterion 4: 音频导出与下载 (key: c04_audio_export, weight: 0.1)

采证方式：页面操作为主，代码为辅。

采证动作：完成排序后点击导出，观察是否有进度指示、能否选择格式与质量、最终能否下载得到合成音频文件；结合代码确认导出编码实现。

评分锚点：检查代码是否包含完整的音频导出能力，含多种格式选项（MP3、WAV）、质量设置与合理的文件命名；评估导出过程是否有进度指示、能否高效处理大文件导出。导出功能缺失或只支持一种格式扣 5 分；导出过程无进度反馈扣 3 分。完整实现多格式支持计 10 分。

### Criterion 5: 代码鲁棒性 (key: c05_robustness, weight: 0.1)

采证方式：代码为主。

采证动作（辅助）：上传损坏或不支持格式的文件，观察错误提示；在音频处理过程中快速连点操作按钮，观察状态是否错乱。

评分锚点：评估代码能否处理常见异常情况（如音频文件损坏、格式不支持、内存受限、浏览器兼容性问题等）并提供友好的错误提示或恢复机制。鲁棒性强的代码应能有效处理文件大小限制、音频处理错误并平滑降级。错误处理全面计 10 分；有基础错误处理计 5 分；完全未处理异常计 0 分。

### Criterion 6: 创新功能 (key: c06_innovation, weight: 0.1)

采证方式：页面操作 + 代码。

评分锚点：检查是否包含提升体验的惊喜功能（如：1. 编辑时的实时波形可视化 2. 片段间的淡入淡出效果 3. 模板化批量处理 4. 音频响度归一化与音量调节 5. 面向熟练用户的键盘快捷键）。每实现一项实用创新加 2 分，上限 10 分。

### Criterion 7: 冗余功能检查 (key: c07_redundancy, weight: 0.1)

采证方式：代码为主。

评分锚点：严查三类冗余：1. 同类功能重复实现（如多套上传处理逻辑并存）2. 与音频处理无关的功能模块（如内置视频编辑器）3. 拖累音频处理性能的重度特效（如复杂的 3D 可视化）。每处冗余扣 3 分；冗余代码干扰核心音频功能直接计 0 分。

### Criterion 8: 工程质量 (key: c08_engineering, weight: 0.1)

采证方式：代码。

评分锚点：审查模块化设计（如音频处理/UI/文件处理分层）、错误处理模式与代码组织。存在全局状态污染或缺少职责分离扣 5 分；代码重复率过高（超过 30%）扣 5 分；未实现音频资源的清理释放扣 3 分。满分 10 分。

### Criterion 9: 界面视觉专业性 (key: c09_visual_design, weight: 0.1)

采证方式：截图。

采证动作：桌面 1440×900 截整页图（含已上传的多段音频轨道与控制区）。

评分锚点：评估整体设计是否符合现代设计原则：1）配色和谐、适合音频编辑场景（主色不超过 3 种）2）布局间距合理、音轨之间分隔清晰 3）字体排印专业、标签与控件清晰可读 4）音频功能图标直观易懂。每处视觉拥挤扣 3 分；对比度差影响可用性扣 5 分；音频控件布局混乱扣 5 分。满分 10 分。

### Criterion 10: 动态交互流畅性 (key: c10_interaction_fluency, weight: 0.1)

采证方式：页面操作。

采证动作：执行拖拽排序、试听预览、导出各 2 次，记录每步的响应延迟、波形渲染流畅度与处理过程中界面是否可响应。

评分锚点：判断动效是否符合音频编辑的工作流预期：1）拖拽响应时间不超过 100ms 2）用户操作后 200ms 内开始音频预览 3）波形渲染流畅不卡顿 4）所有音频操作有清晰的视觉反馈 5）处理过程中进度指示灵敏。每处交互卡顿扣 5 分；音频反馈延迟扣 3 分；音频处理期间界面无响应扣 5 分。满分 10 分。
