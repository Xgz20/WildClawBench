# 图片文字水印工具

## Prompt

请在 /tmp_workspace 下创建项目。如果启动网站时遇到端口冲突，请自行选择其他可用端口。

我想做一个给图片加文字水印的前端项目：用户上传一张图片后，可以在页面上输入想添加的文字，选择文字颜色、字号和位置；点击"添加水印"按钮后，图片上就会显示水印效果。用户还要能把加好水印的图片保存下来。

## Expected Behavior

Agent 应生成可运行的水印工具页面：支持上传图片并预览，用户可输入水印文字、选择颜色／字号／位置，点击"添加水印"后图片上出现相应水印效果，并能把加好水印的图片下载保存到本地。

### Criterion 1: 图片上传功能 (key: c01_image_upload, weight: 0.1)

采证方式：页面操作为主，代码为辅。

采证动作：上传一张 .png 或 .jpg 测试图片，确认预览正常显示；再尝试上传一个非图片文件（如 .txt），记录是否有校验提示；结合代码确认格式校验与大小限制的实现。

评分锚点：审查代码是否正确处理文件输入，包括图片格式校验（.jpg、.png 等）、大小限制、非法文件的错误处理，以及预览展示；检查上传的图片在加水印前是否正确渲染到画布上。没有上传功能计 0 分；基础上传可用但无校验计 5 分；校验与预览全部实现计 10 分。

### Criterion 2: 水印配置系统完备性 (key: c02_watermark_config, weight: 0.1)

采证方式：页面操作为主，代码为辅。

采证动作：逐项操作配置控件：输入文字、换颜色、调字号、调透明度、换位置，观察预览是否实时跟随变化，记录缺失的配置项。

评分锚点：评估代码是否允许用户完整定制水印文字，包含全部所需选项：文字输入、支持 hex/rgba 的颜色选择器、至少 3 种字体可选、带合理上下限（10-72pt）的字号控制、透明度调节（0-100%）、位置控制。每缺一项功能扣 2 分。须包含正确的输入校验和配置变化的实时预览。满分 10 分。

### Criterion 3: 水印应用机制 (key: c03_watermark_apply, weight: 0.1)

采证方式：页面操作为主，代码为辅。

采证动作：设置好水印后点击"添加水印"，放大观察文字边缘是否清晰、透明度是否生效；切换不同位置选项再次应用，核对位置是否准确。

评分锚点：检查代码是否用 Canvas API 或合适的替代方案把文字水印正确应用到图片上；验证文字在不同字号下保持渲染质量、透明度设置得以保留，并按用户选择准确定位（九宫格或自由定位）。文字应用后出现像素化扣 5 分；定位受限或不准确扣 3 分；文字样式渲染不正确扣 5 分。满分 10 分。

### Criterion 4: 图片导出保存功能 (key: c04_image_export, weight: 0.1)

采证方式：页面操作为主，代码为辅。

采证动作：点击保存／下载按钮，确认能得到加了水印的图片文件；结合代码确认 canvas.toDataURL() 或 canvas.toBlob() 的参数与 download 属性用法。

评分锚点：审查代码是否提供可用的保存机制，以原始质量导出加水印图片，提供合适的格式选项（.jpg、.png），保持宽高比，必要时保留元数据；检查 canvas.toDataURL() 或 canvas.toBlob() 的参数是否正确、download 属性是否实现。保存时画质下降扣 5 分；缺少格式选项扣 3 分；保存机制存在浏览器兼容问题扣 5 分。满分 10 分。

### Criterion 5: 代码鲁棒性 (key: c05_robustness, weight: 0.1)

采证方式：代码为主。

采证动作（辅助）：不上传图片直接点"添加水印"，观察是否有友好提示而非报错。

评分锚点：评估代码能否处理常见异常（不支持的图片格式、超大文件、图片加载失败、浏览器兼容问题等）并提供友好的错误提示或恢复机制。鲁棒性强、能有效处理这些边界情况计 10 分；鲁棒性一般计 5 分；完全未处理异常计 0 分。

### Criterion 6: 创新功能 (key: c06_innovation, weight: 0.1)

采证方式：页面操作 + 代码。

评分锚点：检查是否包含提升体验的惊喜功能（如：1. 支持多层水印 2. 水印模板一键套用 3. 多图批量处理 4. 高级文字效果如阴影／描边／渐变）。每实现一项实用创新加 3 分，上限 10 分。

### Criterion 7: 冗余功能检查 (key: c07_redundancy, weight: 0.1)

采证方式：代码为主。

评分锚点：严查三类冗余：1. 同类功能重复实现（如多套图片渲染方式并存）2. 与加水印无关的模块（如不必要的图片滤镜）3. 影响性能的花哨特效（如过多动画）。每处冗余扣 3 分；冗余代码干扰核心功能直接计 0 分。

### Criterion 8: 工程质量 (key: c08_engineering, weight: 0.1)

采证方式：代码。

评分锚点：审查模块化设计（如 UI／逻辑／文件处理分离）、大图性能优化、内存管理与异步操作的正确使用。全局状态污染或未用设计模式扣 5 分；代码重复率过高（超过 30%）扣 5 分；大图处理有明显性能问题扣 5 分。满分 10 分。

### Criterion 9: 界面视觉专业性 (key: c09_visual_design, weight: 0.1)

采证方式：截图。

采证动作：桌面 1440×900 截整页图（上传前 + 配置水印中两个状态）。

评分锚点：评估整体设计是否符合现代设计原则：1）配色和谐（主色不超过 3 种）2）布局间距合理（元素间距遵循 8px 倍数原则）3）专业字体体系（正文不小于 14px、行高不低于 1.5 倍）。每处视觉拥挤扣 3 分；刺眼配色扣 5 分；图文排版混乱扣 5 分。满分 10 分。

### Criterion 10: 动态交互流畅性 (key: c10_interaction_fluency, weight: 0.1)

采证方式：页面操作。

采证动作：连续调整字号／颜色 5 次，记录预览更新延迟；上传一张较大图片，观察处理过程是否有加载指示。

评分锚点：判断动效是否符合人类感知特性：1）水印预览实时更新（不超过 100ms）2）耗时操作有恰当的加载指示 3）所有用户操作有清晰的视觉反馈。水印预览卡顿扣 5 分；图片处理过程缺少加载状态扣 3 分；关键功能难以发现扣 5 分。满分 10 分。
