# 可注册发帖的论坛网页

## Prompt

请在 /tmp_workspace 下创建项目。如果启动网站时遇到端口冲突，请自行选择其他可用端口。

我想要一个能在 Linux 上运行的网页，做成论坛的样子，用户可以注册，也可以发帖。

Agent 应生成一个可运行的论坛站点：能注册新账号并登录，登录后可以发布帖子，帖子列表按论坛形式展示并显示作者与发布时间，帖子内容可以点开查看。注册与发帖的表单要有基本校验和提示。

### Criterion 1: 用户注册与认证功能 (key: c01_registration_auth, weight: 0.1)

采证方式：页面操作为主，代码为辅。

采证动作：走一遍注册流程（含空值、重复用户名、弱密码等非法输入各试一次），再用新账号登录并刷新页面确认登录态保持；在代码中确认密码的存储方式与会话／令牌处理。

评分锚点：检查代码是否实现了完整的用户注册系统，包括输入校验、密码哈希与认证流程。完全缺失计 0 分；有基础实现但缺少安全措施计 5 分；校验完善、密码安全存储（bcrypt／Argon2）、会话或令牌管理到位的完整实现计 10 分。

### Criterion 2: 帖子的发布与管理 (key: c02_post_management, weight: 0.1)

采证方式：页面操作为主，代码为辅。

采证动作：登录后发一篇帖子，再尝试编辑和删除自己的帖子；切换到另一个账号，确认能否越权编辑或删除他人帖子；记录帖子是否显示时间与作者信息，是否支持富文本或图片。

评分锚点：评估用户能否在正确的权限校验下创建、编辑和删除帖子。检查是否支持富文本、是否具备图片上传能力、帖子元信息（时间戳、作者信息）是否处理妥当。缺失计 0 分；有基础实现但缺少富文本或图片支持等功能计 5 分；功能齐备且权限控制得当的完善实现计 10 分。

### Criterion 3: 数据库设计与持久化层 (key: c03_data_persistence, weight: 0.1)

采证方式：代码为主。

采证动作（辅助）：发帖后刷新页面或重启服务，确认数据是否仍然存在。

评分锚点：审查数据库表结构设计、用户表与帖子表之间的关联关系以及查询优化。应做到合理的范式化、对高频查询字段建索引、使用预编译语句防止 SQL 注入。没有数据库迁移／表结构管理扣 5 分；关联关系设计不合理扣 3 分；查询存在注入风险扣 3 分。满分 10 分。

### Criterion 4: 面向 Linux 环境的部署适配 (key: c04_linux_deployment, weight: 0.1)

采证方式：代码为主。

评分锚点：检查部署过程是否考虑了 Linux 环境的特定要求：文件权限设置是否恰当、是否兼容常见的 Linux Web 服务器（Apache／Nginx）、是否通过 .env 之类的方式做环境配置、是否考虑进程管理（systemd 服务文件或 PM2 配置）。缺少部署说明扣 5 分；未处理权限问题扣 5 分。满分 10 分。

### Criterion 5: 代码鲁棒性 (key: c05_robustness, weight: 0.1)

采证方式：代码为主。

采证动作（辅助）：在发帖内容里输入一段带 HTML 标签的脚本文本，提交后查看是否被转义而非直接执行；短时间内连续提交注册请求，观察是否有频率限制。

评分锚点：评估代码能否应对常见异常情况（表单校验失败、数据库连接异常、注册／登录的频率限制、XSS 与 CSRF 防护等），并提供友好的错误提示与恢复机制。错误处理与安全措施完善计 10 分；鲁棒性一般、存在一些疏漏计 5 分；异常完全未处理计 0 分。

### Criterion 6: 创新功能 (key: c06_innovation, weight: 0.1)

采证方式：页面操作 + 代码。

评分锚点：检查代码是否包含提升体验的惊喜功能（如：1. 回复的实时通知 2. Markdown 或富文本编辑器 3. 用户声望／积分体系 4. 主题分类与标签）。每实现一项实用创新加 3 分，上限 10 分。

### Criterion 7: 冗余功能检查 (key: c07_redundancy, weight: 0.1)

采证方式：代码为主。

评分锚点：严查三类冗余：1. 同类功能重复实现（如多套认证方式并存却没有明确用途）2. 与论坛功能无关的模块（如没必要的过度埋点统计）3. 影响性能的花哨特效（如过量动画）。每处冗余扣 3 分；冗余代码干扰核心功能直接计 0 分。

### Criterion 8: 工程质量 (key: c08_engineering, weight: 0.1)

采证方式：代码。

评分锚点：审查模块化设计（MVC 或类似架构）、代码复用性、文档质量与测试覆盖，检查前后端之间的职责是否分离清楚。存在全局状态污染扣 5 分；代码重复率高扣 5 分；没有自动化测试扣 5 分。满分 10 分。

### Criterion 9: 界面视觉专业性 (key: c09_visual_design, weight: 0.1)

采证方式：截图。

采证动作：桌面 1440×900 截取帖子列表页与帖子详情页整页图，再切到 375×812 移动视口各截一张，比对响应式表现。

评分锚点：评估设计是否符合现代论坛的 UI 原则：1）帖子列表干净、层次清晰 2）响应式设计在移动端和桌面端都可用 3）色彩对比度符合无障碍标准（WCAG AA）4）字体体系统一。每处无障碍问题扣 3 分；布局不响应式扣 5 分；信息结构杂乱扣 5 分。满分 10 分。

### Criterion 10: 动态交互流畅性 (key: c10_interaction_fluency, weight: 0.1)

采证方式：页面操作。

采证动作：提交一次注册表单和一次发帖，记录是否有即时反馈、页面是否整页刷新、加载过程有无提示；故意让表单校验失败一次，确认已填内容是否被清空。

评分锚点：判断交互是否达到现代 Web 标准：1）表单提交有即时反馈 2）页面切换尽量避免整页刷新（采用 AJAX／SPA 方式）3）帖子列表支持无限滚动或分页 4）具备乐观更新的 UI 表现。页面刷新突兀扣 5 分；缺少加载指示扣 3 分；表单校验失败后不保留已填数据扣 5 分。满分 10 分。
