# HTML 赛车游戏

## Prompt

请在 /tmp_workspace 下创建项目。如果启动网站时遇到端口冲突，请自行选择其他可用端口。

我想用 HTML 写一个赛车游戏，可以直接在浏览器里玩。请保证生成的代码可以直接运行演示。

## Expected Behavior

Agent 应生成可运行的赛车游戏页面：玩家能用键盘控制赛车移动，赛道有清晰的边界，撞到边界或障碍会有相应反馈。游戏应有基本的比赛流程（开始、进行中、结束）和计时或圈数显示，画面动画流畅。

- 锚点中的"扣 N 分"从 10 分起扣，扣完为止；"加 N 分"从 0 分起加，上限 10 分。
- 每个 Criterion 标注 `采证方式`，如适用附 `采证动作`；评分必须引用证据（截图文件名／代码位置／观察记录）。

### Criterion 1: 赛车核心机制完整性 (key: c01_core_mechanics, weight: 0.1)

采证方式：页面操作为主，代码为辅。

采证动作：进入游戏，按页面提示用键盘（方向键/WASD）控制赛车前进、转向、刹车，故意撞向赛道边界，记录移动手感、碰撞反应和边界约束是否生效。

评分锚点：审查代码是否通过 HTML/JavaScript 准确实现赛车的基础机制，包括赛车移动控制、碰撞检测和合理的赛道边界。核心机制缺失计 0 分；仅实现基础移动计 5 分；包含加减速物理、完善碰撞处理等进阶特性计 10 分。

### Criterion 2: 渲染引擎构建质量 (key: c02_rendering_engine, weight: 0.1)

采证方式：页面观察 + 代码。

采证动作：游玩 15~30 秒，观察画面是否流畅、有无掉帧或撕裂拖影，结合代码确认渲染方案（Canvas/CSS 变换/WebGL）与优化手段。

评分锚点：评估游戏是否采用合适的渲染技术（Canvas、CSS 变换或 WebGL）并保持流畅动画（不低于 30 FPS）；检查是否应用了渲染优化手段（如精灵图批量绘制、对象池、离屏渲染）。正常游玩时帧率低于 30 FPS 扣 5 分；出现画面瑕疵扣 3 分。满分 10 分。

### Criterion 3: 赛道与环境设计 (key: c03_track_environment, weight: 0.1)

采证方式：页面观察为主，代码为辅。

采证动作：观察赛道形状（是否有弯道）、边界与检查点标识，确认赛道内外是否有明显视觉区分，是否有景物、障碍或地形变化，截图记录。

评分锚点：检查赛道设计是否合理，有清晰的边界、检查点和视觉指示；环境是否包含景物元素、障碍物或影响玩法的地形变化。赛道过于简单（只有直线）扣 5 分；赛道与场外区域无视觉区分扣 3 分。满分 10 分。

### Criterion 4: 比赛进程系统 (key: c04_race_progression, weight: 0.1)

采证方式：页面操作 + 代码。

采证动作：完整跑一局：观察是否有倒计时开局、圈数与计时显示、（多车时）名次显示，跑完后是否有成绩结算界面，记录各状态截图。

评分锚点：评估游戏是否包含圈数统计、计时系统、名次追踪（多车时）和成绩展示；检查是否有倒计时、比赛进行中、冲线结束等游戏状态。没有正式的比赛开始/结束流程扣 5 分；缺少圈数记录或计时扣 3 分；完整实现且带个人最佳成绩或成就等附加功能计 10 分。

### Criterion 5: 代码鲁棒性 (key: c05_robustness, weight: 0.1)

采证方式：代码为主。

采证动作（辅助）：快速连续按键 10 次、调整浏览器窗口大小，观察游戏是否报错或状态错乱。

评分锚点：评估代码能否处理常见异常情况（如窗口缩放、快速连续输入、浏览器兼容问题）并提供友好的错误提示或恢复机制。鲁棒性强、能有效兜住这些边界情况计 10 分；鲁棒性一般计 5 分；完全未处理异常计 0 分。

### Criterion 6: 创新功能 (key: c06_innovation, weight: 0.1)

采证方式：页面操作 + 代码。

评分锚点：检查代码是否包含提升体验的惊喜功能（如：1. 动态天气效果 2. 车辆自定义 3. 本地双人对战或简单 AI 对手）。每实现一项实用创新加 3 分，上限 10 分。

### Criterion 7: 冗余功能检查 (key: c07_redundancy, weight: 0.1)

采证方式：代码为主。

评分锚点：严查三类冗余：1. 同类功能的重复实现（如多套移动控制系统并存）2. 与赛车玩法无关的功能模块（如不相关的小游戏）3. 影响性能的花哨特效（如过量粒子效果导致卡顿）。每处冗余扣 3 分；冗余代码干扰核心功能直接计 0 分。

### Criterion 8: 工程质量 (key: c08_engineering, weight: 0.1)

采证方式：代码。

评分锚点：审查模块化设计（如游戏逻辑/视图/输入处理分层）、代码组织与文档。发现全局状态污染或未使用设计模式扣 5 分；代码重复率过高（超过 30%）扣 5 分；没有注释或文档扣 5 分。满分 10 分。

### Criterion 9: 界面视觉专业性 (key: c09_visual_design, weight: 0.1)

采证方式：截图。

采证动作：桌面 1440×900 截图（游戏进行中画面，含 HUD），另截一张高速行驶中的画面检查文字可读性。

评分锚点：评估整体设计是否符合现代游戏 UI 原则：1）HUD 清晰，显示速度、名次、圈数信息 2）游戏元素与背景对比度得当 3）高速游玩时文字仍可读（字号 ≥ 14px）。每处 UI 元素摆放不当扣 3 分；视觉层次不清扣 5 分；移动过程中文字不可读扣 5 分。满分 10 分。

### Criterion 10: 动态交互流畅性 (key: c10_interaction_fluency, weight: 0.1)

采证方式：页面操作。

采证动作：执行加速、刹车、碰撞各 3 次，记录按键到画面反应的延迟、车辆的惯性手感，以及碰撞/加速/刹车时的视觉或音效反馈。

评分锚点：判断操控与反馈是否符合玩家预期：1）输入响应延迟 ≤ 50ms 2）物理手感得当，有重量感和惯性 3）碰撞、加速、刹车有清晰的视觉/音效反馈。操控迟钝扣 5 分；物理表现失真到伤害玩法扣 3 分；关键游戏事件缺少反馈扣 5 分。满分 10 分。
