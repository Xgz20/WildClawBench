# K8s 集群监控看板

## Prompt

请在 /tmp_workspace 下创建项目。如果启动网站时遇到端口冲突，请自行选择其他可用端口。

我想做一个集群监控系统，技术栈用 React + Ant Design + AntV，请把下面几块做出来，代码要能跑起来演示：

1. 集群状态监控——用 AntV G6 做动态拓扑图，展示 Kubernetes 节点之间的关系，支持故障传播分析；用 ECharts 展示内存／CPU／GPU 使用率，超过阈值时能告警。

2. 支持跨时段数据叠加对比——让用户能把不同时间段的监控指标叠加在同一张图上做对比，便于看趋势、发现异常。

3. 告警规则配置表单——表单要能根据所选参数动态渲染字段，支持带嵌套逻辑运算符的复杂条件配置、阈值设置，以及多指标关联规则。

4. 监控数据筛选面板——做一套高级筛选，带日期选择器和多维度条件组合查询，让用户能在各类指标和节点分类中精确定位到需要的数据。

5. 实时监控仪表盘——组件能自动刷新、布局可自定义，并支持下钻，让用户能从集群总览一路看到具体节点的明细指标。

## Expected Behavior

Agent 应生成可运行的 React 监控看板：拓扑图能渲染出节点与连线并可交互选中，资源使用率图表带阈值与告警提示，能选择不同时间段做叠加对比，告警规则表单可随参数变化动态增减字段并配置嵌套条件，筛选面板可按日期与多维条件组合查询，仪表盘可自动刷新并从总览下钻到节点明细。数据可以用内置的模拟数据，不依赖真实集群。

### Criterion 1: G6 动态拓扑图 (key: c01_topology_graph, weight: 0.1)

采证方式：页面操作为主，代码为辅。

采证动作：进入集群拓扑页，记录节点类型（master／worker／pod）是否用不同形状或颜色区分；点击一个节点，观察是否高亮出相关联的组件；触发或选中一个故障节点，记录是否有故障传播路径的展示。

评分锚点：评估代码是否用 G6 完整实现了 K8s 集群拓扑可视化，包括：1）节点表达正确（master 节点、worker 节点、pod）且形状与配色恰当 2）用连线表达关系／依赖 3）可交互选中节点并高亮相关组件 4）故障传播可视化并能追溯路径。只展示基础节点、没有关系连线计 0 分；只有静态拓扑计 5 分；完整实现可交互拓扑并带故障传播分析计 10 分。

### Criterion 2: 资源使用率图表与告警 (key: c02_resource_charts, weight: 0.1)

采证方式：页面操作为主，代码为辅。

采证动作：观察 CPU／内存／GPU 图表不少于 15 秒，记录数据是否自动更新；找到阈值配置入口，把某个阈值调低到当前值以下，记录是否触发告警提示；确认图表上是否能叠加查看历史数据。

评分锚点：检查代码是否正确实现 CPU／内存／GPU 使用率图表，包括：1）数据实时更新 2）阈值可配置且有视觉标识 3）超阈值时触发告警机制 4）可与历史数据对比。图表静态、无实时更新扣 3 分；阈值不可配置扣 3 分；未实现告警通知扣 4 分。满分 10 分。

### Criterion 3: 跨时段数据叠加对比 (key: c03_time_overlay, weight: 0.1)

采证方式：页面操作为主。

采证动作：选择两个不同时间段并叠加到同一张图上，截图记录图例、颜色是否能区分不同时段；调整时间范围选择器，确认图表随之更新；记录是否有对比用的统计指标（如均值、峰值差异）。

评分锚点：评估代码能否有效支持跨时段指标对比：1）同一张图支持多组数据叠加 2）不同时段之间有清晰的视觉区分 3）时间范围可交互选择 4）提供时段对比的统计分析工具。只有基础叠加、缺少图例／区分度扣 5 分；时间选择方式受限扣 3 分；缺少统计对比扣 2 分。满分 10 分。

### Criterion 4: 动态告警规则表单 (key: c04_alert_rule_form, weight: 0.1)

采证方式：页面操作为主，代码为辅。

采证动作：打开告警规则配置，切换所选参数（如从 CPU 切到 GPU），记录表单字段是否随之变化；尝试添加一组嵌套的 AND／OR 条件和多个指标的关联规则，记录能否保存并回显。

评分锚点：评估代码是否实现了完全动态的表单：1）字段随所选参数变化 2）支持复杂的嵌套逻辑运算符（AND／OR／NOT）3）阈值配置支持多种比较运算符 4）支持多指标关联规则。只有基础表单输入计 0 分；实现了动态字段但没有复杂条件计 5 分；完整支持逻辑嵌套与多指标关联计 10 分。

### Criterion 5: 代码鲁棒性 (key: c05_robustness, weight: 0.1)

采证方式：代码为主。

采证动作（辅助）：在筛选面板输入非法的时间范围（如结束早于开始）或空条件查询，观察是否给出提示而不是页面崩溃。

评分锚点：评估代码能否处理常见异常（如接口失败、数据加载错误、返回格式异常等）并给出友好提示或恢复机制。检查是否有错误边界、加载态和兜底 UI 组件。鲁棒性强、能有效处理这些边界情况计 10 分；鲁棒性一般计 5 分；完全未处理异常计 0 分。

### Criterion 6: 创新功能 (key: c06_innovation, weight: 0.1)

采证方式：页面操作 + 代码。

评分锚点：检查代码是否包含提升体验的惊喜功能（如：1. AI 异常检测 2. 指标的自然语言查询界面 3. 故障自动根因分析 4. 结合上下文的修复建议）。每实现一项实用创新加 3 分，上限 10 分。

### Criterion 7: 冗余功能检查 (key: c07_redundancy, weight: 0.1)

采证方式：代码为主。

评分锚点：严查三类冗余：1. 同类可视化组件重复实现（如多个图表库做同一件事）2. 与监控无关的功能模块（如多余的管理工具）3. 影响性能的花哨特效（如过多动画拖慢看板响应）。每处冗余扣 3 分；冗余代码干扰核心功能直接计 0 分。

### Criterion 8: 工程质量 (key: c08_engineering, weight: 0.1)

采证方式：代码。

评分锚点：审查模块化设计（如数据获取／处理／可视化分层）、组件复用性、状态管理和构建流程自动化。存在全局状态污染或未按 React 规范组织扣 5 分；代码重复率过高（超过 30%）扣 5 分；缺少妥当的错误处理或性能优化扣 5 分。满分 10 分。

### Criterion 9: 界面视觉专业性 (key: c09_visual_design, weight: 0.1)

采证方式：截图。

采证动作：桌面 1440×900 截整页图（拓扑页、监控仪表盘、告警规则配置页各一张）。

评分锚点：评估整体设计是否遵循 Ant Design 规范：1）一致地使用 Ant Design 组件，不做破坏设计体系的定制 2）布局与间距得当（遵循 8px 栅格）3）信息层级专业（主次信息区分清楚）。每处元素未对齐扣 3 分；组件样式不统一扣 5 分；看板布局混乱扣 5 分。满分 10 分。

### Criterion 10: 仪表盘体验与响应式 (key: c10_dashboard_experience, weight: 0.1)

采证方式：页面操作。

采证动作：观察仪表盘 30 秒确认是否自动刷新并尝试修改刷新间隔；拖拽或调整一个组件的布局后刷新页面，记录设置是否保留；从集群总览下钻到某个节点明细并返回；把视口切到 1280×800 和 768×1024，记录布局是否正常。

评分锚点：判断监控仪表盘是否实现：1）自动刷新且间隔可配置 2）组件布局可自定义并能保存用户偏好 3）从总览到明细的下钻导航顺畅 4）响应式设计在不同尺寸下都可用。缺少自动刷新扣 5 分；布局不可自定义扣 3 分；下钻导航生硬扣 3 分；不支持响应式扣 3 分。满分 10 分。
