# 老年人用药提醒小工具

## Prompt

请在 /tmp_workspace 下创建项目。如果启动网站时遇到端口冲突，请自行选择其他可用端口。

请帮我写一个给老年人用的用药提醒小工具，要完整、可以直接复制粘贴拿来用的那种。

## Expected Behavior

Agent 应生成可运行的用药提醒应用：可以添加药品（名称、剂量、服药频率）并设置提醒时间，到点有提醒，用户确认服药后有记录；界面为老年人做了适老化设计（大字号、高对比度、大按钮、操作步骤少）；用药数据在刷新或重启后仍然保留。

### Criterion 1: 用药提醒核心功能 (key: c01_reminder_core, weight: 0.1)

采证方式：页面操作为主，代码为辅。

采证动作：新增一条用药提醒（填写药名、剂量、频率、提醒时间）并保存，截图记录；将提醒时间设为最近时刻，等待或触发提醒，执行"已服药"确认，验证记录是否更新。

评分锚点：评估代码是否实现了用药提醒的核心功能：提醒排程、药品信息设置（名称、剂量、频率）、通知提醒机制、服药确认。核心功能缺失计 0 分；只实现了基础提醒、缺乏灵活性计 5 分；支持多种排程方式（每天、每周、指定时间）并带药品信息管理计 10 分。

### Criterion 2: 适老化界面设计 (key: c02_elderly_accessibility, weight: 0.1)

采证方式：页面观察 + 截图 + 代码。

采证动作：桌面 1440×900 截主界面图；结合代码核对正文字号、颜色对比度、按钮触控区尺寸、完成一次核心操作所需步骤数，并确认是否提供字号调节选项。

评分锚点：检查 UI 是否遵循适老化设计原则：大字号（不小于 16px）、高对比度配色（对比度不低于 7:1）、简化的导航、清晰的按钮（触控目标不小于 44×44px）、完成任务的步骤尽量少。每违反一条无障碍准则扣 3 分。只有界面对老年用户有针对性设计（包括字号缩放选项）才能给满分。

### Criterion 3: 照护者协同功能 (key: c03_caregiver_integration, weight: 0.1)

采证方式：页面操作为主，代码为辅。

采证动作：查找并进入照护者相关入口（漏服提醒、服药依从性统计、远程监护面板、紧急联系人），逐一截图记录实际可用情况。

评分锚点：评估代码是否实现了照护者监护能力：漏服药提醒、服药依从性追踪、远程监护面板、紧急联系人集成。缺少远程监护扣 3 分；缺少依从性追踪扣 3 分；未实现紧急联系人功能扣 4 分。满分 10 分。

### Criterion 4: 数据持久化与离线可用 (key: c04_persistence_offline, weight: 0.1)

采证方式：页面操作 + 代码。

采证动作：新增用药数据后刷新页面／重启应用，验证数据是否保留；结合代码确认存储方案（localStorage／数据库）、数据校验与备份恢复机制，以及断网状态下能否正常使用。

评分锚点：评估代码是否妥善处理数据存储（本地存储或数据库实现）、同步机制与离线可用性；检查是否有数据校验、备份机制与恢复流程。应用重启后用药数据不保留扣 5 分；必须联网才能使用扣 5 分。具备完整离线能力且有数据完整性保护才能给满分。

### Criterion 5: 代码鲁棒性 (key: c05_robustness, weight: 0.1)

采证方式：代码为主。

采证动作（辅助）：在表单中输入非法值（空药名、负剂量）提交，观察是否有友好提示。

评分锚点：评估代码能否处理常见异常情况（如错误输入、网络中断、系统通知被禁用等）并提供友好的错误提示或恢复机制。鲁棒性强、能有效处理这些边界情况计 10 分；鲁棒性一般计 5 分；完全未处理异常计 0 分。

### Criterion 6: 创新功能 (key: c06_innovation, weight: 0.1)

采证方式：页面操作 + 代码。

评分锚点：检查代码是否包含提升体验的惊喜功能（如：1. 用摄像头识别药品 2. 语音提醒与语音指令 3. 根据用户习惯自适应调整提醒时间 4. 服药依从性的游戏化激励）。每实现一项实用创新加 3 分，上限 10 分。

### Criterion 7: 冗余功能检查 (key: c07_redundancy, weight: 0.1)

采证方式：代码为主。

评分锚点：严查三类冗余：1. 同类功能重复实现（如多套通知系统并存）2. 与用药提醒无关的功能模块（如内置游戏板块）3. 影响性能的花哨特效（如可能让老年用户困惑的多余动画）。每处冗余扣 3 分；冗余代码干扰核心功能直接计 0 分。

### Criterion 8: 工程质量 (key: c08_engineering, weight: 0.1)

采证方式：代码。

评分锚点：审查模块化设计（如数据层／UI 层／通知层分离）、单元测试覆盖与构建流程自动化。发现全局状态污染或未使用设计模式扣 5 分；代码重复率过高（超过 30%）扣 5 分；构建流程未自动化扣 5 分。满分 10 分。

### Criterion 9: 界面视觉专业性 (key: c09_visual_design, weight: 0.1)

采证方式：截图。

采证动作：桌面 1440×900 截整页图（主界面 + 添加用药界面）。

评分锚点：评估整体设计是否符合现代设计原则：1）配色和谐（主色不超过 3 种）2）布局间距合理（元素间距遵循 8px 倍数原则）3）专业字体体系（面向老年用户正文字号不小于 16px、行高不低于 1.5 倍）。每处视觉拥挤扣 3 分；刺眼配色扣 5 分；图文排版混乱扣 5 分。满分 10 分。

### Criterion 10: 动态交互流畅性 (key: c10_interaction_fluency, weight: 0.1)

采证方式：页面操作。

采证动作：执行新增用药、确认服药、切换页面各 3 次，记录每次操作的反馈、过渡动画时长观感，以及关键功能按钮是否一眼可辨。

评分锚点：判断动效是否符合老年用户的感知特点：1）每个操作都有清晰反馈 2）过渡动画时长控制在 400~700ms（针对老年用户适当放慢）3）重要操作有明显的视觉提示，最好辅以听觉提示。每处操作无反馈扣 5 分；过渡效果令人困惑扣 3 分；关键功能按钮难以找到扣 5 分。满分 10 分。
