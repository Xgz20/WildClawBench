# CSS 代码自动格式化工具

## Prompt

请在 /tmp_workspace 下创建项目。如果启动网站时遇到端口冲突，请自行选择其他可用端口。

我想做一个 CSS 代码自动格式化工具：用户把杂乱或未格式化的 CSS 代码粘贴进文本框，工具自动完成格式化，并且保留代码里的注释，让代码更易读。

## Expected Behavior

Agent 应生成可运行的 CSS 格式化工具页面：用户在输入框粘贴杂乱的 CSS 后触发格式化，输出区展示整理后的代码，缩进与换行规范统一，原有注释完整保留；非法输入有明确提示，格式化结果便于复制。

### Criterion 1: CSS 解析与格式化核心能力 (key: c01_parsing_formatting, weight: 0.1)

采证方式：页面操作为主，代码为辅。

采证动作：粘贴一段包含嵌套规则、媒体查询、keyframes、厂商前缀的杂乱 CSS 并执行格式化，对比输出是否结构正确、风格统一；再用含复杂选择器的样例复测一次，记录两次结果。

评分锚点：评估代码能否正确解析各类 CSS 结构（包括嵌套规则、媒体查询、keyframes、厂商前缀等）并以统一风格格式化。解析器在复杂 CSS 上直接失败计 0 分；能处理基础选择器和属性、但高级特性处理吃力计 5 分；完整支持全部 CSS3 规范（含复杂选择器与 at 规则）计 10 分。

### Criterion 2: 注释保留与排版 (key: c02_comment_preservation, weight: 0.1)

采证方式：页面操作为主，代码为辅。

采证动作：粘贴一段含行内注释、块注释与文件头版权注释的 CSS 执行格式化，逐条核对注释是否全部保留、内容未被改动、位置仍与相关规则对应。

评分锚点：检查工具在格式化时能否正确识别并保留各类 CSS 注释（行内注释、块注释、版权头注释），既不改动注释内容，也不破坏注释与相关规则的对应关系。有注释丢失或错位扣 5 分；注释位置处理不一致扣 3 分；不必要地改动注释内部原有排版扣 2 分。满分 10 分。

### Criterion 3: 格式化选项可配置性 (key: c03_formatting_options, weight: 0.1)

采证方式：页面操作为主，代码为辅。

采证动作：查看设置区提供了哪些格式化选项（缩进宽度、Tab/空格、单行/多行、属性排序等），修改至少 2 项后重新格式化，验证输出是否随配置变化。

评分锚点：审查工具是否提供格式化偏好配置（如缩进宽度、Tab 与空格切换、规则单行/多行、属性排序等）。没有任何选项计 0 分；只有基础选项计 5 分；配置全面、默认值合理并提供格式化效果的可视化预览计 10 分。

### Criterion 4: 非法 CSS 输入的错误处理 (key: c04_error_handling, weight: 0.1)

采证方式：页面操作为主，代码为辅。

采证动作：粘贴一段有语法错误的 CSS（如缺少右花括号、属性缺冒号）执行格式化，记录错误提示内容、是否标注出错行号、页面是否仍可正常使用。

评分锚点：评估工具对非法 CSS 输入的处理：是否给出有帮助的错误信息、高亮出错行、给出修复建议，或在保留原始输入的前提下尝试部分格式化。不标注错误位置扣 3 分；报错信息晦涩难懂扣 4 分；遇到非法输入直接崩溃、无法恢复扣 5 分。满分 10 分。

### Criterion 5: 代码鲁棒性 (key: c05_robustness, weight: 0.1)

采证方式：代码为主。

采证动作（辅助）：粘贴含 Unicode 选择器、转义序列与异常空白的 CSS 片段，观察格式化结果是否正常。

评分锚点：评估代码能否处理各类边界情况（超长文件、异常空白模式、选择器中的 Unicode 字符、转义序列等）并给出恰当的响应。鲁棒性强、能有效处理这些边界情况计 10 分；鲁棒性一般计 5 分；完全未处理边界情况计 0 分。

### Criterion 6: 创新功能 (key: c06_innovation, weight: 0.1)

采证方式：页面操作 + 代码。

评分锚点：检查是否包含提升体验的惊喜功能（如：1. 格式化输出带语法高亮 2. 原始代码与格式化结果的可视化对比 3. CSS 属性排序/分组选项 4. 在格式化之外提供压缩开关）。每实现一项实用创新加 3 分，上限 10 分。

### Criterion 7: 冗余功能检查 (key: c07_redundancy, weight: 0.1)

采证方式：代码为主。

评分锚点：严查三类冗余：1. 本可合并的重复解析逻辑 2. 与 CSS 格式化无关的多余处理步骤 3. 拖慢核心格式化功能的高开销特性。每处冗余扣 3 分；冗余代码干扰核心功能直接计 0 分。

### Criterion 8: 工程质量 (key: c08_engineering, weight: 0.1)

采证方式：代码。

评分锚点：审查模块化设计（词法分析/解析/格式化组件分离）、针对各类 CSS 结构的测试覆盖与可维护性。全局状态引发副作用扣 5 分；代码重复率过高（超过 30%）扣 5 分；核心格式化函数没有单元测试扣 5 分。满分 10 分。

### Criterion 9: 界面视觉专业性 (key: c09_visual_design, weight: 0.1)

采证方式：截图。

采证动作：桌面 1440×900 截整页图（输入区、输出区与设置区同框）。

评分锚点：评估 UI 是否符合现代设计原则：1）输入/输出区域划分清晰、对比度充足 2）布局间距合理（元素间距遵循 8px 倍数原则）3）专业字体体系、代码展示使用等宽字体（不小于 14px）。每处局促的界面元素扣 3 分；对比度差导致代码难读扣 5 分；布局混乱、间距不统一扣 5 分。满分 10 分。

### Criterion 10: 动态交互流畅性 (key: c10_interaction_fluency, weight: 0.1)

采证方式：页面操作。

采证动作：执行格式化、复制结果、清空各 3 次，记录响应延迟与反馈提示；粘贴较大的 CSS 文本格式化一次，观察是否卡死、有无处理中提示；尝试常用操作的快捷键。

评分锚点：判断工具的使用体验：1）常规文件的格式化响应时间在 500ms 以内 2）处理大文件时有视觉反馈 3）常用操作（格式化、复制、清空）配有快捷键。格式化时 UI 明显卡死扣 5 分；缺少处理中的视觉指示扣 3 分；格式化结果不便选中/复制扣 5 分。满分 10 分。
