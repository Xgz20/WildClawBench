# 云安全中心资产总览页

## Prompt

请在 /tmp_workspace 下创建项目。如果启动网站时遇到端口冲突，请自行选择其他可用端口。

我是个程序员，想用 HTML 和 JS 做一个云安全中心「资产管理」模块下「资产总览」页面的原型界面。

请尽量做成能直接跑起来演示的代码。

Agent 应生成可运行的资产总览页面：页面呈现资产清单、安全状态、风险分布、告警汇总等分区，配有图表展示资产与风险数据，提供资产的搜索与筛选，并用颜色区分不同的安全等级。点击筛选、查看资产详情等交互应有即时反馈。

### Criterion 1: 总览看板结构 (key: c01_dashboard_structure, weight: 0.1)

采证方式：页面观察 + 代码。

采证动作：打开页面，记录顶部到底部各个分区（资产清单、安全状态、风险分布、告警汇总）的划分与排布；查看 HTML 源码确认是否使用了 header、main、section 等语义化标签。

评分锚点：评估代码是否实现结构清晰的看板布局，包含资产清单、安全状态、风险分布、告警汇总等合适分区。检查 HTML 结构是否正确使用语义化元素（header、main、section 等）。无清晰的看板结构计 0 分；有基础元素但缺乏组织计 5 分；布局符合安全看板最佳实践、信息层级合理计 10 分。

### Criterion 2: 数据可视化组件 (key: c02_data_visualization, weight: 0.1)

采证方式：页面操作为主，代码为辅。

采证动作：逐个查看页面上的图表（资产分布饼图、风险趋势折线图、漏洞柱状图等），把鼠标悬停到图表元素上，记录是否出现提示浮层或高亮等交互反馈；结合代码确认使用的图表库和数据绑定方式。

评分锚点：审查图表实现情况（如资产分布饼图、风险趋势折线图、漏洞柱状图）。评估是否使用了合适的可视化库（D3.js、Chart.js 等），可视化是否清晰传达安全洞察。图表为静态、不可交互扣 5 分；缺少数据绑定扣 3 分；缺少无障碍支持扣 2 分。满分 10 分。

### Criterion 3: 资产搜索与筛选 (key: c03_search_filter, weight: 0.1)

采证方式：页面操作为主，代码为辅。

采证动作：在搜索框输入一个关键词，记录结果变化是否实时；再依次按资产类型、风险等级、合规状态等条件筛选，观察是否支持多条件叠加、是否显示结果条数。

评分锚点：检查代码是否实现按资产类型、风险等级、合规状态等条件筛选的搜索机制。验证筛选系统是否有实时反馈和结果计数。无搜索／筛选计 0 分；只有基础搜索、没有高级筛选计 5 分；同时具备搜索、多条件筛选和高效的结果处理计 10 分。

### Criterion 4: 安全状态指示与告警 (key: c04_security_indicators, weight: 0.1)

采证方式：页面观察 + 截图。

采证动作：截图记录页面上的安全状态标识（威胁等级、合规状态）与告警列表，检查不同等级是否用不同颜色区分、是否标注严重级别和时间戳。

评分锚点：评估代码是否实现安全状态的可视化标识（威胁等级、合规状态）以及安全告警的通知机制。验证标识是否使用了合适的颜色编码、严重级别和时间戳。安全标识缺少视觉区分扣 5 分；无告警优先级体系扣 3 分；缺少时效性信息处理扣 2 分。满分 10 分。

### Criterion 5: 代码鲁棒性 (key: c05_robustness, weight: 0.1)

采证方式：代码为主。

采证动作（辅助）：在搜索框输入一个不存在的关键词，观察是否有空态提示而非白屏。

评分锚点：评估代码能否处理常见异常（如接口调用失败、数据集为空、用户输入错误等）并提供友好的错误提示或恢复机制。检查是否有恰当的错误处理、数据校验和兜底展示。鲁棒性强、能处理所有这些边界情况计 10 分；一般计 5 分；完全未处理异常计 0 分。

### Criterion 6: 创新功能 (key: c06_innovation, weight: 0.1)

采证方式：页面操作 + 代码。

评分锚点：检查是否包含提升安全监控体验的惊喜功能（如：1. 实时威胁可视化 2. 展示资产关系的交互式拓扑图 3. 可自定义的风险评分体系 4. 用 AI 自动给资产分类）。每实现一项实用创新加 3 分，上限 10 分。

### Criterion 7: 冗余功能检查 (key: c07_redundancy, weight: 0.1)

采证方式：代码为主。

评分锚点：严查三类冗余：1. 同类功能重复实现（如用多种方式查看同一份资产数据）2. 与安全资产管理无关的功能模块（如不相干的系统工具）3. 影响性能的花哨特效（如拖慢看板加载的过度动画）。每处冗余扣 3 分；核心功能被冗余代码干扰直接计 0 分。

### Criterion 8: 工程质量 (key: c08_engineering, weight: 0.1)

采证方式：代码。

评分锚点：审查模块化设计（如数据获取／数据处理／可视化分层）、代码复用性和性能优化。存在全局变量污染或未使用设计模式扣 5 分；代码重复率过高（超过 30%）扣 5 分；未使用性能优化手段（如懒加载、分页）扣 5 分。满分 10 分。

### Criterion 9: 界面视觉专业性 (key: c09_visual_design, weight: 0.1)

采证方式：截图。

采证动作：桌面 1440×900 截整页图，另截一张首屏（不滚动）图，用于判断关键信息是否无需滚动即可看到。

评分锚点：评估整体设计是否符合现代安全看板设计原则：1）配色合适（安全用蓝／绿，警告用黄，严重问题用红）2）信息密度与布局合理（关键信息无需滚动即可获取）3）专业的字体体系（层级统一、数据表格易读）。每处视觉元素杂乱扣 3 分；安全状态标识有误导性扣 5 分；信息架构混乱扣 5 分。满分 10 分。

### Criterion 10: 动态交互流畅性 (key: c10_interaction_fluency, weight: 0.1)

采证方式：页面操作。

采证动作：记录页面首次加载耗时；触发一次数据刷新，确认是否整页重载；从总览点进某个资产的详情，数清所需点击次数；连续做 3 次筛选／排序记录是否卡顿；再切到 768 宽和 375 宽各截一张图检查响应式。

评分锚点：判断交互元素是否满足安全运营需求：1）看板更新／刷新无需整页重载 2）不超过 2 次点击即可查看资产详情 3）适配不同屏幕尺寸的响应式设计 4）不同数据视图之间切换过渡流畅。看板加载慢（超过 2s）扣 5 分；筛选／排序时交互卡顿扣 3 分；响应式失效、在不同屏幕上布局错乱扣 5 分。满分 10 分。
