# 物流管理系统

## Prompt

请在 /tmp_workspace 下创建项目。如果启动网站时遇到端口冲突，请自行选择其他可用端口。

我想要一个物流管理系统：管理员可以跟踪货物运输状态、管理运输车辆和司机信息；客户可以登录查看自己的货物状态和运输日志。

要求生成完整、可运行的项目代码，所有代码文件完整不省略，并配上简单易懂的注释。如果需求涉及外部 API 或用户数据（图片、视频、音频等），请用 mock 数据代替。

## Expected Behavior

Agent 应生成可运行的物流管理系统：管理员登录后可查看货物运输状态与轨迹记录、管理车辆与司机信息；客户登录后可查看自己名下货物的当前状态与运输日志。系统应区分管理员与客户两种角色的登录与权限，数据可用 mock 数据支撑。

### Criterion 1: 货物跟踪核心功能 (key: c01_cargo_tracking, weight: 0.1)

采证方式：页面操作为主，代码为辅。

采证动作：以管理员身份进入系统，打开货物跟踪页面，查看某一票货物的状态、位置与节点记录；确认状态变更是否留有完整的历史轨迹。

评分锚点：评估代码是否正确实现货物跟踪功能，包括实时状态更新、位置跟踪与运输节点记录；检查系统是否为所有货物流转与状态变更保留完整的审计轨迹。缺货物跟踪计 0 分；有基础跟踪但缺实时能力计 5 分；实现完善、含时间戳、位置数据与状态历史计 10 分。

### Criterion 2: 车辆与司机管理 (key: c02_vehicle_driver_mgmt, weight: 0.1)

采证方式：页面操作为主，代码为辅。

采证动作：进入车辆管理与司机管理页面，分别尝试新增、编辑一条记录，并查看车辆-司机-线路的分派功能是否存在。

评分锚点：审查系统是否支持对运输车辆（登记、保养计划、可用状态）与司机信息（档案、驾照、排班、绩效指标）的全面管理；检查是否有把车辆分派给司机与线路的功能。管理功能缺失计 0 分；仅实现基础增删改查计 5 分；管理全面、含排班、可用性跟踪与分派算法计 10 分。

### Criterion 3: 登录认证与角色权限 (key: c03_auth_rbac, weight: 0.1)

采证方式：页面操作 + 代码。

采证动作：分别用管理员与客户账号登录，确认两种角色看到的功能范围不同；尝试以客户身份访问管理员页面，观察是否被拦截；在代码中核对密码哈希与会话管理实现。

评分锚点：检查系统是否为管理员与客户实现了各自的认证流程与恰当的基于角色的权限控制；核实是否落实密码哈希、会话管理及常见攻击防护等安全措施。缺认证计 0 分；有基础登录但缺角色区分或安全措施计 5 分；认证完善安全、权限控制到位计 10 分。

### Criterion 4: 客户货物查询界面 (key: c04_customer_portal, weight: 0.1)

采证方式：页面操作为主。

采证动作：以客户身份登录，查看名下货物的当前状态、历史运输日志与预计送达时间，记录界面展示效果与可交互功能。

评分锚点：评估客户登录后能否查看货物状态，包括历史运输日志、当前位置、预计送达时间与通知能力；检查界面是否友好、货物流转是否有清晰的可视化。缺客户跟踪界面计 0 分；有基础查看但缺交互功能计 5 分；实现完善、含跟踪可视化、搜索功能与通知系统计 10 分。

### Criterion 5: 代码鲁棒性 (key: c05_robustness, weight: 0.1)

采证方式：代码为主。

采证动作（辅助）：在登录表单提交空值／错误账号，观察错误提示是否友好。

评分锚点：评估代码能否处理常见异常情况（如非法输入、数据库连接失败、认证错误等）并提供友好的错误提示或恢复机制。错误处理与恢复机制完善计 10 分；鲁棒性一般、有部分错误处理计 5 分；完全没有异常处理计 0 分。

### Criterion 6: 创新功能 (key: c06_innovation, weight: 0.1)

采证方式：页面操作 + 代码。

评分锚点：检查是否包含提升体验的惊喜功能（如：1. 基于历史数据的预计送达时间预测 2. 移动端自适应设计与推送通知 3. 展示货运线路的交互式地图 4. 提示天气对配送延误影响的天气集成）。每实现一项实用创新加 3 分，上限 10 分。

### Criterion 7: 冗余功能检查 (key: c07_redundancy, weight: 0.1)

采证方式：代码为主。

评分锚点：严查三类冗余：1. 相似功能的重复实现（如多套货物状态更新方式并存）2. 与物流管理无关的功能模块（如内置小游戏或不必要的社交功能）3. 影响性能的花哨特效（如拖慢页面加载的重动画）。每发现一处冗余扣 3 分；冗余代码干扰核心功能直接计 0 分。

### Criterion 8: 工程质量 (key: c08_engineering, weight: 0.1)

采证方式：代码。

评分锚点：审查模块化设计（如业务逻辑／视图／数据访问分层）、单元测试覆盖与构建流程自动化；检查设计模式使用、代码复用性与可维护性。发现全局状态污染或未使用设计模式扣 5 分；代码重复率过高（超过 30%）扣 5 分；构建流程未自动化扣 5 分。满分 10 分。

### Criterion 9: 界面视觉专业性 (key: c09_visual_design, weight: 0.1)

采证方式：截图。

采证动作：桌面 1440×900 分别截取管理员端与客户端主页面整页图。

评分锚点：评估整体设计是否符合现代设计原则：1）配色和谐（主色不超过 3 种）2）布局间距合理（元素间距遵循 8px 倍数原则）3）专业字体体系（正文不小于 14px、行高不低于 1.5 倍）4）导航与信息层级直观。每处视觉拥挤扣 3 分；刺眼配色扣 5 分；图文排版混乱扣 5 分。满分 10 分。

### Criterion 10: 动态交互流畅性 (key: c10_interaction_fluency, weight: 0.1)

采证方式：页面操作。

采证动作：在主要页面间切换 3 次并点击核心按钮，记录点击反馈延迟、过渡动画与物流数据可视化表现。

评分锚点：判断动效是否符合人类感知特性：1）点击反馈延迟不超过 100ms 2）过渡动画时长控制在 300~500ms 3）视觉焦点引导清晰 4）物流信息有直观的数据可视化。每处操作无反馈扣 5 分；快速滚动或切换时出现视觉残影扣 3 分；关键功能按钮难以找到扣 5 分。满分 10 分。
