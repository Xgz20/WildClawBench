# 元宝风格聊天窗口

## Prompt

请在 /tmp_workspace 下创建项目。如果启动网站时遇到端口冲突，请自行选择其他可用端口。

我想用 AntDesignPro 做一个类似腾讯元宝的聊天窗口，代码请用 TypeScript 写。

## Expected Behavior

Agent 应生成可运行的聊天窗口页面：左侧是会话列表，中间是消息区，下方是输入区，顶部有标题栏。发出和收到的消息用不同样式和位置区分，带头像和时间，新消息进来时自动滚到底部。输入框可以打字并发送消息，会话之间可以切换。

### Criterion 1: 聊天窗口基础结构 (key: c01_chat_layout, weight: 0.1)

采证方式：页面操作为主，代码为辅。

采证动作：打开页面，逐一确认会话列表侧栏、消息区、输入区、顶部标题栏是否齐全并截图；把窗口宽度从 1440 缩到 768，观察布局是否自适应。

评分锚点：审查代码是否用 Ant Design Pro 组件实现了类似腾讯元宝聊天窗口的关键 UI 部件：会话列表侧栏、聊天消息区、输入区和顶部标题栏。检查布局是否妥善处理了响应式适配。基础结构缺失计 0 分；只实现了部分结构计 5 分；完整还原元宝式结构且样式到位计 10 分。

### Criterion 2: 消息展示功能 (key: c02_message_display, weight: 0.1)

采证方式：页面操作为主。

采证动作：发送若干条消息并接收回复，观察收发消息的样式与左右位置是否区分、是否显示时间与头像；连发多条确认消息区是否自动滚到最新一条。

评分锚点：评估代码是否实现了消息气泡，能通过不同样式与位置正确区分发出和收到的消息。检查是否显示时间戳、是否有头像，以及消息区是否自动滚动到最新消息。缺少按时间分组扣 3 分；未实现已读回执扣 3 分；不支持图片、文件等富媒体内容展示扣 2 分。满分 10 分。

### Criterion 3: 消息输入与发送 (key: c03_message_input, weight: 0.1)

采证方式：页面操作为主，代码为辅。

采证动作：在输入框输入文本并发送，尝试打开表情选择器、点击附件上传入口；提交一条空消息看是否被拦截；在代码中核对消息对象的 TypeScript 类型定义。

评分锚点：检查输入区是否包含文本输入、表情选择器、文件附件入口和发送按钮。核实代码是否用规范的 TypeScript 类型完成了消息的组装、校验与发送。缺少表情支持扣 3 分；未实现文件附件扣 3 分；没有输入校验扣 2 分。消息对象的 TypeScript 接口定义不完整或有误扣 5 分。满分 10 分。

### Criterion 4: 历史消息与会话管理 (key: c04_conversation_management, weight: 0.1)

采证方式：页面操作 + 代码。

采证动作：在会话列表中切换会话，观察消息是否正确切换；使用会话搜索输入关键词看是否过滤；向上滚动消息区看是否加载更多历史；检查未读数标记；刷新页面确认状态是否保留。

评分锚点：评估代码是否包含会话列表管理、分页加载历史消息、会话搜索功能和未读消息标记。检查是否使用 React hooks 或 Redux 做了合理的状态管理。缺少会话搜索扣 3 分；未实现历史消息分页扣 3 分；跨会话没有状态持久化扣 4 分。满分 10 分。

### Criterion 5: 代码鲁棒性 (key: c05_robustness, weight: 0.1)

采证方式：代码为主。

采证动作（辅助）：发送一条超长文本消息、进入一个没有任何消息的空会话，观察页面是否溢出或报错。

评分锚点：评估代码能否处理常见异常（如网络错误、超长消息、空状态、消息发送失败等）并提供友好提示或恢复机制。鲁棒性强、能有效处理这些边界情况的计 10 分。鲁棒性一般计 5 分，完全未处理异常计 0 分。

### Criterion 6: 创新功能 (key: c06_innovation, weight: 0.1)

采证方式：页面操作 + 代码。

评分锚点：检查是否包含提升体验的惊喜功能（如：1. 消息表情回应 2. 语音／视频消息 3. 带动画的已读回执 4. 消息翻译）。每实现一项实用创新加 3 分，上限 10 分。

### Criterion 7: 冗余功能检查 (key: c07_redundancy, weight: 0.1)

采证方式：代码为主。

评分锚点：严查三类冗余：1. 同类功能重复实现（如多套消息发送逻辑并存） 2. 与聊天无关的功能模块（如不相干的仪表盘组件） 3. 影响性能的花哨特效（如过量动画）。每处冗余扣 3 分；若冗余代码干扰了核心功能，直接计 0 分。

### Criterion 8: 工程质量 (key: c08_engineering, weight: 0.1)

采证方式：代码。

评分锚点：审查模块化设计（如 UI 组件／服务／状态管理分离）、TypeScript 类型质量、组件复用性和代码组织。存在全局状态污染扣 3 分；TypeScript 接口／类型定义粗糙或使用了 any 类型扣 3 分；代码重复率过高（超过 30%）扣 2 分；组件架构不遵循 Ant Design Pro 惯例扣 2 分。满分 10 分。

### Criterion 9: 界面视觉专业性 (key: c09_visual_design, weight: 0.1)

采证方式：截图。

采证动作：桌面 1440×900 截整页图，包含会话列表、消息区与输入区。

评分锚点：评估整体设计是否遵循 Ant Design 规范：1）统一使用 Ant Design 组件，不做自定义覆盖 2）用 Ant Design 栅格系统排布，间距合理 3）字体层级遵循 Ant Design 的文本规范。每处视觉元素不统一扣 3 分；跳出 Ant Design 配色体系扣 3 分；布局混乱、不符合 Ant Design Pro 范式扣 4 分。满分 10 分。

### Criterion 10: 动态交互流畅性 (key: c10_interaction_fluency, weight: 0.1)

采证方式：页面操作。

采证动作：发送消息、切换会话各 3 次，记录反馈延迟与过渡动画；观察加载历史消息时是否出现加载态指示。

评分锚点：判断动效是否符合人类感知特性：1）消息发送反馈延迟不超过 100ms 2）新消息出现和会话切换有过渡动画 3）加载状态与进度提示清晰。每处操作无反馈扣 3 分；滚动或过渡卡顿扣 3 分；拉取数据时缺少加载状态扣 4 分。满分 10 分。
