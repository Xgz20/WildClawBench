# 声音反应小游戏

## Prompt

请在 /tmp_workspace 下创建项目。如果启动网站时遇到端口冲突，请自行选择其他可用端口。

我想用 HTML 和 JavaScript 实现一个"声音反应"系统：给游戏加一套声音反应机制，玩家需要对特定音效及时做出反应，才能躲开危险或抓住机会。

实现上可以参考这样的思路：播放特定音效，同时设置需要玩家快速反应的事件，比如躲避陷阱、攻击敌人。

请在代码里写好注释，方便其他开发者理解你的实现思路。

## Expected Behavior

Agent 应生成可运行的声音反应游戏页面：游戏会播放音效并触发对应事件，玩家通过键盘/鼠标等输入在时间窗口内做出反应，反应成功与失败都有明确反馈。声音提示应配有同步的视觉提示，页面提供音量、静音等基本音频控制。代码应带有清楚的注释。

### Criterion 1: 音频加载与管理系统 (key: c01_sound_loading, weight: 0.1)

采证方式：代码为主，页面为辅。

采证动作（辅助）：打开页面并启动游戏，观察音频是否正常加载播放、控制台是否有加载报错。

评分锚点：评估代码是否实现完善的音频资源管理系统，包括预加载能力、格式兼容性检查、不支持格式时的兜底机制。未实现音频加载计 0 分；有基础音频加载但没有错误处理计 5 分；完整实现预加载、多格式支持和完善错误处理的系统计 10 分。

### Criterion 2: 声音驱动的事件触发 (key: c02_sound_event_trigger, weight: 0.1)

采证方式：页面操作为主，代码为辅。

采证动作：启动游戏，等待音效事件触发，分别在提示后立即反应和故意不反应，记录两种情况下的游戏反馈与判定结果；结合代码确认反应时间窗口的实现。

评分锚点：检查代码是否把声音事件与玩法机制有效关联，包括准确的声音判定时间窗口，以及需要玩家反应时的恰当反馈。声音事件与玩法无关联计 0 分；有基础的声音-动作关联但时间窗口过于死板计 5 分；反应时机校准得当且用户反馈清晰计 10 分。

### Criterion 3: 玩家反应输入机制 (key: c03_reaction_input, weight: 0.1)

采证方式：页面操作 + 代码。

采证动作：分别用键盘和鼠标（如支持）触发反应操作各 3 次，快速连按同一按键观察是否有防抖处理；结合代码确认输入检测与时间校验实现。

评分锚点：评估玩家对声音做出反应的输入检测实现，包括键盘/鼠标/触摸控制、恰当的防抖处理和无障碍选项。未实现反应输入计 0 分；有基础输入检测但无无障碍特性计 5 分；输入方式全面、带无障碍支持和精确时间校验计 10 分。

### Criterion 4: 音画同步反馈系统 (key: c04_audio_visual_feedback, weight: 0.1)

采证方式：页面观察为主。

采证动作：将声音静音后继续游戏，观察是否仍能通过视觉提示识别需要做出的反应；截图记录音效触发时的视觉提示形态。

评分锚点：审查系统是否提供与音频信号对应的视觉提示，确保玩家在关闭声音或听障情况下也能识别需要做出的反应。音频提示完全没有视觉配合计 0 分；有基础视觉指示计 5 分；音画完整同步并考虑无障碍设计计 10 分。

### Criterion 5: 代码鲁棒性 (key: c05_robustness, weight: 0.1)

采证方式：代码为主。

采证动作（辅助）：不与页面交互直接刷新加载，观察自动播放受限时是否有友好提示或引导。

评分锚点：评估代码能否处理常见异常（浏览器音频 API 限制、自动播放限制、音频设备变化等）并提供友好提示或恢复机制。完全未处理异常计 0 分；只覆盖部分关键边界情况计 5 分；全面覆盖主要音频相关异常的错误处理计 10 分。

### Criterion 6: 创新功能 (key: c06_innovation, weight: 0.1)

采证方式：页面操作 + 代码。

评分锚点：检查是否包含提升体验的惊喜功能（如：1. 基于反应时间的动态难度调整 2. 声音可视化以增强无障碍体验 3. 支持用户自定义上传音效）。每实现一项实用创新加 3 分，上限 10 分。

### Criterion 7: 冗余功能检查 (key: c07_redundancy, weight: 0.1)

采证方式：代码为主。

评分锚点：严查三类冗余：1. 重复的音频处理逻辑 2. 影响性能的不必要音频处理 3. 对核心反应玩法没有贡献的过度复杂音频特性。每处冗余扣 3 分；冗余代码干扰核心功能直接计 0 分。

### Criterion 8: 工程质量 (key: c08_engineering, weight: 0.1)

采证方式：代码。

评分锚点：审查模块化设计（音频引擎/游戏逻辑/UI 分离）、音频资源管理模式与代码组织原则。发现全局音频状态污染扣 5 分；代码重复率过高（超过 30%）扣 5 分；音频逻辑与游戏机制未分离扣 5 分。满分 10 分。

### Criterion 9: 界面设计规范 (key: c09_interface_design, weight: 0.1)

采证方式：截图。

采证动作：桌面 1440×900 截整页图（游戏主界面，含音频控制区），记录音效事件的视觉指示与反应反馈动画。

评分锚点：评估整体设计是否符合现代设计原则：1）音频事件有清晰的视觉指示 2）反应操作有恰当的反馈动画 3）专业的声音控制 UI（音量调节、静音选项）。每处不清晰的音频相关视觉指示扣 3 分；反应反馈混乱扣 5 分；缺少基本音频控制扣 5 分。满分 10 分。

### Criterion 10: 音频反应性能 (key: c10_audio_performance, weight: 0.1)

采证方式：页面操作 + 代码。

采证动作：连续进行 5 轮以上声音反应，记录音效触发到反馈出现的延迟观感、密集播放时页面是否掉帧卡顿。

评分锚点：判断音频反应系统的响应速度与性能：1）音频-反应延迟不超过 100ms 2）音效播放期间帧率稳定 3）音频资源内存管理高效。存在明显音频延迟扣 5 分；密集播放音频时性能下降扣 3 分；音频处理存在内存泄漏扣 5 分。满分 10 分。
