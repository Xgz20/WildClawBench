# 班级考试成绩查看页

## Prompt

请在 /tmp_workspace 下创建项目。如果启动网站时遇到端口冲突，请自行选择其他可用端口。

我们的用户名编码规则里，第 5、6 位合起来表示班级号。例如 23010102 表示 01 班的学生，同理 23010201 表示 02 班的学生。

我想要一个查看班级考试成绩的模板页面，能显示班级平均分。如果同一个学生在同一场考试里有多条成绩，只取最高的那条参与计算。

模板名字你自己定，权限设置成教师可以查看。页面具体怎么组织你来安排。

## Expected Behavior

Agent 应生成可运行的成绩查看页面：能从用户名的第 5、6 位解析出班级号并据此分组，展示学生成绩明细和班级平均分，同一学生同场考试的多条成绩只取最高分参与计算。页面带有教师身份的访问控制，非教师身份访问时给出相应提示。

### Criterion 1: 成绩查看模板实现完整性 (key: c01_score_template, weight: 0.1)

采证方式：页面操作为主，代码为辅。

采证动作：打开页面，查看学生成绩列表与班级平均分是否都展示；挑一个班级人工核算平均分，与页面显示值比对；确认同一学生同场考试有多条成绩时页面取的是最高分。

评分锚点：核实模板是否正确展示学生个人成绩并计算班级平均分。实现应能正确解析用户名以提取班级号（第 5、6 位）并据此对学生分组。检查同一学生在同一场考试有多条成绩时，是否只取最高分参与计算。核心展示逻辑缺失计 0 分；实现了基础成绩展示但没有正确的班级分组计 5 分；全部需求完整实现（包括从用户名正确提取班级、正确选取最高分）计 10 分。

### Criterion 2: 用户名解析逻辑正确性 (key: c02_username_parsing, weight: 0.1)

采证方式：代码为主，页面操作为辅。

采证动作：在代码中定位班级号提取函数，用 23010102、23010201 两个样例核对结果是否分别为 01 班、02 班；再检查位数不足或含非数字的用户名走的是哪条分支。

评分锚点：评估代码是否能从用户名的第 5、6 位正确提取班级号（例如 23010102 → 01 班，23010201 → 02 班）。检查提取逻辑是否处理了非法用户名、位数缺失等边界情况。提取逻辑错误扣 5 分；未处理边界情况扣 3 分。对所有合法输入解析正确且能妥善处理异常得满分。

### Criterion 3: 最高分选取算法 (key: c03_max_score_selection, weight: 0.1)

采证方式：代码为主。

采证动作（辅助）：在数据中找一个同场考试有多条成绩的学生，核对页面参与计算的是不是最高的那条。

评分锚点：检查代码在学生同一场考试有多条成绩时，是否正确识别并只使用最高分。算法应高效地完成比较取最大值，不做不必要的遍历。算法选分错误扣 5 分；结果正确但效率低扣 3 分。实现既正确又优化的计 10 分。

### Criterion 4: 教师权限控制 (key: c04_teacher_permission, weight: 0.1)

采证方式：页面操作 + 代码。

采证动作：以教师身份进入页面确认可以查看；再以非教师身份（或直接访问受限地址）尝试进入，记录是否被拦截以及提示文案；结合代码确认权限校验和会话处理的实现方式。

评分锚点：评估模板是否包含把查看权限限制为教师的访问控制机制，应含身份校验以及未授权访问时的相应错误提示。无权限控制计 0 分；实现了基础身份校验但存在安全漏洞计 5 分；实现了健壮的权限控制，含正确的会话校验与错误处理计 10 分。

### Criterion 5: 代码鲁棒性 (key: c05_robustness, weight: 0.1)

采证方式：代码为主。

采证动作（辅助）：输入格式错误的用户名、切换到没有学生的空班级，观察页面是否报错或白屏。

评分锚点：评估代码能否处理常见异常（如数据缺失、用户名格式错误、空班级等）并提供友好提示或恢复机制。鲁棒性强的代码应能有效处理这些边界情况。能覆盖全部常见边界情况计 10 分，处理一般计 5 分，完全没有异常处理计 0 分。

### Criterion 6: 创新功能 (key: c06_innovation, weight: 0.1)

采证方式：页面操作 + 代码。

评分锚点：检查是否包含提升体验的惊喜功能（如：1. 排序／筛选 2. 图表等数据可视化 3. 报表导出 4. 班级之间的对比分析）。每实现一项实用创新加 3 分，上限 10 分。

### Criterion 7: 冗余功能检查 (key: c07_redundancy, weight: 0.1)

采证方式：代码为主。

评分锚点：严查三类冗余：1. 同类功能重复实现 2. 与成绩查看无关的功能模块 3. 无谓影响性能的花哨特效。每处冗余扣 3 分；若冗余代码干扰了核心功能，直接计 0 分。

### Criterion 8: 工程质量 (key: c08_engineering, weight: 0.1)

采证方式：代码。

评分锚点：审查模块化设计（如数据／视图／控制层分离）、代码可读性和可维护性。检查注释是否到位、命名是否统一、组件是否可复用。存在全局状态污染或未使用设计模式扣 5 分；代码重复率过高（超过 30%）扣 5 分；文档注释匮乏或难以维护扣 5 分。

### Criterion 9: 界面视觉专业性 (key: c09_visual_design, weight: 0.1)

采证方式：截图。

采证动作：桌面 1440×900 截整页图，覆盖成绩列表与班级平均分区域。

评分锚点：评估整体设计是否符合现代设计原则：1）配色和谐（主色不超过 3 种） 2）布局间距合理（元素间距遵循 8px 倍数原则） 3）专业字体体系（正文字号不小于 14px、行高不低于 1.5 倍）。每处视觉拥挤扣 3 分；刺眼配色扣 5 分；图文排版混乱扣 5 分。满分 10 分。

### Criterion 10: 动态交互流畅性 (key: c10_interaction_fluency, weight: 0.1)

采证方式：页面操作。

采证动作：点击排序、切换筛选条件各 3 次，记录反馈延迟与过渡动画表现；确认排序、筛选等关键按钮是否一眼能找到。

评分锚点：判断动效是否符合人类感知特性：1）点击反馈延迟不超过 100ms 2）过渡动画时长控制在 300~500ms 3）排序按钮、筛选器等交互元素有清晰的视觉焦点引导。每处操作无反馈扣 5 分；快速交互时出现视觉残影扣 3 分；关键功能按钮难以找到扣 5 分。满分 10 分。
