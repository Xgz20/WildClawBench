# 动态天气模拟经营游戏

## Prompt

请在 /tmp_workspace 下创建项目。如果启动网站时遇到端口冲突，请自行选择其他可用端口。

我想用 HTML 和 JavaScript 实现一个模拟游戏：动态天气与环境影响。

核心玩法是一套动态天气系统——不同的天气状况会影响游戏环境和玩家操作。可以通过调整场景参数来模拟天气对资源产出或角色行为的影响。

请做出这个游戏，并在代码里写好注释，方便其他开发者理解你的实现思路。

Agent 应生成可运行的天气模拟游戏页面：具备多种天气状态并可切换，天气变化对场景环境（植被、水位等）和玩家操作产生可见影响，页面有相应的视觉反馈。代码应带有清楚的注释。

### Criterion 1: 天气系统实现 (key: c01_weather_system, weight: 0.1)

采证方式：页面操作为主，代码为辅。

采证动作：进入游戏，通过页面控件或等待自动变化，逐一触发不同天气状态并记录种类数量；观察天气切换过程是否有过渡动画与视觉／音频反馈。

评分锚点：评估代码是否实现了完整的动态天气系统，包含多种天气状态（雨、雪、晴、风等）及状态间的平滑过渡。无天气系统计 0 分；只有基础天气状态、无过渡计 5 分；包含至少 5 种不同天气状况、带平滑过渡动画和恰当的视觉／音频反馈计 10 分。

### Criterion 2: 环境影响机制 (key: c02_environmental_impact, weight: 0.1)

采证方式：页面操作为主，代码为辅。

采证动作：切换天气后观察场景中植被、水位、地形等环境元素是否发生变化，记录哪些元素有响应、变化是否影响玩法。

评分锚点：检查天气状况是否对游戏环境（植被生长、水位、地形状况等）产生有意义的影响，且后果可见、符合逻辑。天气对环境没有可见影响扣 5 分；影响纯属视觉装饰、无玩法效果扣 3 分；至少 3 个环境元素能对天气变化动态响应可得满分。

### Criterion 3: 天气对玩家操作的影响 (key: c03_player_interaction, weight: 0.1)

采证方式：页面操作为主，代码为辅。

采证动作：在不同天气下执行相同的玩家操作（移动、采集等），对比移动速度、效率等数值差异并记录。

评分锚点：评估天气状况是否以有意义的方式影响玩家操作／行动（移动速度、能力效果、资源采集速率等）。玩家与天气毫无交互计 0 分；仅实现简单的速度／可见度影响计 5 分；天气能创造策略性玩法选择、促使玩家调整行为计 10 分。

### Criterion 4: 天气预报与调控机制 (key: c04_forecast_control, weight: 0.1)

采证方式：页面操作 + 代码。

采证动作：查看页面是否有天气预报 UI、季节循环显示；若有玩家影响天气的入口则触发一次并记录效果。

评分锚点：评估模拟系统是否包含天气预报、季节规律或可由玩家影响的天气调控机制。天气纯随机变化、无规律扣 5 分；无预报类 UI 元素扣 3 分；实现了有可预测规律的季节循环、并可选地支持玩家干预天气可得满分。

### Criterion 5: 代码鲁棒性 (key: c05_robustness, weight: 0.1)

采证方式：代码为主。

采证动作（辅助）：快速连续切换天气 5 次以上，观察是否报错或状态错乱。

评分锚点：评估代码能否处理常见异常情况（天气快速切换、极端条件、用户误操作等）并提供友好的错误提示或恢复机制。鲁棒性强、能有效处理这些边界情况计 10 分；鲁棒性一般计 5 分；完全未处理异常计 0 分。

### Criterion 6: 创新功能 (key: c06_innovation, weight: 0.1)

采证方式：页面操作 + 代码。

评分锚点：检查是否包含提升体验的惊喜功能（如：1. 基于天气的事件触发 2. 随天气变化的动态配乐 3. 天气历史记录与统计）。每实现一项实用创新加 3 分，上限 10 分。

### Criterion 7: 冗余功能检查 (key: c07_redundancy, weight: 0.1)

采证方式：代码为主。

评分锚点：严查三类冗余：1. 相似天气效果的重复实现 2. 与天气／环境模拟无关的功能模块 3. 影响性能却对模拟没有价值的花哨特效。每处冗余扣 3 分；核心功能被冗余代码干扰直接计 0 分。

### Criterion 8: 工程质量 (key: c08_engineering, weight: 0.1)

采证方式：代码。

评分锚点：审查模块化设计（如天气系统／环境／UI 分层）、代码组织与实现效率。存在全局状态污染或未使用设计模式扣 5 分；代码重复率过高（超过 30%）扣 5 分；未对天气粒子渲染做优化扣 5 分。满分 10 分。

### Criterion 9: 视觉设计质量 (key: c09_visual_design, weight: 0.1)

采证方式：截图。

采证动作：桌面 1440×900 分别在 2-3 种不同天气下截取整页图，对比天气效果的真实感与状态区分度。

评分锚点：评估天气效果与环境变化是否符合现代设计原则：1）视觉表现真实 2）动画与过渡使用得当 3）不同天气状态视觉区分清晰。每处不够可信的天气效果扣 3 分；天气状态切换生硬突兀扣 5 分；环境影响的视觉反馈不清晰扣 5 分。满分 10 分。

### Criterion 10: 性能与优化 (key: c10_performance, weight: 0.1)

采证方式：页面操作 + 代码。

采证动作：连续切换天气 3 次，观察切换过程中是否掉帧卡顿；结合代码检查粒子系统的优化手段与低端设备适配选项。

评分锚点：判断天气模拟运行是否高效：1）天气过渡期间保持 60 FPS 2）粒子系统与环境特效有优化 3）针对不同设备能力实现了合适的细节分级。天气变化时出现明显掉帧扣 5 分；渲染手法低效扣 3 分；缺少面向低端设备的优化选项扣 5 分。满分 10 分。
