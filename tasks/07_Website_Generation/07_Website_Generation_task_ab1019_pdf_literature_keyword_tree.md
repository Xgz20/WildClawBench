# 移动端 PDF 文献分类工具

## Prompt

请在 /tmp_workspace 下创建项目。如果启动网站时遇到端口冲突，请自行选择其他可用端口。

我想做一个网页工具：

1. 总体功能：读取 PDF 文献，进行识别和总结
2. 具体实现：PDF 文献可以按研究方向关键词分类，并按时间先后、方向差异、研究机构、期刊等类别以树状结构组织（这个功能是重点）
3. 文献很多的时候用关键词来筛选。首页展示关键词，字号大小代表相关文献的数量，不同颜色和词代表不同类别的文章。点击某个关键词后展开一棵可以放大缩小的小树，用来查看文献的范围，有点像苹果的分类栏——没点开时只有几个图标，点开后显示全部图标
4. 请提供面向移动端的 HTML、CSS 和 JavaScript 代码

## Expected Behavior

Agent 应生成一个可在移动端浏览器打开的文献管理页面：支持导入／读取 PDF 并提取文本，抽取关键词并给出内容概要。首页以关键词云呈现，字号随相关文献数量变化、颜色区分类别；点击关键词后展开可缩放的树状视图，能按时间、研究方向、机构、期刊等维度查看文献。整体布局与交互按手机屏幕适配。

### Criterion 1: PDF 读取与文本提取 (key: c01_pdf_extraction, weight: 0.1)

采证方式：页面操作为主，代码为辅。

采证动作：通过页面入口导入一份 PDF，记录导入后是否显示提取出的文本或篇目信息；对照原文检查段落、标题等结构是否保留。

评分锚点：检查代码是否实现了可用的 PDF 解析机制，能从上传的 PDF 文件中提取文本内容。未实现 PDF 读取计 0 分；基础文本提取可用但结构／排版有问题计 5 分；文本提取稳定且保留文档结构计 10 分。

### Criterion 2: 文献摘要与关键词抽取 (key: c02_summarization, weight: 0.1)

采证方式：页面操作 + 代码。

采证动作：导入文献后查看是否生成关键词列表和内容摘要，记录抽取出的关键词与摘要文本，判断其是否与文献内容相关。

评分锚点：评估文本分析能力，看能否从学术 PDF 中识别关键信息并生成有意义的摘要。完全没有摘要功能计 0 分；只有基础元数据提取计 3 分；关键词抽取可用但摘要能力弱计 7 分；关键词抽取与摘要都做得扎实计 10 分。

### Criterion 3: 层级树状结构实现 (key: c03_tree_structure, weight: 0.1)

采证方式：页面操作为主，代码为辅。

采证动作：打开树状视图，依次切换按时间、研究方向、研究机构、期刊等分类维度，逐项记录哪些维度可用；展开／收起若干节点，记录交互是否顺畅。

评分锚点：评估用于按题目要求的各类维度组织文献的树状结构实现。缺少树状结构计 0 分；有基础树但缺乏合适的分类维度计 5 分；树支持多种分类方案但交互不够顺畅计 8 分；功能完备、题目要求的分类维度齐全计 10 分。

### Criterion 4: 关键词云可视化 (key: c04_keyword_cloud, weight: 0.1)

采证方式：页面操作 + 截图。

采证动作：在首页截图记录关键词云，核对字号是否随文献数量变化、颜色是否区分类别；点击一个关键词，记录展开为小树的过程与缩放操作是否可用。

评分锚点：评估首页关键词云的实现，看是否通过字号大小体现文献数量。没有关键词云计 0 分；有基础词云但字号／配色处理不到位计 5 分；字号与配色都到位但过渡生硬计 8 分；可视化完整、交互顺滑计 10 分。

### Criterion 5: 代码鲁棒性 (key: c05_robustness, weight: 0.1)

采证方式：代码为主。

采证动作（辅助）：导入一个非 PDF 文件或损坏的文件，在没有文献数据时打开树状视图，记录是否有友好提示而非白屏或报错。

评分锚点：评估代码能否处理常见异常情况并给出友好提示或恢复机制。完全没有异常处理计 0 分；有基础错误处理但缺少恢复机制计 5 分；错误处理全面且提供了对用户友好的恢复方式计 10 分。

### Criterion 7: 冗余功能检查 (key: c07_redundancy, weight: 0.1)

评分锚点：评估界面是否遵循专业的移动端设计原则、是否针对小屏做了优化。每处不适合触控操作的元素扣 3 分；布局不响应式扣 5 分；文字在手机上小到难以阅读扣 5 分。满分 10 分。

评分锚点：判断动效与性能是否针对移动设备做了优化。交互过程有明显卡顿扣 5 分；状态切换过程中出现渲染问题扣 3 分；文献数量增多后出现内存问题扣 5 分。满分 10 分。
