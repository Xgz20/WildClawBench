# 本地软件分类展示页

## Prompt

请在 /tmp_workspace 下创建项目。如果启动网站时遇到端口冲突，请自行选择其他可用端口。

我想用一个网页把电脑里下载的各种软件统一分好类并配图展示出来，软件都放在 D:\Download 文件夹里。请写代码实现，页面要做得好看、雅致一些。

请确保代码能跑起来演示。

Agent 应产出可运行的网页：能读取（或以模拟数据还原）D:\Download 目录下的软件文件，按类型分好类展示，每个条目配有图标或缩略图。页面提供分类浏览与搜索筛选，找不到目录或读取失败时给出清晰提示，整体视觉干净雅致。

### Criterion 1: 文件扫描与分类实现 (key: c01_file_scanning, weight: 0.1)

采证方式：代码为主，页面观察为辅。

采证动作：在代码中确认目录遍历方式（Node/后端接口、File System Access API 或模拟数据）、类型识别依据（扩展名还是文件内容特征）以及权限、占用、大目录等情况的处理；页面上清点实际展示出的分类数量与归类是否正确。

评分锚点：审查代码是否正确实现了能遍历 D:\Download 目录的文件扫描器，能准确识别文件类型，并按扩展名或文件内容特征归类；检查是否处理了权限不足、文件被占用、目录过大等边界情况。没有文件扫描功能计 0 分；仅按扩展名做基础分类计 5 分；能结合内容特征识别并有完善错误处理计 10 分。

### Criterion 2: 界面分类视觉体系 (key: c02_visual_categorization, weight: 0.1)

采证方式：截图 + 页面操作。

采证动作：截取分类总览页，记录是否为网格布局、各类目是否有统一的图标与配色语言；逐个切换分类查看信息层级是否清晰、不同类目是否有明显区分。

评分锚点：评估界面是否建立了清晰的视觉分类体系，不同软件类型有统一一致的视觉语言；检查界面是否采用网格布局、是否使用了合适的缩略图／图标、是否为软件分类提供了视觉提示。各分类之间视觉语言不统一扣 5 分；信息层级差扣 3 分；分类之间缺少视觉区分扣 5 分。分类体系完善、设计得当计 10 分。

### Criterion 3: 图片渲染与缩略图生成 (key: c03_thumbnail_rendering, weight: 0.1)

采证方式：代码为主，页面观察为辅。

采证动作：在代码中确认缩略图的生成与缓存方式、是否有懒加载、无法提取图标时是否有默认图兜底；页面上滚动长列表观察图片是否按需加载、清晰度如何。

评分锚点：评估代码是否为软件安装包正确生成并缓存缩略图、优化图片加载、实现懒加载以提升性能；检查在无法提取缩略图时是否使用了合适的默认图标。没有缩略图生成扣 5 分；缩略图未做缓存扣 3 分；图片质量差扣 2 分。缩略图提取效果好且有兜底机制计 10 分。

### Criterion 4: 搜索与筛选功能 (key: c04_search_filter, weight: 0.1)

采证方式：页面操作为主。

采证动作：在搜索框输入关键词观察是否实时过滤、命中处是否高亮；依次使用大小、日期、类型、名称等筛选条件并记录结果变化；试用快捷键（如 Ctrl+F、Esc）看是否生效。

评分锚点：检查实现是否包含可靠的搜索能力，支持实时筛选、多种筛选条件（大小、日期、类型、名称），并在搜索过程中保持良好的可用性。没有搜索功能计 0 分；仅有基础文本搜索计 5 分；搜索完善、支持多条件筛选、结果高亮和快捷键计 10 分。

### Criterion 5: 代码鲁棒性 (key: c05_robustness, weight: 0.1)

采证方式：代码为主。

采证动作（辅助）：指向一个不存在的目录、放入一张损坏的图片文件、断开网络后再加载一次，观察是否有友好提示或页面异常。

评分锚点：评估代码能否处理常见异常情况（如文件缺失、访问被拒绝、图片损坏、获取元数据时网络中断）并提供友好的错误提示或恢复机制。鲁棒性强、能有效处理这些边界情况计 10 分；鲁棒性一般计 5 分；完全未处理异常计 0 分。

### Criterion 6: 创新功能 (key: c06_innovation, weight: 0.1)

采证方式：页面操作 + 代码。

评分锚点：检查代码是否包含提升体验的惊喜功能（例如：1. 用 AI 自动分类 2. 跨分类检测重复文件 3. 下载记录的可视化时间线 4. 接入软件更新检查）。每实现一项实用创新功能加 3 分（上限 10 分）。

### Criterion 7: 冗余功能检查 (key: c07_redundancy, weight: 0.1)

采证方式：代码为主。

评分锚点：严格检查三类冗余：1. 重复的文件扫描算法 2. 与核心功能无关的多余数据处理 3. 影响加载速度和性能的花哨特效（如过量动画）。每发现一处冗余扣 3 分；冗余代码干扰核心功能直接计 0 分。

### Criterion 8: 工程质量 (key: c08_engineering, weight: 0.1)

采证方式：代码。

评分锚点：审查模块化设计（如文件系统访问／UI 渲染／数据处理分离）、错误处理覆盖面以及 Web 技术选型是否得当。存在全局状态污染或未使用设计模式扣 5 分；代码重复率过高（超过 30%）扣 5 分；没有构建流程或模块化机制扣 5 分。满分 10 分。

### Criterion 9: 界面视觉专业性 (key: c09_visual_design, weight: 0.1)

采证方式：截图。

采证动作：桌面 1440×900 截整页图（分类总览与某一分类详情各一张）。

评分锚点：评估整体设计是否符合现代设计原则：1）配色和谐（主色不超过 3 种）2）布局间距合理（元素间距遵循 8px 倍数原则）3）专业字体体系（正文字号不小于 14px、行高不低于 1.5 倍）。每处视觉拥挤扣 3 分；刺眼配色扣 5 分；图文排版混乱扣 5 分。满分 10 分。

### Criterion 10: 动态交互流畅性 (key: c10_interaction_fluency, weight: 0.1)

采证方式：页面操作。

采证动作：点击软件卡片 3 次记录反馈延迟；在分类之间快速来回切换 5 次，观察是否有残影或闪烁；记录关键功能按钮（搜索、切换视图）是否一眼可见。

评分锚点：判断动效是否符合人类感知特性：1）点击反馈延迟不超过 100ms 2）过渡动画时长控制在 300-500ms 3）软件选中与分类导航有清晰的视觉焦点引导。每处操作无反馈扣 5 分；快速切换分类时出现视觉残影扣 3 分；关键功能按钮难以找到扣 5 分。满分 10 分。
