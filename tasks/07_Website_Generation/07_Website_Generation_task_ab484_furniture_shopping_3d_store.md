# 家具在线商城网站

## Prompt

请在 /tmp_workspace 下创建项目。如果启动网站时遇到端口冲突，请自行选择其他可用端口。

我想做一个家具在线购物网站，具体需求是：

- 首页要有不同家具风格的展示区，比如现代简约、欧式古典等等；点击某个风格，进入对应风格的家具列表页。
- 列表页上每件家具都有一个 3D 模型展示按钮，点击后新开一个窗口，查看这件家具完整的 3D 模型。
- 商品详情页要有家具的尺寸测量图和摆放建议。
- 购物车页面支持按商品品类分组，方便查看不同类别的商品。
- 结算时可以使用优惠券，输入优惠码后算出实付金额。

代码请写完整的注释，用通俗易懂的语言说明。如果涉及外部 API 调用或需要用到图片、视频、音频等素材，请自行提供模拟数据。

## Expected Behavior

Agent 应生成一个可运行的多页面家具商城：首页展示多种家具风格分区，点击可进入对应风格的列表页；列表页每件商品有 3D 模型查看入口，点开后能看到可操作的三维模型；详情页展示尺寸标注图与摆放建议；购物车按品类分组呈现；结算页输入优惠码后能实时算出并展示实付金额。所有商品、模型、图片均使用模拟数据。

### Criterion 1: 家具风格分类体系 (key: c01_style_category, weight: 0.1)

采证方式：页面操作为主，代码为辅。

采证动作：打开首页截图记录有哪些风格分区，依次点击其中 2 个风格进入列表页，确认跳转是否正确、列表内容是否与风格对应；在代码中查看风格数据是硬编码还是有数据结构支撑。

评分锚点：检查代码是否用合适的数据结构和导航方式实现了家具风格分类（现代简约、欧式古典等）。首页应清晰展示这些分类并有视觉区分，路由应能正确跳转到对应风格的列表页。同时评估分类体系是否便于后续扩展。风格硬编码、没有合理数据结构计 0 分；有基础分类但缺少视觉区分计 5 分；数据建模合理、视觉区分明确、首页与风格页之间跳转顺畅的完整实现计 10 分。

### Criterion 2: 3D 家具模型查看功能 (key: c02_3d_viewer, weight: 0.1)

采证方式：页面操作为主，代码为辅。

采证动作：在列表页点击某件家具的 3D 模型展示按钮，确认是否按要求新开窗口／弹层；在模型视图中执行旋转、缩放、平移各 2 次，记录响应情况与加载耗时。

评分锚点：审查 3D 模型查看功能的实现。检查是否使用了合适的库（Three.js、Babylon.js 等）、模型加载是否高效、是否提供完善的相机控制（缩放、平移、旋转）、材质与光照渲染是否正确。查看器应按要求以弹层／新窗口打开，并在不同设备上保持性能。缺少 3D 查看功能计 0 分；能看到模型但缺少必要控制计 3 分；可查看且有基础控制但存在性能问题计 7 分；加载优化到位、控制直观、响应式适配良好的完整实现计 10 分。

### Criterion 3: 尺寸测量图与摆放建议 (key: c03_dimension_placement, weight: 0.1)

采证方式：页面操作 + 截图。

采证动作：进入某件家具的详情页，截图记录尺寸标注图与摆放建议区域，尝试与尺寸图交互（悬停、点击、切换视角），记录是否有可交互反馈。

评分锚点：核实商品详情页是否包含带清晰数值与比例标识的交互式尺寸图，是否有把家具放在实际场景（房间布局等）中的摆放建议可视化。这些内容不应只是静态图片，而要通过交互性或细致的可视化提供实际价值。缺少尺寸图／摆放建议计 0 分；只有基础静态示意图计 5 分；示意图详尽但不可交互计 8 分；尺寸可交互、摆放建议结合场景的完整实现计 10 分。

### Criterion 4: 购物车按品类分组 (key: c04_cart_grouping, weight: 0.1)

采证方式：页面操作为主，代码为辅。

采证动作：加入至少 3 件不同品类的商品，打开购物车确认是否按品类分组显示、有无分组标题与视觉分隔，尝试折叠／展开分组，刷新页面后确认分组状态是否保留。

评分锚点：评估购物车的品类分组实现。核实商品是否被正确归类并在购物车视图中分组展示，是否有合适的视觉分隔、分组标题以及分组折叠／展开能力。检查页面刷新后是否通过合理的状态管理保持分组。没有分组计 0 分；有基础分组但视觉层次不清或存在易用性问题计 5 分；视觉层次清晰、状态管理得当、交互顺滑的完整实现计 10 分。

### Criterion 5: 代码鲁棒性 (key: c05_robustness, weight: 0.1)

采证方式：代码为主。

采证动作（辅助）：在优惠码输入框填入无效码与空值各一次，观察是否有友好提示而非报错或静默失败。

评分锚点：评估代码能否应对常见异常情况（网络中断、非法用户输入、接口失败、3D 模型加载出错等），并提供友好的错误提示或恢复机制。鲁棒性强的代码应有完善的输入校验、错误边界和降级兜底。完全没有异常处理计 0 分；有基础错误处理但各组件之间不一致计 5 分；全站范围内错误处理完善、恢复机制对用户友好计 10 分。

### Criterion 6: 创新功能 (key: c06_innovation, weight: 0.1)

采证方式：页面操作 + 代码。

评分锚点：检查代码是否包含提升体验的惊喜功能（如：1. AR 摆放，把家具放进用户房间预览 2. 家具颜色／材质自定义 3. 房间规划工具 4. 带 3D 预览的社交分享）。每实现一项实用创新加 3 分，上限 10 分。功能必须完整可用并确实提升用户体验。

### Criterion 7: 冗余功能检查 (key: c07_redundancy, weight: 0.1)

采证方式：代码为主。

评分锚点：严查三类冗余：1. 同类功能重复实现（如多套购物车系统并存）2. 与家具购物无关的功能模块（如内置小游戏）3. 影响性能的花哨特效（如拖慢页面加载的过量动画或粒子效果）。每处冗余扣 3 分；冗余代码干扰核心功能直接计 0 分。

### Criterion 8: 工程质量 (key: c08_engineering, weight: 0.1)

采证方式：代码。

评分锚点：审查模块化设计（如 UI 组件、业务逻辑与数据服务分离）、组件复用性、状态管理方案与构建流程自动化，并评估代码组织、命名规范与文档质量。存在全局状态污染或未使用设计模式扣 5 分；代码重复率过高（超过 30%）扣 5 分；构建流程未自动化扣 5 分。满分 10 分。

### Criterion 9: 界面视觉专业性 (key: c09_visual_design, weight: 0.1)

采证方式：截图。

采证动作：桌面 1440×900 分别截取首页、列表页、详情页、购物车整页图，比对各页版式是否一致。

评分锚点：评估整体设计是否符合现代电商设计原则：1）配色和谐、契合家具零售调性 2）版式间距合理、留白充足 3）专业的字体体系 4）高质量的商品图与可视化呈现。每处视觉拥挤扣 3 分；配色与家具风格不搭扣 5 分；各页面版式风格不统一扣 5 分。满分 10 分。

### Criterion 10: 动态交互流畅性 (key: c10_interaction_fluency, weight: 0.1)

采证方式：页面操作。

采证动作：执行加入购物车、切换商品视图、操作 3D 模型、输入优惠码各 2 次，记录反馈延迟、过渡动画表现以及优惠码生效后的金额变化提示。

评分锚点：判断动效是否达到高品质电商交互水准：1）购物车更新的视觉反馈在 100ms 以内 2）商品视图之间过渡顺滑 3）3D 模型控制响应灵敏 4）优惠券使用流程直观、有即时反馈。每处操作无反馈扣 5 分；动画或过渡卡顿扣 3 分；优惠券使用流程不直观扣 5 分。满分 10 分。
