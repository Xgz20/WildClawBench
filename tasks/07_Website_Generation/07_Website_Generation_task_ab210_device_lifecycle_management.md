# 化工企业设备全生命周期管理系统

## Prompt

请在 /tmp_workspace 下创建项目。如果启动网站时遇到端口冲突，请自行选择其他可用端口。

我想给精细化工企业做一套设备全生命周期管理系统，使用对象是设备管理人员、三大员（机械工程师、电气工程师、仪表工程师）和设备使用人员，用于日常的设备工作管理，供指定人员使用。

配色请以藏青色和白色为主色调。请用 HTML 格式输出。

## Expected Behavior

Agent 应生成可运行的设备管理系统页面：覆盖设备从登记到报废的生命周期各阶段，可查看和管理设备台账、维保计划与工单等日常工作内容；系统区分设备管理人员、机械/电气/仪表工程师、设备使用人员等角色，不同角色看到与自己职责相符的功能。界面采用藏青加白的主色调，风格符合企业软件的专业观感。

### Criterion 1: 设备生命周期核心功能 (key: c01_lifecycle_core, weight: 0.1)

采证方式：页面操作为主，代码为辅。

采证动作：进入系统，依次查看设备登记／台账、维保计划、状态监控、报废管理等入口并逐一打开；尝试新增一台设备并变更其状态（如"在用→维修中"），记录状态流转是否生效；结合代码确认生命周期各阶段的实现。

评分锚点：审查代码是否通过 HTML/JavaScript 准确实现设备全生命周期各阶段，包括设备登记、维保排程、状态监控、报废计划和资产追踪；检查是否覆盖从采购到处置的全流程并有正确的状态流转。核心生命周期逻辑未实现计 0 分；仅有基础增删改查计 5 分；完整实现生命周期管理并带自动化流转计 10 分。

### Criterion 2: 多角色用户管理 (key: c02_role_management, weight: 0.1)

采证方式：页面操作为主，代码为辅。

采证动作：查找登录／角色切换入口，分别以设备管理人员、某一类工程师（机械/电气/仪表）、设备使用人员的身份进入系统，截图对比各角色看到的功能与页面差异；结合代码确认权限校验逻辑。

评分锚点：评估系统是否为设备管理人员、机械/电气/仪表工程师和设备使用人员实现了基于角色的访问控制；检查权限是否合理隔离、是否有角色专属工作台、认证机制是否安全；验证各角色的访问级别和功能是否与其职责匹配。角色划分不清晰扣 5 分；缺少权限校验扣 3 分。满分 10 分。

### Criterion 3: 设备工作管理与排程 (key: c03_work_scheduling, weight: 0.1)

采证方式：页面操作为主，代码为辅。

采证动作：创建一条工单并指派给某位工程师，记录流程与结果；查看维保计划日历／列表、设备停机记录和统计分析页面；结合代码确认预防性维护、故障维修、应急响应等流程的实现。

评分锚点：检查代码是否实现日常工作管理功能，包括维保计划、工单创建与指派、设备停机跟踪和绩效统计分析；评估预防性维护、故障维修和应急响应流程的设计是否完善。排程算法过于简单扣 5 分；缺少通知提醒机制扣 3 分。满分要求实现带冲突处理的高级排程。

### Criterion 4: 精细化工行业合规与安全 (key: c04_industry_compliance, weight: 0.1)

采证方式：页面操作 + 代码。

采证动作：在页面上查找危险设备分类标识、安全检查清单、作业许可（动火/受限空间等）、事故上报等化工行业特有功能并逐一打开验证；结合代码确认安全流程是否有强制约束（如未通过检查不能开工）。

评分锚点：审查系统是否覆盖精细化工行业的特有需求，如危险设备分类、安全规程强制执行、法规合规跟踪和事故上报机制；检查是否集成安全检查清单、作业许可制度和环境监测。行业特性功能流于泛泛扣 5 分；安全规程无强制约束扣 3 分。满分 10 分。

### Criterion 5: 代码鲁棒性 (key: c05_robustness, weight: 0.1)

采证方式：代码为主。

采证动作（辅助）：在设备登记表单中提交空值和非法数据（如日期填字母），观察是否有校验提示且不报错；快速连点提交按钮，观察是否产生重复数据或状态错乱。

评分锚点：评估代码能否处理常见异常情况（如非法设备数据输入、网络中断、多用户并发操作、数据损坏等）并提供友好的错误提示或恢复机制；鲁棒性强的代码应能有效处理数据库故障、接口超时、用户权限变更等边界情况。鲁棒性强计 10 分，一般计 5 分，完全没有异常处理计 0 分。

### Criterion 6: 创新功能 (key: c06_innovation, weight: 0.1)

采证方式：页面操作 + 代码。

评分锚点：检查代码是否包含提升运营效率的实用功能（如：1. 基于设备传感器数据的预测性维护 2. 面向现场技术员的移动端适配界面 3. 与 ERP/CMMS 系统的集成 4. AI 设备故障预测 5. 二维码设备识别）。每实现一项实用创新加 2~3 分，上限 10 分。

### Criterion 7: 冗余功能检查 (key: c07_redundancy, weight: 0.1)

采证方式：代码为主。

评分锚点：严查三类冗余：1. 同类功能重复实现（如多套设备搜索机制并存）2. 与设备管理无关的功能模块（如内置小游戏或社交功能）3. 影响企业软件性能的过度动画。每处冗余扣 3 分；冗余代码干扰核心设备管理功能直接计 0 分。

### Criterion 8: 企业级工程质量 (key: c08_engineering, weight: 0.1)

采证方式：代码。

评分锚点：审查模块化设计（数据层／业务逻辑层／展示层分离）、安全实现、数据库设计规范性和可扩展性考量。敏感数据未妥善保护或存在 SQL 注入漏洞扣 5 分；代码结构不支持企业级扩展扣 5 分；未实现数据备份／恢复机制扣 5 分。满分 10 分。

### Criterion 9: 藏青白配色与专业界面 (key: c09_visual_design, weight: 0.1)

采证方式：截图。

采证动作：桌面 1440×900 截整页图（主工作台 + 至少一个功能页面），检查藏青／白配色、对比度与排版层次。

评分锚点：评估藏青加白的配色是否按企业设计规范专业落地：1）藏青色系变体使用统一（如 #1e3a5f、#2c5282 等）2）对比度满足无障碍要求（不低于 4.5:1）3）字体排版专业、层次清晰 4）留白运用得当。配色使用不一致扣 3 分；对比度差影响可读性扣 5 分；观感不专业、不适合工业场景扣 5 分。

### Criterion 10: 企业日常操作体验 (key: c10_daily_ux, weight: 0.1)

采证方式：页面操作。

采证动作：从首页出发完成一次高频操作（如创建工单或查询某台设备），统计所需点击次数；在表单中提交缺失必填项的数据验证校验提示；切换不同角色检查导航是否按角色清晰区分；将视口缩至平板／手机宽度检查响应式布局。

评分锚点：判断界面是否针对企业日常使用做了优化：1）高频功能可快速访问 2）数据录入表单高效且带校验 3）导航清晰、适配不同用户角色 4）响应式设计适配工业场景中的各类设备。每处需要过多点击的流程扣 5 分；表单缺少必要校验扣 3 分；导航未按角色清晰划分功能扣 5 分。满分 10 分。
