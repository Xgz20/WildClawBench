# 主题圈子博客社区

## Prompt

请在 /tmp_workspace 下创建项目。如果启动网站时遇到端口冲突，请自行选择其他可用端口。

我想搭一个博客社区，支持按主题圈子给文章分类：用户可以加入多个自己感兴趣的主题圈子，在圈子里发布主题文章，也可以给圈子里其他人的文章投票、评论。

## Expected Behavior

Agent 应生成可运行的博客社区网站：支持用户注册/登录、文章的创建/编辑/浏览；用户可以发现并同时加入多个主题圈子，文章按圈子归类展示；圈子内支持对文章投票和评论等社交互动，并提供热门文章等内容发现入口。

### Criterion 1: 社区博客核心系统 (key: c01_blog_core, weight: 0.1)

采证方式：页面操作为主，代码为辅。

采证动作：注册并登录一个账号，新建一篇文章并发布，再打开该文章查看；结合代码确认文章模型包含标题、内容、作者、时间戳、浏览量等字段。

评分锚点：评估代码是否实现博客社区的基本功能：用户注册/登录、文章创建/编辑与浏览。检查文章模型是否正确包含标题、内容、作者引用、时间戳与浏览计数。核心发布系统缺失计 0 分；有基础增删改查但欠打磨计 5 分；功能完备并带草稿保存与发布流程计 10 分。

### Criterion 2: 主题圈子功能 (key: c02_topic_circles, weight: 0.1)

采证方式：页面操作为主，代码为辅。

采证动作：浏览圈子列表并连续加入 2 个以上圈子，在某个圈子内发一篇文章，确认文章归属正确；尝试用搜索/筛选查找圈子，记录结果。

评分锚点：审查主题圈子系统是否允许用户创建、加入多个兴趣圈子并在其中互动。检查数据模型是否正确处理用户与圈子的多对多关系、文章是否按主题正确归类。用户无法同时加入多个圈子扣 5 分；圈子难以被发现扣 3 分。满分要求圈子具备搜索/筛选功能。

### Criterion 3: 社交互动系统 (key: c03_social_interaction, weight: 0.1)

采证方式：页面操作为主，代码为辅。

采证动作：对一篇文章点赞/点踩、发表评论并尝试回复评论（验证嵌套）、重复投票验证防重；记录各互动的状态变化。

评分锚点：检查投票（赞/踩）、评论、分享、关注等功能的实现。检查评论是否支持嵌套/盖楼、投票系统是否防止重复投票。缺少互动通知系统扣 3 分；没有评论管理工具扣 5 分。满分要求至少 3 种社交互动且状态管理正确。

### Criterion 4: 内容发现与推荐 (key: c04_content_discovery, weight: 0.1)

采证方式：页面操作 + 代码。

采证动作：查看首页/发现页是否有热门文章、推荐流或主题浏览入口，逐一点开验证；结合代码确认推荐逻辑是否考虑用户兴趣与行为。

评分锚点：评估平台是否提供通过热门文章、个性化推荐或主题浏览发现内容的途径。检查系统是否使用考虑用户兴趣与行为的算法。没有任何发现功能计 0 分；有基础分类计 5 分；包含个性化信息流与热度指标并有恰当的热度可视化计 10 分。

### Criterion 5: 代码鲁棒性 (key: c05_robustness, weight: 0.1)

采证方式：代码为主。

采证动作（辅助）：提交空标题/空内容的文章、在评论框输入超长文本与特殊字符，观察校验提示是否友好。

评分锚点：评估代码能否处理常见异常（非法输入、服务端错误、用户并发操作等）并提供友好提示或恢复机制。鲁棒性强的代码应实现完善校验、错误边界与降级处理。错误处理全面计 10 分；鲁棒性一般计 5 分；完全没有异常处理计 0 分。

### Criterion 6: 创新功能 (key: c06_innovation, weight: 0.1)

采证方式：页面操作 + 代码。

评分锚点：检查是否包含提升体验的惊喜功能（如：1. 实时协同编辑 2. AI 辅助内容审核 3. 社区活跃度的交互式数据可视化 4. 带预览的 Markdown 或富文本编辑）。每实现一项实用创新加 3 分，上限 10 分。

### Criterion 7: 冗余功能检查 (key: c07_redundancy, weight: 0.1)

采证方式：代码为主。

评分锚点：严查三类冗余：1. 同类功能重复实现（如多套评论系统并存）2. 与博客社区无关的功能模块（如未整合的小游戏、计算器）3. 影响性能的花哨特效（如每次页面交互都触发过量动画）。每处冗余扣 3 分；冗余代码干扰核心功能直接计 0 分。

### Criterion 8: 工程质量 (key: c08_engineering, weight: 0.1)

采证方式：代码。

评分锚点：审查模块化设计（API/业务逻辑/UI 组件分离）、组件复用性、状态管理模式与测试覆盖。发现全局状态污染或未用设计模式扣 5 分；代码重复率过高（超过 30%）扣 5 分；没有组件拆分或合理的文件组织扣 5 分。满分 10 分。

### Criterion 9: 界面视觉专业性 (key: c09_visual_design, weight: 0.1)

采证方式：截图。

采证动作：桌面 1440×900 截整页图（首页文章流、圈子页、文章详情页）。

评分锚点：评估整体设计是否符合现代设计原则：1）配色和谐（主色不超过 3 种）2）布局间距合理（元素间距遵循 8px 倍数原则）3）专业排版体系（正文不小于 14px、行高超过 1.5 倍）。每处视觉拥挤扣 3 分；刺眼配色扣 5 分；图文排版混乱扣 5 分。满分 10 分。

### Criterion 10: 动态交互流畅性 (key: c10_interaction_fluency, weight: 0.1)

采证方式：页面操作。

采证动作：连续点击投票、展开评论、切换圈子各 3 次，记录反馈延迟；滚动文章列表观察加载方式（骨架屏/加载指示、分页或无限滚动）与滚动流畅度。

评分锚点：判断动效是否符合人类感知特性：1）点击反馈延迟不超过 100ms 2）过渡动画时长控制在 300-500ms 3）视觉焦点引导清晰。检查内容加载是否使用骨架屏或加载指示，文章列表是否实现分页或无限滚动。每处操作无反馈扣 5 分；滚动卡顿扣 3 分；关键功能按钮难以找到扣 5 分。满分 10 分。
