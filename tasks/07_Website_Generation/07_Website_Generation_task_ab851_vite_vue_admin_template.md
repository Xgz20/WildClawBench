请在 /tmp_workspace 下创建项目。如果启动网站时遇到端口冲突，请自行选择其他可用端口。

我想用 Vite、Vue 和 Tailwind CSS 做一套后台管理模板。

请尽量保证代码能直接跑起来。

### Criterion 1: Vite + Vue + Tailwind 技术栈落地情况 (key: c01_tech_stack, weight: 0.1)

采证方式：代码为主。

采证动作（辅助）：确认开发服务器能正常启动、页面无编译报错，并记录 Tailwind 的原子类在页面上确实生效。

评分锚点：检查项目结构是否遵循 Vite 最佳实践，配置文件（vite.config.js、tailwind.config.js、postcss.config.js）是否齐备。确认 Vue 3 是否正确搭建，使用 Composition API 或 Options API 均可。Tailwind CSS 应正确集成并配上必要的插件。核心配置缺失计 0 分；基础搭建可用但配置有错计 5 分；所有配置都设置得当并有相应性能优化计 10 分。

### Criterion 2: 后台布局组件是否齐全 (key: c02_layout_components, weight: 0.1)

采证方式：页面操作为主，代码为辅。

采证动作：逐一确认侧边导航、顶部栏（用户信息／通知）、主内容区、页脚、面包屑是否存在；点击侧边菜单切换路由，观察布局是否保持；缩窄窗口检查响应式表现。

评分锚点：评估模板是否包含后台布局的基础组件：响应式侧边栏／导航、带用户信息与通知的顶部栏、主内容区、页脚、面包屑。检查是否用 flexbox/grid 做了合理的布局结构。每缺一个组件扣 2 分。只有当所有组件都具备响应式并与 Vue 路由正确集成时才给满分。

### Criterion 3: 登录与权限功能 (key: c03_auth, weight: 0.1)

采证方式：页面操作为主，代码为辅。

采证动作：访问登录页并尝试登录、登出；直接访问受保护路由观察是否被拦截；在代码中确认路由守卫与登录状态管理的实现。

评分锚点：检查是否有登录／登出功能、基于角色的访问控制、受保护路由，以及 JWT／会话管理。确认是否用 Pinia 或 Vuex 正确管理登录状态。有基础登录界面给 3 分；有妥当的登录状态管理给 3 分；有包含路由守卫和接口鉴权在内的完整角色权限保护给 4 分。完全没有实现登录鉴权则不给分。

### Criterion 4: 后台常用 UI 组件与工具 (key: c04_ui_components, weight: 0.1)

采证方式：页面操作 + 代码。

采证动作：遍历各页面，清点并截图记录出现的组件：数据表格、带校验的表单、图表、弹窗／对话框、提示／消息条、卡片、仪表盘小部件；在代码中确认这些组件是否被复用。

评分锚点：确认是否具备可复用的后台组件，如数据表格、带校验的表单、图表、弹窗／对话框、提示／通知条、卡片、仪表盘小部件。检查这些组件是否有效利用了 Vue 的组件机制。每实现好一个组件加 1 分（最高 10 分）。若组件不可复用或不符合 Vue 最佳实践扣 5 分。

### Criterion 5: 代码鲁棒性 (key: c05_robustness, weight: 0.1)

采证方式：代码为主。

采证动作（辅助）：提交空表单或填入非法值，观察是否有校验提示；缩放窗口至极窄宽度，观察布局是否错乱。

评分锚点：评估代码能否处理常见异常情况（如接口请求失败、表单校验错误、响应式布局的边界情况）并给出友好提示或恢复机制。检查 Vue 组件中是否有妥当的错误边界处理。鲁棒性强、能有效应对这些边界情况计 10 分；鲁棒性一般计 5 分；完全未处理异常计 0 分。

### Criterion 6: 创新功能 (key: c06_innovation, weight: 0.1)

采证方式：页面操作 + 代码。

评分锚点：检查代码是否包含提升体验的惊喜功能（例如：1. 深色／浅色主题切换并能识别系统偏好 2. 支持拖拽小部件的可自定义仪表盘 3. 可交互的数据可视化 4. 面向高频用户的键盘快捷键 5. 实时通知）。每实现一项实用创新加 2 分，上限 10 分。

### Criterion 7: 冗余功能检查 (key: c07_redundancy, weight: 0.1)

采证方式：代码为主。

评分锚点：严查三类冗余：1. 同类组件重复实现（如多套用途相同的按钮样式）2. 没有被使用的工具函数／组件 3. 过度复杂、拖累性能的动画。每发现一处冗余扣 3 分；若核心功能被冗余代码干扰，直接计 0 分。

### Criterion 8: 工程质量 (key: c08_engineering, weight: 0.1)

采证方式：代码。

评分锚点：审查组件架构（组合是否合理、组件是否可复用）、状态管理方案、路由懒加载的代码分割，以及构建优化。全局状态被滥用扣 3 分；单个组件超过 300 行扣 3 分；没有做代码分割扣 2 分；构建产物未做优化扣 2 分。满分 10 分。

### Criterion 9: 界面视觉专业性 (key: c09_visual_design, weight: 0.1)

采证方式：截图。

采证动作：桌面 1440×900 截整页图（仪表盘页 + 一个列表／表单页），另在窄视口再截一张对比响应式表现。

评分锚点：评估设计是否遵循现代后台 UI 原则：1）使用 Tailwind 色彩体系保持配色一致 2）间距工具类（p-x、m-y、gap-z）使用得当 3）在各种视口下都做到响应式 4）对比度和聚焦态符合无障碍要求。间距不统一扣 3 分；响应式表现差扣 3 分；存在无障碍问题扣 2 分；字体层级混乱扣 2 分。满分 10 分。

### Criterion 10: 动态交互流畅性 (key: c10_interaction_fluency, weight: 0.1)

采证方式：页面操作。

采证动作：连续切换路由 3 次，提交一次表单（含校验失败与成功各一次），记录页面过渡是否突兀、异步过程有无加载状态、表单反馈是否清晰。

评分锚点：判断 UI 交互是否达到现代水准：1）路由切换过渡平滑 2）异步操作有加载状态 3）表单反馈到位（校验、成功／失败）4）导航方式符合直觉。缺少加载指示扣 3 分；页面切换突兀扣 3 分；表单交互反馈差扣 2 分；导航方式令人困惑扣 2 分。满分 10 分。
