# 层次分析法决策小工具

## Prompt

请在 /tmp_workspace 下创建项目。如果启动网站时遇到端口冲突，请自行选择其他可用端口。

帮我写一个用 AHP（层次分析法）做决策的小工具。

代码尽量能直接跑起来。

## Expected Behavior

Agent 应生成可运行的页面：用户能定义准则与备选方案，按 1-9 标度填写两两比较矩阵（互反值自动补全），程序算出各层的相对重要性并做一致性检验（CR），最终给出备选方案的综合排序，并以表格或图表形式呈现结果。输入非法或判断矩阵不一致时给出提示。

### Criterion 1: AHP 核心算法正确性 (key: c01_ahp_algorithm, weight: 0.1)

采证方式：代码为主，页面操作为辅。

采证动作：填入一组已知的判断矩阵完整跑一遍，记录界面输出的权重与一致性比率 CR；结合代码核对特征向量求解与 RI 取值表。

评分锚点：核查代码是否正确实现 AHP 的关键环节：判断矩阵构建、归一化、一致性检验（CR < 0.1）和最终权重计算。检查是否用特征向量法求权重，以及是否用随机一致性指标（RI）正确计算一致性比率。实现完整计 10 分；仅有基础矩阵运算、没有一致性检验计 5 分；核心算法缺失计 0 分。

### Criterion 2: 两两比较功能完整性 (key: c02_pairwise_comparison, weight: 0.1)

采证方式：页面操作为主。

采证动作：在比较矩阵中给某一对填入 3，确认对称位置自动变为 1/3；再尝试填入超出 1-9 标度的值或非数字，记录是否有校验提示。

评分锚点：核查代码是否提供按标准 1-9 标度输入两两比较的机制，实现是否正确处理互反值（若 A 比 B 重要 3 倍，则 B 相对 A 必须是 1/3）。实现完整且带校验计 10 分；仅有基础输入、无校验计 5 分；功能缺失计 0 分。

### Criterion 3: 准则与方案的层次结构 (key: c03_hierarchy_structure, weight: 0.1)

采证方式：页面操作 + 代码。

采证动作：尝试添加主准则、子准则和备选方案各若干项，记录界面是否支持子准则层级；结合代码确认层次结构的数据组织方式。

评分锚点：评估代码是否支持完整的层次结构，包含主准则、可能的子准则和备选方案，程序至少要能处理一层子准则。仅支持扁平准则、没有层次扣 5 分；层次仅限两层扣 3 分。满分 10 分。

### Criterion 4: 结果呈现与敏感性分析 (key: c04_results_sensitivity, weight: 0.1)

采证方式：页面操作为主。

采证动作：完成一次完整计算，截图记录方案排序结果与可视化图表；查找敏感性分析入口，调整某个判断值观察排序是否随之更新。

评分锚点：检查程序是否计算出备选方案的最终排序，并提供某种形式的敏感性分析，以理解判断值变化对最终决策的影响；核查是否包含结果可视化（柱状图、表格等）。结果完善且含敏感性分析计 10 分；仅有基础结果、无敏感性分析计 5 分；结果呈现过于简陋或缺失计 0 分。

### Criterion 5: 代码鲁棒性 (key: c05_robustness, weight: 0.1)

采证方式：代码为主。

采证动作（辅助）：输入 0 或负数、留空必填项、构造一个明显不一致的矩阵，观察是否给出友好提示而非崩溃。

评分锚点：评估代码是否处理常见错误（非法输入、判断不一致、矩阵奇异等）并给出友好提示或恢复机制。鲁棒性强的代码应校验所有用户输入、处理数学边界情况、防止程序崩溃。错误处理全面计 10 分，有基础错误处理计 5 分，完全没有错误处理计 0 分。

### Criterion 6: 创新功能 (key: c06_innovation, weight: 0.1)

采证方式：页面操作 + 代码。

评分锚点：检查是否包含提升体验的惊喜功能（如：1. 层次结构的交互式可视化 2. 针对不一致判断给出自动修正建议 3. 导出为 PDF/Excel 4. 群体决策支持）。每实现一项实用创新加 3 分，上限 10 分。

### Criterion 7: 冗余功能检查 (key: c07_redundancy, weight: 0.1)

采证方式：代码为主。

评分锚点：严查三类冗余：1. 同类功能重复实现（如多套矩阵归一化方法并存）2. 与 AHP 决策无关的功能模块 3. 本可简化的不必要复杂度。每处冗余扣 3 分；冗余代码干扰核心功能直接计 0 分。

### Criterion 8: 工程质量 (key: c08_engineering, weight: 0.1)

采证方式：代码。

评分锚点：审查模块化设计（如计算逻辑与界面分离）、代码组织、文档和可复用性。存在全局状态污染或未使用设计模式扣 5 分；代码重复率过高（超过 30%）扣 5 分；文档说明不足扣 5 分。满分 10 分。

### Criterion 9: 界面设计专业性 (key: c09_visual_design, weight: 0.1)

采证方式：截图。

采证动作：桌面 1440×900 截整页图，覆盖准则定义、比较矩阵输入和结果展示三个环节。

评分锚点：评估用户界面（若有）是否遵循良好的设计原则：1）输入表单组织清晰 2）从准则定义到结果输出的流程直观 3）表格与输入控件使用得当。每处令人困惑的界面元素扣 3 分；决策层次组织混乱扣 5 分；结果呈现不清晰扣 5 分。满分 10 分。

### Criterion 10: 用户交互引导性 (key: c10_user_guidance, weight: 0.1)

采证方式：页面操作。

采证动作：以"完全不懂 AHP"的视角走一遍流程，记录每一步是否有说明文字、一致性检验后是否给出可理解的反馈、结果页是否附有解读。

评分锚点：判断程序是否在 AHP 全流程中提供清晰指引：1）两两比较有明确说明 2）一致性方面有有用的反馈 3）结果呈现易于理解。用户必须深入了解 AHP 才能使用扣 5 分；比较过程繁琐、没有快捷方式扣 3 分；结果解读需要额外的外部说明扣 5 分。满分 10 分。
