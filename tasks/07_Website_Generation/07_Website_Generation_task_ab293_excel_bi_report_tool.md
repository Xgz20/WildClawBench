# Excel 导入自动 BI 分析工具

## Prompt

请在 /tmp_workspace 下创建项目。如果启动网站时遇到端口冲突，请自行选择其他可用端口。

我想做一个桌面端用的 BI 分析工具，能导入 Excel 文件、把导入进来的字段正确映射好，然后自动生成 BI 分析报表。

## Expected Behavior

Agent 应生成可运行的 BI 分析页面：用户能选择并导入 Excel 文件，页面解析出表格数据并展示字段列表，允许确认或调整每个字段的类型与用途映射；映射完成后自动生成分析报表，包含统计结果与图表，报表内容可查看、可交互。页面应自带示例数据，在没有用户文件时也能演示完整流程。

### Criterion 1: Excel 导入能力 (key: c01_excel_import, weight: 0.1)

采证方式：页面操作为主，代码为辅。

采证动作：准备一个含数字、日期、文本三类列的 .xlsx 文件（或使用页面自带的示例数据入口），通过导入入口载入，记录导入后的数据预览是否与源文件一致；再检查代码中对 XLS/CSV、多工作表的支持路径。

评分锚点：验证代码能否处理多种 Excel 文件格式（XLS、XLSX、CSV），是否支持多个工作表，导入过程中是否正确处理数据类型（数字、日期、文本等）。检查对损坏文件、大数据量、字符编码问题的错误处理。未实现导入计 0 分；有基础导入但有明显局限计 5 分；实现健壮且错误处理完备计 10 分。

### Criterion 2: 字段映射系统 (key: c02_field_mapping, weight: 0.1)

采证方式：页面操作为主，代码为辅。

采证动作：导入数据后进入字段映射界面，检查系统是否自动识别出各列的数据类型；手动把某一列的类型改成别的类型并确认改动生效；记录是否有数据预览区域，以及缺失值是如何呈现的。

评分锚点：评估代码是否实现了智能字段映射系统：能自动识别数据类型、给出映射建议、允许手动覆盖。检查数据清洗能力、缺失值处理和映射字段的校验。缺少自动字段类型识别扣 3 分；没有数据预览功能扣 3 分；缺少字段关联关系识别扣 4 分。满分 10 分。

### Criterion 3: BI 分析功能完备性 (key: c03_bi_analysis, weight: 0.1)

采证方式：页面操作 + 代码。

采证动作：生成报表后逐项确认呈现了哪些分析：描述性统计、趋势分析、相关性分析、异常值检测、预测建模，逐项记录有无及展示形式；结合代码确认分析方法是否按字段类型（分类型／数值型）分别处理。

评分锚点：检查代码是否包含核心 BI 分析能力：描述性统计、趋势分析、相关性分析、异常值检测和预测建模。确认分析方法与数据类型（分类型 vs 数值型）匹配。每缺一项核心分析功能扣 2 分。所有必要分析均以合适的算法实现且带统计校验计 10 分。

### Criterion 4: 报表洞察质量 (key: c04_report_insight, weight: 0.1)

采证方式：页面操作 + 代码。

采证动作：查看自动生成的报表，记录是否有异常点标注、趋势结论、关键指标摘要、对比分析等文字性洞察，而不只是堆原始数据；检查是否有报表模板选择和导出入口（PDF／HTML 等），逐个点击确认。

评分锚点：评估自动报表生成系统是否产出可付诸行动的洞察，而不只是原始数据的罗列。检查是否包含异常高亮、趋势识别、关键指标摘要和对比分析。确认报表可自定义并可保存为多种格式（PDF、HTML 等）。未突出洞察扣 3 分；导出选项有限扣 3 分；缺少报表模板扣 4 分。满分 10 分。

### Criterion 5: 代码鲁棒性 (key: c05_robustness, weight: 0.1)

采证方式：代码为主。

采证动作（辅助）：导入一个非 Excel 文件（如 .txt）或空文件，观察是否给出友好提示而不是白屏或控制台报错。

评分锚点：评估代码能否处理常见异常（如大数据量导致的内存不足、非预期输入值、应用崩溃等）。检查异常处理是否得当、是否有降级方案和数据恢复机制。鲁棒性强、能给出有意义的错误信息与恢复路径计 10 分；鲁棒性一般计 5 分；完全未处理异常计 0 分。

### Criterion 6: 创新功能 (key: c06_innovation, weight: 0.1)

采证方式：页面操作 + 代码。

评分锚点：检查代码是否包含提升体验的惊喜功能（如：1. AI 自动生成洞察 2. 自然语言查询界面 3. 根据数据特征自动推荐看板 4. 实时协作功能）。每实现一项实用创新加 3 分，上限 10 分。

### Criterion 7: 冗余功能检查 (key: c07_redundancy, weight: 0.1)

采证方式：代码为主。

评分锚点：严查三类冗余：1. 可优化却重复执行的分析计算 2. 与 BI 分析无关的功能模块（如多余的多媒体功能）3. 对理解数据没有帮助却很吃资源的可视化。每处冗余扣 3 分；冗余代码干扰核心功能直接计 0 分。

### Criterion 8: 工程质量 (key: c08_engineering, weight: 0.1)

采证方式：代码。

评分锚点：审查模块化设计（如数据处理／分析／可视化分层）、单元测试覆盖和性能优化手段。全局状态管理实现得差扣 5 分；代码缺少注释和文档扣 3 分；未考虑大数据量下的内存管理扣 2 分。满分 10 分。

### Criterion 9: 界面视觉专业性 (key: c09_visual_design, weight: 0.1)

采证方式：截图。

采证动作：桌面 1440×900 截整页图（导入／字段映射界面、生成后的报表看板各一张）。

评分锚点：评估 UI 是否遵循现代数据可视化原则：1）可视化风格统一 2）信息层级清晰、关键指标有恰当强调 3）留白与栅格对齐得当 4）配色兼顾数据类型和可读性。看板拥挤扣 3 分；图表类型与数据类型不匹配扣 3 分；数据标签和数值可读性差扣 4 分。满分 10 分。

### Criterion 10: 动态交互流畅性 (key: c10_interaction_fluency, weight: 0.1)

采证方式：页面操作。

采证动作：在报表上执行筛选、下钻、切换视图各 3 次，记录响应耗时与过渡动画是否卡顿；确认缩放、筛选、查看明细这几类交互是否都能找到入口。

评分锚点：判断交互元素是否真的有助于数据探索：1）筛选与下钻在 300ms 内响应 2）不同视图与分析之间切换过渡平滑 3）数据选择与对比的交互直观。大数据量下可视化卡顿扣 3 分；交互方式不符合直觉扣 3 分；缺少必要交互（缩放、筛选、按需查看明细）扣 4 分。满分 10 分。
