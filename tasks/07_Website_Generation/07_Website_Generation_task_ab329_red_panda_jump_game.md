# 小熊猫跳跃闯关小游戏

## Prompt

请在 /tmp_workspace 下创建项目。如果启动网站时遇到端口冲突，请自行选择其他可用端口。

我想做一个跳跃类小游戏网站，主角是一只小熊猫，形象要傻乎乎的、很可爱，接近龙猫那种感觉，整体走吉卜力风格。背景里要有奇幻冒险的元素。玩法参考 Doodle Jump（涂鸦跳跃）。

## Expected Behavior

Agent 应生成可运行的跳跃游戏页面：小熊猫角色能在平台间连续弹跳，画面随角色上升持续滚动，左右方向可操控角色移动；平台会不断生成，掉落至画面下方即判定结束；背景与角色呈现吉卜力式的奇幻风格，界面上有分数等基本信息。

### Criterion 1: 核心跳跃机制 (key: c01_jump_mechanic, weight: 0.1)

采证方式：页面操作为主，代码为辅。

采证动作：开始游戏，用左右方向键连续操控角色跳跃 15 秒以上，记录起跳高度是否稳定、画面是否随上升滚动、落到平台上能否触发弹跳，并观察操作到角色响应的跟手程度。

评分锚点：审查代码是否准确实现了 Doodle Jump 式的物理效果（重力、起跳力、画面持续向上滚动）。检查垂直移动是否顺滑、平台碰撞检测是否准确、角色操控是否跟手。核心移动机制缺失计 0 分；实现了基础跳跃但手感别扭计 5 分；跳跃物理带有合理的加速度曲线、手感与 Doodle Jump 完全一致计 10 分。

### Criterion 2: 小熊猫角色的风格还原 (key: c02_character_style, weight: 0.1)

采证方式：截图 + 页面观察。

采证动作：分别在角色静止、上升、下落三个状态各截一张图，比对角色是否有对应的动画表现与表情变化。

评分锚点：评估小熊猫角色是否达到题目要求的"傻乎乎、很可爱"、接近龙猫的美术感觉。角色至少应有待机、跳跃、下落三种动画。检查角色是否有生动的表情特征，是否保持吉卜力的美术调性（圆润造型、柔和配色、讨喜细节）。风格与龙猫／吉卜力不符扣 3 分；动画僵硬或缺失扣 3 分；角色缺乏表现力扣 3 分。

### Criterion 3: 背景与场景的吉卜力氛围 (key: c03_background_aesthetic, weight: 0.1)

采证方式：截图 + 页面观察。

采证动作：在游戏进行中截取不同高度的两张画面，对比背景层是否随角色移动产生视差位移，记录出现了哪些奇幻元素。

评分锚点：检查背景是否包含吉卜力作品里典型的奇幻冒险元素（如浮空岛、奇趣云朵、魔法植物、梦幻色调）。评估视差滚动是否营造出层次感、配色是否使用吉卜力标志性的柔和粉彩、场景元素的美术风格是否统一。背景缺少吉卜力氛围扣 5 分；缺少奇幻冒险元素扣 3 分；背景元素静止、没有视差效果扣 3 分。

### Criterion 4: 平台生成系统 (key: c04_platform_generation, weight: 0.1)

采证方式：页面操作为主，代码为辅。

采证动作：持续向上跳跃至少 20 个平台，记录出现了哪几种平台（普通、移动、可碎裂等），是否出现跳不上去的断层；在代码中确认离屏平台的回收逻辑。

评分锚点：检查代码是否实现了类似 Doodle Jump 的动态平台生成系统，平台随角色上升不断出现。评估平台种类是否丰富（普通、移动、可碎裂等）、分布算法是否合理（不应出现无法跳跃的断层）、是否做了性能优化（移除离开屏幕的平台）。缺少平台生成计 0 分；只有基础静态平台计 5 分；具备多种平台类型且优化到位的完善系统计 10 分。

### Criterion 5: 代码鲁棒性 (key: c05_robustness, weight: 0.1)

采证方式：代码为主。

采证动作（辅助）：改变浏览器窗口尺寸后继续游戏，并快速连按方向键，观察是否报错或画面错乱。

评分锚点：评估代码能否应对常见异常情况（窗口缩放、触屏与鼠标两种操作方式、不同设备方向、性能受限时的降频等），并提供友好的错误处理。鲁棒性强计 10 分；一般计 5 分；完全未处理异常计 0 分。

### Criterion 6: 创新功能 (key: c06_innovation, weight: 0.1)

采证方式：页面操作 + 代码。

评分锚点：检查代码是否包含提升体验的惊喜功能（如：1. 影响玩法的天气效果 2. 带特殊能力的吉卜力风格收集道具 3. 随高度增强的动态配乐）。每实现一项实用创新加 3 分，上限 10 分。

### Criterion 7: 冗余功能检查 (key: c07_redundancy, weight: 0.1)

采证方式：代码为主。

评分锚点：严查三类冗余：1. 同类功能重复实现（如多套跳跃控制系统并存）2. 与跳跃游戏无关的功能模块（如内置计算器）3. 影响性能的花哨特效（如导致卡顿的过量粒子系统）。每处冗余扣 3 分；冗余代码干扰核心功能直接计 0 分。

### Criterion 8: 工程质量 (key: c08_engineering, weight: 0.1)

采证方式：代码。

评分锚点：审查模块化设计（如游戏逻辑／视图／输入处理分离）、资源加载优化与渲染性能。存在全局状态污染或未使用设计模式扣 5 分；代码重复率过高（超过 30%）扣 5 分；在常规设备上运行表现差扣 5 分。满分 10 分。

### Criterion 9: 界面视觉专业性 (key: c09_visual_design, weight: 0.1)

采证方式：截图。

采证动作：桌面 1440×900 截整页图，覆盖游戏主画面与分数、操作提示等 UI 区域。

评分锚点：评估整体设计是否符合现代设计原则：1）配色和谐并与吉卜力风格相衬 2）分数、操作、菜单等 UI 元素布局间距合理 3）专业的字体体系并强化奇幻主题（字距合适、既有风格又不失易读）。每处视觉拥挤扣 3 分；配色冲突、破坏吉卜力氛围扣 5 分；图文排版混乱扣 5 分。满分 10 分。

### Criterion 10: 动态交互流畅性 (key: c10_interaction_fluency, weight: 0.1)

采证方式：页面操作。

采证动作：连续操作角色左右移动与跳跃各 5 次，记录按键到画面响应的延迟、起跳与落地动画是否连贯、快速移动时画面是否卡顿。

评分锚点：判断动效是否符合人类感知特性：1）角色操控响应不超过 100ms 2）跳跃、落地、拾取道具的动画过渡顺滑 3）玩家操作与游戏事件有清晰的视觉反馈。每处操作无反馈扣 5 分；快速移动时动画卡顿扣 3 分；帧率不稳定扣 5 分。满分 10 分。
