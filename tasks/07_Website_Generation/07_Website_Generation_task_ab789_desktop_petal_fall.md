# 桌面花瓣飘落特效

## Prompt

请在 /tmp_workspace 下创建项目。如果启动网站时遇到端口冲突，请自行选择其他可用端口。

我想做一个在电脑桌面上飘落花瓣的程序，花瓣要能自然地从上往下飘，看着舒服。

请确保代码能直接跑起来看到效果。

## Expected Behavior

Agent 应产出可直接运行的花瓣飘落程序：页面（或桌面覆盖层）加载后花瓣持续从上方生成并向下飘落，下落过程带有摆动、旋转等自然运动，花瓣形态有多种变化。程序长时间运行不应出现明显卡顿或内存堆积，窗口尺寸变化后仍能正常显示。

### Criterion 1: 花瓣动画系统实现 (key: c01_petal_animation, weight: 0.1)

采证方式：页面观察 + 代码。

采证动作：打开页面持续观察 15 秒，记录花瓣的生成、下落轨迹是否各不相同；截图 2-3 张不同时刻的画面对比；在代码中确认动画驱动方式（requestAnimationFrame 或等价机制）与重力／风力参数。

评分锚点：审查代码是否准确实现花瓣飘落的物理效果，包括真实的重力、风力影响以及运动路径的自然随机化；检查是否正确使用 requestAnimationFrame 或类似的计时机制。未实现动画计 0 分；仅有基础下落动画计 5 分；花瓣呈现自然多变的飘落形态且有完整物理模拟计 10 分。

### Criterion 2: 桌面集成能力 (key: c02_desktop_integration, weight: 0.1)

采证方式：代码为主，页面观察为辅。

采证动作：在代码中查找是否使用 Electron 透明窗口、kiosk 模式或系统 API 实现桌面覆盖层，以及是否设置了鼠标事件穿透；页面运行时尝试点击花瓣下方的元素，记录是否被特效遮挡。

评分锚点：评估代码是否创建了能与桌面环境正确集成的透明覆盖层（使用 Electron、浏览器 kiosk 模式或合适的系统 API）；检查花瓣飘落时是否仍能正常使用桌面。仅能在浏览器窗口内运行扣 5 分；干扰桌面正常操作扣 3 分。满分 10 分。

### Criterion 3: 花瓣样式与多样性 (key: c03_petal_variety, weight: 0.1)

采证方式：截图 + 代码。

采证动作：截取包含较多花瓣的画面，放大观察花瓣的形状、颜色、大小是否有差异；在代码中统计花瓣类型（花种）数量及渲染方式（SVG／Canvas）。

评分锚点：评估代码是否支持多种花瓣类型、颜色、尺寸和形状；检查是否包含至少 3 种花卉类型并有相应的季节变化。只有一种花瓣计 0 分；有少量变化计 5 分；具备丰富的自定义能力且用 SVG 或 Canvas 实现逼真花瓣渲染计 10 分。

### Criterion 4: 资源管理与性能优化 (key: c04_performance, weight: 0.1)

采证方式：代码为主，页面观察为辅。

采证动作：在代码中确认是否有对象池、花瓣数量上限、离屏回收、帧率节流等机制；页面持续运行 60 秒后再观察一次画面流畅度，记录是否比刚打开时明显变差。

评分锚点：检查代码是否实现对象池、合理的垃圾回收和节流机制，以防止内存泄漏和 CPU 占用过高；确认是否能根据屏幕尺寸和系统性能自动调整规模。性能随运行时间下降扣 5 分；不根据系统负载调整扣 3 分。满分 10 分。

### Criterion 5: 代码鲁棒性 (key: c05_robustness, weight: 0.1)

采证方式：代码为主。

采证动作（辅助）：改变窗口尺寸 2-3 次（含缩到很窄），切换标签页后再切回，观察画面是否错乱或报错。

评分锚点：评估代码能否处理常见异常情况（如窗口缩放、前后台切换、不同屏幕分辨率等）并提供妥当的错误处理。鲁棒性强、能适应各种环境而不出错计 10 分；鲁棒性一般计 5 分；完全未处理异常计 0 分。

### Criterion 6: 创新功能 (key: c06_innovation, weight: 0.1)

采证方式：页面操作 + 代码。

评分锚点：检查代码是否包含提升体验的惊喜功能（例如：1. 花瓣可响应鼠标移动的交互效果 2. 昼夜循环或天气效果 3. 季节变化或节日主题）。每实现一项实用创新功能加 3 分（上限 10 分）。

### Criterion 7: 冗余功能检查 (key: c07_redundancy, weight: 0.1)

采证方式：代码为主。

评分锚点：严格检查三类冗余：1. 可优化掉的重复动画计算 2. 与花瓣动画无关的功能模块（如多余的 UI 控件）3. 无实际价值却拖累性能的特效（如过量的粒子系统）。每发现一处冗余扣 3 分；冗余代码干扰核心功能直接计 0 分。

### Criterion 8: 工程质量 (key: c08_engineering, weight: 0.1)

采证方式：代码。

评分锚点：审查模块化设计（如渲染层／物理层／配置层分离）、代码组织和实现效率。过度使用全局变量扣 5 分；缺少注释或文档扣 5 分；使用低效算法或实现方式扣 5 分。满分 10 分。

### Criterion 9: 视觉设计专业度 (key: c09_visual_design, weight: 0.1)

采证方式：截图。

采证动作：桌面 1440×900 截整页图，并对花瓣密集区域局部放大截图，用于判断形状、透明度、明暗与色彩细节。

评分锚点：评估花瓣设计是否美观：1）形状与纹理自然 2）透明度和明暗处理得当 3）同类花瓣内部有细微的色彩变化。花瓣形状失真扣 3 分；表现扁平、卡通化缺乏细节扣 5 分；颜色或纹理不自然扣 5 分。满分 10 分。

### Criterion 10: 动画流畅自然度 (key: c10_animation_smoothness, weight: 0.1)

采证方式：页面观察。

采证动作：连续观察 20 秒并录屏或连拍截图，记录是否掉帧卡顿、花瓣下落中是否有摆动和旋转、加速与风力表现是否自然、不同花瓣的运动是否雷同。

评分锚点：判断动画是否符合现实物理规律：1）帧率流畅（不低于 30fps）2）下落过程中有自然的摆动和旋转 3）加速度和风力效果真实。动画卡顿扣 5 分；运动方式不自然扣 3 分；花瓣行为整齐划一、机械缺乏变化扣 5 分。满分 10 分。
