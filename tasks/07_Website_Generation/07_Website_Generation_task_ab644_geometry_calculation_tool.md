# 几何图形计算工具

## Prompt

请在 /tmp_workspace 下创建项目。如果启动网站时遇到端口冲突，请自行选择其他可用端口。

我想要一个几何计算工具，支持常见平面图形（圆、三角形、矩形、正多边形等）和立体图形（球、圆柱、圆锥、棱柱等）的面积、周长、体积和表面积计算。用户选择图形类型、输入必要参数（如边长、半径、高等），就能得到计算结果。

工具还要提供交互式图形预览：根据用户输入实时更新图形示意图，并标注关键尺寸。另外要有显示／隐藏计算公式的选项。

## Expected Behavior

Agent 应生成可运行的几何计算工具页面：可切换平面与立体图形类型，输入参数后即时得到面积、周长、体积、表面积等计算结果；页面有随输入实时更新的图形预览并标注关键尺寸；提供公式显示／隐藏开关，公式内容正确。

### Criterion 1: 图形覆盖与计算实现 (key: c01_shape_calculations, weight: 0.1)

采证方式：页面操作为主，代码为辅。

采证动作：逐一切换图形类型（至少覆盖圆、三角形、矩形、正多边形、球、圆柱、圆锥、棱柱），各输入一组参数并人工核算一两个结果（如圆面积、圆柱体积）是否正确，记录已实现的图形清单。

评分锚点：评估代码是否准确实现全部要求的平面图形（圆、三角形、矩形、正多边形）和立体图形（球、圆柱、圆锥、棱柱）的计算功能。实现的图形不足要求的 50% 计 0 分；实现了基础图形但功能有限计 5 分；全部图形实现完整、面积／周长／体积／表面积计算逻辑齐备计 10 分。

### Criterion 2: 参数输入与校验 (key: c02_input_validation, weight: 0.1)

采证方式：页面操作为主，代码为辅。

采证动作：输入负数、0、非数字等非法值，记录是否被拦截并给出清晰错误提示；检查各图形的必要参数项是否齐全、是否有单位选择。

评分锚点：检查输入系统是否允许用户为每种图形指定全部必要参数（边长、半径、高等），并有相应的约束和校验。缺少输入校验扣 3 分；允许输入负数或非法值扣 3 分；没有单位选择扣 2 分。输入系统健壮、校验全部输入、给出清晰错误提示且带合适单位计 10 分。

### Criterion 3: 交互式图形预览 (key: c03_graphical_preview, weight: 0.1)

采证方式：页面操作为主。

采证动作：修改某个参数（如把半径从 5 改到 10），观察示意图是否实时更新、比例是否随之变化、关键尺寸是否有标注，截图记录修改前后对比。

评分锚点：评估工具是否根据用户输入实时更新图形的可视化预览，预览应准确反映比例与尺寸。可视化不能实时更新扣 5 分；尺寸没有标注扣 3 分；图形表示不准确或有误导扣 5 分。满分要求基于 SVG 或 Canvas 的响应式示意图精确反映输入参数。

### Criterion 4: 公式显示选项 (key: c04_formula_toggle, weight: 0.1)

采证方式：页面操作为主，代码为辅。

采证动作：点击公式显示／隐藏开关各 1 次，核对公式是否正确（如圆面积 πr²、球体积 4/3πr³）、排版是否清晰易读，截图留证。

评分锚点：评估用户能否对每种图形显示／隐藏计算公式；公式应数学上正确，并以易读格式呈现（如 MathJax/LaTeX 或清晰的文本排版）。公式不能切换显示／隐藏扣 5 分；公式有误扣 3 分；公式排版差、难以阅读扣 3 分。满分要求公式展示优雅、数学符号规范。

### Criterion 5: 代码鲁棒性 (key: c05_robustness, weight: 0.1)

采证方式：代码为主。

采证动作（辅助）：输入 0 尺寸、极大数值，观察结果与提示是否合理。

评分锚点：评估代码能否处理常见异常情况（如非法输入、0 尺寸等边界情况、浮点精度问题等）并提供友好的错误提示或恢复机制。鲁棒性强、能有效处理这些边界情况计 10 分；鲁棒性一般计 5 分；完全未处理异常计 0 分。

### Criterion 6: 创新功能 (key: c06_innovation, weight: 0.1)

采证方式：页面操作 + 代码。

评分锚点：检查是否包含提升体验的惊喜功能（如：1. 立体图形 3D 旋转 2. 计算结果导出为 PDF／图片 3. 多图形对比模式 4. 体积填充或面积覆盖的动画演示）。每实现一项实用创新加 3 分，上限 10 分。

### Criterion 7: 冗余功能检查 (key: c07_redundancy, weight: 0.1)

采证方式：代码为主。

评分锚点：严查三类冗余：1. 同类计算重复实现（如同一图形有多套面积计算方法）2. 与几何计算无关的功能模块（如不必要的动画）3. 影响性能或可用性的花哨特效。每发现一处冗余扣 3 分；若冗余代码干扰了核心功能，直接计 0 分。

### Criterion 8: 工程质量 (key: c08_engineering, weight: 0.1)

采证方式：代码。

评分锚点：审查模块化设计（如计算逻辑／可视化／UI 层分离）、代码组织与可维护性。存在全局状态污染或未使用合适的设计模式扣 5 分；代码重复率过高（超过 30%）扣 5 分；计算逻辑与展示层没有清晰分离扣 5 分。满分 10 分。

### Criterion 9: 界面视觉专业性 (key: c09_visual_design, weight: 0.1)

采证方式：截图。

采证动作：桌面 1440×900 截整页图（含输入区、预览区、结果区）。

评分锚点：评估整体设计是否符合现代设计原则：1）配色和谐（主色不超过 3 种）2）布局间距合理（元素间距遵循 8px 倍数原则）3）专业字体体系（正文字号不小于 14px、行高超过 1.5 倍）。每处视觉拥挤扣 3 分；刺眼配色扣 5 分；图文排版混乱扣 5 分。满分 10 分。

### Criterion 10: 动态交互流畅性 (key: c10_interaction_fluency, weight: 0.1)

采证方式：页面操作。

采证动作：连续修改参数 5 次，记录输入反馈延迟、示意图更新速度以及输入区到结果区的视觉引导。

评分锚点：判断动效是否符合人类感知特性：1）输入反馈延迟不超过 100ms 2）参数变化后视觉及时更新 3）输入与输出元素之间有清晰的视觉焦点引导。每处操作无反馈扣 5 分；可视化更新卡顿扣 3 分；交互方式令人困惑或控件难找扣 5 分。满分 10 分。
