# 微信风格聊天窗口

## Prompt

请在 /tmp_workspace 下创建项目。如果启动网站时遇到端口冲突，请自行选择其他可用端口。

我需要一个类似微信聊天窗口的页面，请用 Ant Design + Vue 3 来写。页面只需要展示聊天消息，不需要发送消息的功能。消息数据是后端返回的多条记录。请保证生成的代码可以直接运行演示。

## Expected Behavior

Agent 应生成可运行的聊天消息展示页面：以微信风格渲染一组模拟后端返回的消息记录，收发双方的消息分列左右、带头像与气泡样式，能区分不同消息类型。页面基于 Vue 3 与 Ant Design 组件搭建，消息列表可正常滚动浏览。

### Criterion 1: Vue 3 与 Ant Design 集成 (key: c01_vue_antd_integration, weight: 0.1)

采证方式：代码为主，页面操作为辅。

采证动作（辅助）：打开页面确认能正常渲染、控制台无组件加载报错；检查 package.json 依赖与入口文件的插件注册、样式引入。

评分锚点：检查项目是否正确搭建 Vue 3 + Ant Design，包括组件导入是否规范、Ant Design Vue 插件配置、CSS/Less 样式引入；核对 package.json 是否包含正确依赖（ant-design-vue、vue@3.x）。组件导入方式错误扣 5 分；缺少全局样式扣 5 分；未处理版本兼容问题扣 3 分。满分 10 分。

### Criterion 2: 聊天窗口组件结构 (key: c02_component_structure, weight: 0.1)

采证方式：代码为主。

评分锚点：评估聊天窗口的组件层级与结构，至少应包含：容器组件、消息列表组件和单条消息组件，并对发送与接收消息做出区分。结构缺失计 0 分；有基本结构但组织欠佳计 5 分；组件拆分合理、符合 Vue 3 最佳实践、props/emit 使用得当计 10 分。

### Criterion 3: 消息渲染实现完整性 (key: c03_message_rendering, weight: 0.1)

采证方式：页面观察 + 代码。

采证动作：浏览消息列表，确认文本、图片、系统通知等不同类型消息是否分别正确渲染；缩放窗口观察布局是否自适应；结合代码检查 v-for 的 key 绑定。

评分锚点：审查代码是否正确处理后端数据中的不同消息类型（文本、图片、系统通知等）并分别妥善渲染；核实消息列表是否使用 v-for 且 key 绑定规范。消息类型未做区分扣 5 分；key 缺失或使用不当扣 3 分；渲染不具备响应式适配扣 3 分。满分 10 分。

### Criterion 4: 微信视觉风格还原度 (key: c04_wechat_style, weight: 0.1)

采证方式：截图。

采证动作：桌面 1440×900 截取聊天窗口整页图，对照微信风格核对气泡样式、配色、消息左右对齐（接收在左、发送在右）、时间戳与头像。

评分锚点：检查 UI 是否还原微信聊天界面，包括气泡样式、配色、消息对齐方式（接收靠左、发送靠右）、时间戳和头像。完全不像微信计 0 分；有基本相似度计 5 分；高度还原微信设计并注重细节（气泡小尾巴、间距得当、风格统一）计 10 分。

### Criterion 5: 代码鲁棒性 (key: c05_robustness, weight: 0.1)

采证方式：代码为主。

采证动作（辅助）：查看模拟数据中是否包含缺字段、空消息、超长消息、特殊字符等用例，并在页面上确认其渲染表现。

评分锚点：评估代码能否处理常见异常情况（如消息字段缺失、空消息、超长且无断行的消息、消息中含特殊字符等）并提供合适的兜底或错误处理。鲁棒性强、能有效兜住这些边界情况计 10 分；鲁棒性一般计 5 分；完全未处理异常计 0 分。

### Criterion 6: 创新功能 (key: c06_innovation, weight: 0.1)

采证方式：页面操作 + 代码。

评分锚点：检查代码是否包含提升体验的惊喜功能（如：1. 消息已读状态标识 2. 消息按时间分组 3. 自动滚动到最新消息 4. 消息骨架屏加载）。每实现一项实用创新加 3 分，上限 10 分。

### Criterion 7: 冗余功能检查 (key: c07_redundancy, weight: 0.1)

采证方式：代码为主。

评分锚点：严查三类冗余：1. 同类功能的重复实现（如多套消息展示方案并存）2. 与聊天展示无关的功能模块（如不必要的动画）3. 影响性能的花哨特效（如每条消息都做复杂过渡）。每处冗余扣 3 分；冗余代码干扰核心功能直接计 0 分。

### Criterion 8: 工程质量 (key: c08_engineering, weight: 0.1)

采证方式：代码。

评分锚点：审查模块化设计（如 UI 组件与数据处理逻辑分离）、组合式 API 的运用以及类型安全（TypeScript 或 PropTypes）。不必要地使用全局状态扣 5 分；代码重复度高扣 5 分；展示层与业务逻辑不分离扣 5 分。满分 10 分。

### Criterion 9: 界面视觉专业性 (key: c09_visual_design, weight: 0.1)

采证方式：截图。

采证动作：桌面 1440×900 截整页图，检查消息间距、字体大小与对比度。

评分锚点：评估整体设计是否符合现代设计原则：1）配色和谐，与微信色板保持一致 2）消息之间及消息内部间距布局合理 3）专业的字体体系，字号与对比度得当。每处视觉拥挤扣 3 分；刺眼配色扣 5 分；图文排版混乱扣 5 分。满分 10 分。

### Criterion 10: 动态交互流畅性 (key: c10_interaction_fluency, weight: 0.1)

采证方式：页面操作。

采证动作：在消息列表上下滚动 3 次，观察滚动是否顺滑；刷新页面观察消息加载时是否有加载状态；确认每条消息的发送者归属是否一目了然。

评分锚点：判断动效是否符合人类感知特性：1）历史消息滚动顺滑 2）拉取消息时有恰当的加载状态 3）消息类型与发送者之间视觉区分清晰。滚动卡顿扣 5 分；缺少加载状态扣 3 分；消息归属混乱（分不清谁发的）扣 5 分。满分 10 分。
