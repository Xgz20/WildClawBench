# 时间轴文件管理系统

## Prompt

请在 /tmp_workspace 下创建项目。如果启动网站时遇到端口冲突，请自行选择其他可用端口。

我想做一个基于时间轴的文件管理系统：用户上传的所有文件按上传时间生成一条时间轴，用户拖动时间轴滑块就能快速找到特定的文件。

## Expected Behavior

Agent 应生成可运行的文件管理页面：用户能上传文件并记录上传时间，所有文件按时间组织在一条时间轴上，拖动时间轴滑块时文件列表随之实时更新，能定位到指定时间段的文件。文件本身还应支持预览、下载、重命名、删除等常规管理操作。

### Criterion 1: 文件上传与时间轴组织 (key: c01_upload_timeline_org, weight: 0.1)

采证方式：页面操作为主，代码为辅。

采证动作：上传 2-3 个文件（或使用页面预置的示例数据），确认每个文件的上传时间被记录并出现在时间轴对应位置；结合代码确认时间戳记录与按时间检索的数据结构。

评分锚点：审查代码是否准确实现文件上传功能，包括合适的校验、存储处理与时间戳记录；检查时间轴组织是否采用合适的数据结构支撑按时间戳高效检索。核心上传功能缺失计 0 分；基础上传可用但时间戳处理不到位计 5 分；实现完整的文件元数据跟踪并有可靠的按时间组织计 10 分。

### Criterion 2: 时间轴滑块组件 (key: c02_timeline_slider, weight: 0.1)

采证方式：页面操作为主。

采证动作：拖动时间轴滑块到不同位置，观察文件视图是否实时更新、拖动过程是否有视觉反馈，检查时间轴上是否有不同时间段文件密度的提示，截图记录。

评分锚点：评估供用户浏览时间轴的滑块组件实现：拖动是否顺滑、事件处理是否正确、更新是否及时、交互过程是否有视觉反馈；滑块应准确反映文件在时间上的分布。滑块拖动时文件视图不实时更新扣 5 分；缺少不同时间段文件密度的视觉提示扣 3 分。满分 10 分。

### Criterion 3: 文件展示与按时间筛选 (key: c03_time_filtering, weight: 0.1)

采证方式：页面操作 + 代码。

采证动作：拖动滑块选择不同时间范围，核对展示的文件是否确实落在所选范围内，感受筛选是否有明显延迟；结合代码确认时区处理与时间上下文展示。

评分锚点：检查用户拖动时间轴滑块时系统是否动态更新文件展示；评估筛选机制能否正确识别并展示所选时间范围内的文件；检查系统是否正确处理时区并提供清晰的时间上下文。筛选有明显延迟（超过 200ms）扣 5 分；时间范围选择缺少精确控制手段扣 3 分。满分 10 分。

### Criterion 4: 时间轴之外的文件管理功能 (key: c04_file_management, weight: 0.1)

采证方式：页面操作为主，代码为辅。

采证动作：对一个文件依次尝试预览、下载、重命名、删除、分类操作，确认操作后时间轴视图同步更新。

评分锚点：评估代码是否包含完善的文件管理功能，如预览、下载、重命名、删除和分类；检查这些操作是否与时间轴系统正确集成并保持数据一致。基础文件操作缺失扣 5 分；操作后时间轴视图未相应更新扣 3 分。完整实现且与时间轴无缝集成计 10 分。

### Criterion 5: 代码鲁棒性 (key: c05_robustness, weight: 0.1)

采证方式：代码为主。

采证动作（辅助）：尝试上传非法类型文件、把滑块快速拖到时间轴两端，观察是否报错或状态错乱。

评分锚点：评估代码能否处理常见异常（如上传失败、非法文件类型、大文件处理、时间轴边界情况等）并提供友好提示或恢复机制。鲁棒性强计 10 分，一般计 5 分，完全未处理异常计 0 分。

### Criterion 6: 创新功能 (key: c06_innovation, weight: 0.1)

采证方式：页面操作 + 代码。

评分锚点：检查是否包含提升体验的惊喜功能（如：1. 基于 AI 的文件内容自动分类 2. 用热力图展示上传频率的时间轴可视化 3. 基于时间的文件聚类或规律识别）。每实现一项实用创新加 3 分，上限 10 分。

### Criterion 7: 冗余功能检查 (key: c07_redundancy, weight: 0.1)

采证方式：代码为主。

评分锚点：严查三类冗余：1. 同类功能重复实现（如多套作用相同的时间轴导航方式）2. 与时间轴文件管理无关的功能模块（如不必要的社交分享）3. 影响性能的花哨特效（如过量动画拖慢时间轴导航）。每处冗余扣 3 分；冗余代码干扰核心功能直接计 0 分。

### Criterion 8: 工程质量 (key: c08_engineering, weight: 0.1)

采证方式：代码。

评分锚点：审查模块化设计（如文件处理逻辑／时间轴可视化／UI 组件分离）、单元测试覆盖与构建流程自动化。存在全局状态污染或未使用设计模式扣 5 分；代码重复率过高（超过 30%）扣 5 分；构建流程未自动化扣 5 分。满分 10 分。

### Criterion 9: 界面视觉专业性 (key: c09_visual_design, weight: 0.1)

采证方式：截图。

采证动作：桌面 1440×900 截整页图（时间轴 + 文件列表主界面）。

评分锚点：评估整体设计是否符合现代设计原则：1）配色和谐（主色不超过 3 种）2）布局间距合理（元素间距遵循 8px 倍数原则）3）专业字体体系（正文字号不小于 14px、行高超过 1.5 倍）。每处视觉拥挤扣 3 分；刺眼配色扣 5 分；图文排版混乱扣 5 分。满分 10 分。

### Criterion 10: 动态交互流畅性 (key: c10_interaction_fluency, weight: 0.1)

采证方式：页面操作。

采证动作：来回拖动时间轴滑块 3 次，记录拖动响应延迟、文件列表切换动画与当前所选时间段的标识是否清晰。

评分锚点：判断时间轴滑块与文件展示更新是否符合人类感知特性：1）时间轴拖动响应延迟不超过 100ms 2）文件展示过渡动画时长控制在 300-500ms 3）所选时间段有清晰的视觉标识。每处操作无反馈扣 5 分；时间轴导航过程出现视觉卡顿扣 3 分；时间轴位置与展示文件对不上、令人困惑扣 5 分。满分 10 分。
