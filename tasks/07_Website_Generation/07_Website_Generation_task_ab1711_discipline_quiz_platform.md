# 纪检监督业务知识在线答题平台

## Prompt

请在 /tmp_workspace 下创建项目。如果启动网站时遇到端口冲突，请自行选择其他可用端口。

我想搭一个纪检监督业务知识的在线答题平台，请帮我生成代码，并告诉我搭建这个平台的流程和方法。

代码要能直接跑起来演示。

## Expected Behavior

Agent 应生成可运行的答题平台：包含题库与题目分类管理、多种题型的答题流程、答案判定与计分、答题计时和进度提示，用户可查看历史成绩与学习进度；同时在回复中说明平台的搭建流程与技术方案。

### Criterion 1: 答题系统核心功能完整性 (key: c01_quiz_core, weight: 0.1)

采证方式：页面操作为主，代码为辅。

采证动作：进入一次答题，覆盖单选、多选、判断、填空各题型各答一题（有多少答多少），记录判定结果、得分变化和计时器表现；结合代码确认未在页面出现的题型是否已实现。

评分锚点：审查代码是否通过 HTML/JavaScript 准确实现题目管理，包括多种题型（单选、多选、判断、填空）、答案校验逻辑、计分算法和计时功能。核心答题逻辑未实现计 0 分；仅实现基础题目展示计 5 分；完整包含全部题型与校验机制计 10 分。

### Criterion 2: 纪检知识库管理系统 (key: c02_knowledge_base, weight: 0.1)

采证方式：页面操作 + 代码。

采证动作：进入题库管理界面，尝试新增／编辑／删除一道题，记录知识分类维度、难度分级和标签筛选是否可用；试用搜索功能查找一道题。

评分锚点：检查平台是否包含完善的知识分类（党纪、行政监察、案件查办等）、题库的增删改查管理、难度分级和基于标签的筛选。知识分类不完整扣 5 分；缺少搜索功能扣 3 分。满分 10 分。

### Criterion 3: 用户管理与进度追踪 (key: c03_user_progress, weight: 0.1)

采证方式：页面操作 + 代码。

采证动作：走一遍登录流程，记录不同角色（管理员／教师／学员）看到的入口差异；答题后查看学习进度、历史成绩和统计分析页面；刷新页面确认登录态是否保持。

评分锚点：评估是否实现用户认证、基于角色的权限控制（管理员／教师／学员）、学习进度追踪、成绩历史和表现分析，用户会话需双向校验并做数据持久化。缺少用户角色管理扣 5 分；进度追踪不完整扣 3 分。满分 10 分。

### Criterion 4: 平台架构与数据流 (key: c04_architecture, weight: 0.1)

采证方式：代码为主。

评分锚点：检查代码是否包含完整的平台架构：前后端分离、RESTful API 设计、题目／用户／成绩的数据库表结构，以及结果的实时同步。未提供 API 文档扣 5 分；数据库表关系设计不佳扣 3 分。完整实现且具备规范的 MVC 架构计 10 分。

### Criterion 5: 代码鲁棒性 (key: c05_robustness, weight: 0.1)

采证方式：代码为主。

采证动作（辅助）：不选答案直接提交、快速连点提交按钮、中途刷新页面，观察是否给出友好提示或能恢复答题状态。

评分锚点：评估代码能否处理常见异常情况（网络超时、非法的答题提交、并发访问、数据损坏等）并给出友好提示或恢复机制。鲁棒性强计 10 分，一般计 5 分，完全未处理异常计 0 分。

### Criterion 6: 创新功能 (key: c06_innovation, weight: 0.1)

采证方式：页面操作 + 代码。

评分锚点：检查是否包含提升学习体验的惊喜功能（如：1. 根据答题表现自适应调整难度 2. 实时排行榜与游戏化元素 3. AI 智能推荐题目 4. 交互式案例模拟）。每实现一项实用创新加 3 分，上限 10 分。

### Criterion 7: 冗余功能检查 (key: c07_redundancy, weight: 0.1)

采证方式：代码为主。

评分锚点：严查三类冗余：1. 同类功能重复实现（如多套计分体系并存）2. 与答题平台无关的功能模块（如内置社交媒体功能）3. 影响性能的花哨特效（如答题过程中过量动画）。每处冗余扣 3 分；冗余代码干扰核心答题功能直接计 0 分。

### Criterion 8: 工程质量 (key: c08_engineering, weight: 0.1)

采证方式：代码。

评分锚点：审查模块化设计（如答题逻辑／界面组件／API 层分离）、输入校验与净化、安全措施（防 SQL 注入、防 XSS）和代码组织。发现安全漏洞或校验缺失扣 5 分；代码结构一坨、没有关注点分离扣 5 分；没有错误日志机制扣 5 分。满分 10 分。

### Criterion 9: 界面视觉专业性 (key: c09_visual_design, weight: 0.1)

采证方式：截图。

采证动作：桌面 1440×900 截整页图，覆盖首页、答题页和成绩／进度页。

评分锚点：评估整体设计是否符合现代教育平台的设计原则：1）配色专业可信，适合政务／机构场景 2）信息层级清晰、间距合理（元素间距遵循 8px 倍数原则）3）字体无障碍友好（正文字号不小于 14px、对比度高）。每处视觉拥挤扣 3 分；配色不够专业扣 5 分；可读性差扣 5 分。满分 10 分。

### Criterion 10: 动态交互流畅性 (key: c10_interaction_fluency, weight: 0.1)

采证方式：页面操作。

采证动作：连续切换题目 5 次并提交一次答卷，记录反馈延迟、题目间过渡动画时长、进度指示是否清晰。

评分锚点：判断答题体验是否符合用户预期：1）题目切换与提交的反馈延迟不超过 100ms 2）题目之间过渡流畅，时长控制在 200-400ms 3）进度指示清晰、用户操作有视觉反馈 4）答题界面直观、认知负担低。每处操作缺少恰当反馈扣 5 分；导航流程令人困惑扣 3 分；答题状态指示不清扣 5 分。满分 10 分。
