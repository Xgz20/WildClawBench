# 个人空间多媒体主页

## Prompt

请在 /tmp_workspace 下创建项目。如果启动网站时遇到端口冲突，请自行选择其他可用端口。

请用 HTML 帮我写一个完整的个人空间：头像和昵称都能通过弹窗自定义修改，可以发布视频、图片、文字、音乐等各种内容。

界面要好看，数据要能存下来，刷新页面之后不会丢。

## Expected Behavior

Agent 应生成可运行的个人空间页面：点击头像或昵称能弹出编辑弹窗完成修改，发布区支持文字、图片、视频、音乐几类内容并在动态流中正常展示与播放，所有数据写入本地存储，刷新页面后内容和个人资料依然在。

## LLM Judge Rubric

说明：

- 每个 Criterion 只能使用 `0.0 ~ 1.0`、步长 `0.1`（对应原 checklist 的 0~10 分，下文锚点以 0~10 分表述）。
- 锚点中的"扣 N 分"从 10 分起扣，扣完为止；"加 N 分"从 0 分起加，上限 10 分。
- 每个 Criterion 标注 `采证方式`，如适用附 `采证动作`；评分必须引用证据（截图文件名／代码位置／观察记录）。
- 采证动作执行失败时，先在代码中确认该功能是否实现；若代码已实现而操作未生效，记录采证失败及原因（原生弹窗、拖拽模拟失效等），按代码实现情况给分，不因采证失败直接扣分。
- 满分锚点是质量天花板而非需求底线（如 Criterion 1 的头像裁剪），Prompt 未明示的能力做不到时表现为得分低，不判零。

### Criterion 1: 头像与昵称自定义 (key: c01_profile_customization, weight: 0.1)

采证方式：页面操作为主，代码为辅。

采证动作：点击头像与昵称分别打开弹窗，上传一张图片观察是否有预览和裁剪；把昵称改成超长字符串或含特殊字符后提交，记录校验提示。

评分锚点：评估头像／昵称自定义的弹窗是否正常工作。检查头像上传是否支持裁剪、预览和多种文件格式（JPG、PNG、WebP）。核实昵称修改是否带校验（长度限制、禁用字符）。未实现计 0 分；有基础功能但缺少校验计 5 分；实现完整、校验与错误处理到位计 10 分。

### Criterion 2: 多媒体内容发布 (key: c02_media_posting, weight: 0.1)

采证方式：页面操作为主。

采证动作：分别发布一条文字、一条图片、一条视频、一条音乐内容，逐条记录发布入口是否存在、发布后能否正常展示与播放（视频播放器控件、音频控件、图片预览、文字排版）。

评分锚点：检查系统是否支持发布视频（带完善的播放器控件和格式支持）、图片（带预览与懒加载）、文字（支持富文本排版）和音乐（带音频控件）。核实每种媒体类型在创建、展示和管理上是否都有对应的界面元素。每缺一种媒体类型扣 3 分。只有全部媒体类型都支持且界面集成到位才给满分。

### Criterion 3: 数据持久化 (key: c03_data_persistence, weight: 0.1)

采证方式：页面操作 + 代码。

采证动作：发布若干内容并修改头像昵称后刷新页面，核对数据是否完整保留；结合代码检查存储方案、序列化与反序列化以及存储异常处理。

评分锚点：核实是否正确使用 localStorage/IndexedDB 做数据持久化。检查数据序列化／反序列化是否规范、存储操作是否有错误处理、页面加载时能否自动恢复数据。检查是否有备份机制或数据结构变更时的迁移方案。刷新后数据丢失计 0 分；有基础持久化但存在局限计 5 分；持久化层完善、错误处理到位计 10 分。

### Criterion 4: 内容创作与管理界面 (key: c04_content_management_ui, weight: 0.1)

采证方式：页面操作为主。

采证动作：对已发布的一条内容尝试编辑、删除、归档；查找排序／筛选控件以及分类、标签、收藏等组织方式，逐一记录是否可用。

评分锚点：评估内容创作界面（发布编辑器、媒体上传界面）和管理功能（编辑、删除、归档）。检查是否有直观的排序／筛选控件和内容组织方式（分类、标签、收藏）。发布后不能编辑扣 5 分；管理功能有限扣 3 分；界面完整、直观计 10 分。

### Criterion 5: 代码鲁棒性 (key: c05_robustness, weight: 0.1)

采证方式：代码为主。

采证动作（辅助）：上传一个格式不支持的文件、提交一条空内容，观察是否有友好提示而非页面报错。

评分锚点：评估代码能否处理常见异常（上传文件非法、存储空间超限、网络中断、用户误操作）并给出友好提示或恢复机制。鲁棒性强计 10 分，一般计 5 分，完全未处理异常计 0 分。

### Criterion 6: 创新功能 (key: c06_innovation, weight: 0.1)

采证方式：页面操作 + 代码。

评分锚点：检查是否包含提升体验的惊喜功能（如：1. 深色模式切换 2. 可自定义的主题／布局 3. 内容数据统计与洞察 4. AI 辅助创作工具）。每实现一项实用创新加 3 分，上限 10 分。

### Criterion 7: 冗余功能检查 (key: c07_redundancy, weight: 0.1)

采证方式：代码为主。

评分锚点：严查三类冗余：1. 同类功能重复实现（如多套图片上传模块）2. 与个人空间无关的功能模块（如内置小游戏）3. 影响性能的花哨特效（如过多的动画或过渡）。每处冗余扣 3 分；核心功能被冗余代码干扰直接计 0 分。

### Criterion 8: 工程质量 (key: c08_engineering, weight: 0.1)

采证方式：代码。

评分锚点：审查模块化设计（如 UI／数据／存储分层）、CSS 组织方式（是否使用 CSS 变量或预处理器）和脚本的模块化程度。发现全局状态污染或未使用设计模式扣 5 分；代码重复率过高（超过 30%）扣 5 分；没有做关注点分离扣 5 分。满分 10 分。

### Criterion 9: 界面视觉专业性 (key: c09_visual_design, weight: 0.1)

采证方式：截图。

采证动作：桌面 1440×900 截整页图（个人主页动态流 + 资料编辑弹窗）。

评分锚点：评估整体设计是否符合现代设计原则：1）配色和谐（主色不超过 3 种）2）布局间距合理（元素间距遵循 8px 倍数原则）3）专业字体体系（正文字号不小于 14px、行高不低于 1.5 倍）。每处视觉拥挤扣 3 分；刺眼配色扣 5 分；图文排版混乱扣 5 分。满分 10 分。

### Criterion 10: 动态交互流畅性 (key: c10_interaction_fluency, weight: 0.1)

采证方式：页面操作。

采证动作：开关资料弹窗 3 次、发布内容 2 次，并快速滚动动态流，记录反馈延迟、动画时长、滚动时是否有残影，以及发布等关键按钮是否好找。

评分锚点：判断动效是否符合人类感知特性：1）点击反馈延迟不超过 100ms 2）过渡动画时长控制在 300~500ms 3）有清晰的视觉焦点引导。每处操作无反馈扣 5 分；快速滚动时出现视觉残影扣 3 分；关键功能按钮难以找到扣 5 分。满分 10 分。
