# 网络设备监控系统

## Prompt

请在 /tmp_workspace 下创建项目。如果启动网站时遇到端口冲突，请自行选择其他可用端口。

我想做一个网络设备监控系统，用来监控公司内部路由器、交换机这类网络设备的状态，代码要能跑起来演示。

系统需要实现管理员登录（用户名：admin，密码：123456），支持添加设备（设备名称、IP 地址、型号、位置），查看设备的实时状态（在线／离线），以及设置告警阈值。系统要有一个仪表盘页面，用图形化的方式展示网络拓扑结构，用不同颜色标识设备状态，并支持点击设备查看详情。

## Expected Behavior

Agent 应生成可运行的网络设备监控系统页面：用 admin/123456 能登录进入系统，登录后可添加、编辑、删除设备并填写设备名称、IP 地址、型号、位置；设备列表展示在线／离线状态并会随时间更新；可设置告警阈值并在超限时产生告警记录；仪表盘用图形化拓扑展示设备连接关系，不同状态用不同颜色区分，点击某个设备能弹出或跳转到详情。设备与状态数据可用内置的模拟数据驱动。

### Criterion 1: 管理员登录系统 (key: c01_admin_login, weight: 0.1)

采证方式：页面操作为主，代码为辅。

采证动作：先用错误的用户名或密码登录一次，记录提示信息；再用 admin／123456 登录，记录是否成功进入系统；检查代码中是否有会话管理与超时机制。

评分锚点：审查登录机制是否包含正确的身份校验、会话管理和安全措施。系统必须校验凭据（admin／123456）、实现超时机制、并对常见攻击有防护。未实现身份校验计 0 分；基础登录能用但没有安全措施计 5 分；完整实现且有妥当的安全考虑计 10 分。

### Criterion 2: 设备管理功能完整性 (key: c02_device_crud, weight: 0.1)

采证方式：页面操作为主。

采证动作：新增一台设备，逐一填写设备名称、IP 地址、型号、位置，记录必填校验与 IP 格式校验的表现；再用同一个 IP 或同一设备名新增一次，记录是否有重复检测；对已有设备执行编辑和删除，确认列表同步更新。

评分锚点：检查系统是否支持添加、编辑、删除网络设备，且包含全部必需字段（设备名称、IP 地址、型号、位置）。确认实现中有数据校验、重复检测和妥当的存储机制。缺任一必需字段扣 3 分；校验不到位扣 3 分；增删改查不完整扣 4 分。满分 10 分。

### Criterion 3: 设备实时状态监控 (key: c03_realtime_status, weight: 0.1)

采证方式：页面操作 + 代码。

采证动作：在设备列表或仪表盘上观察不少于 30 秒，记录是否有设备状态发生变化以及变化时是否有通知；结合代码确认轮询周期、超时处理和状态变更的通知逻辑。

评分锚点：评估系统是否真正实现了设备状态（在线／离线）的实时监控，是否使用了合适的协议（ICMP、SNMP 等）。检查轮询机制、超时处理和状态变更通知。完全没有监控行为计 0 分；有基础轮询但缺少可靠性处理计 5 分；完整实现且有妥当的错误处理和实时更新计 10 分。

### Criterion 4: 告警阈值配置 (key: c04_alarm_threshold, weight: 0.1)

采证方式：页面操作为主，代码为辅。

采证动作：打开告警阈值配置，记录可以设置哪些指标（响应时间、丢包率、带宽利用率等）；把某个阈值调到必然触发的数值，记录是否产生告警及通知形式；查看是否有告警历史列表并可管理。

评分锚点：审查告警阈值配置系统是否完整。应支持为多种指标设置阈值（响应时间、丢包率、带宽利用率等），支持通知机制，并提供告警历史。阈值类型有限扣 3 分；缺少通知方式扣 3 分；缺少告警历史或告警管理扣 4 分。满分 10 分。

### Criterion 5: 代码鲁棒性 (key: c05_robustness, weight: 0.1)

采证方式：代码为主。

采证动作（辅助）：在设备表单里填入非法 IP（如 999.999.1.1）或留空必填项后提交，观察是否有友好提示而不是页面崩溃。

评分锚点：评估代码能否处理常见异常（如网络超时、设备不可达、非法输入等）并给出友好提示或恢复机制。鲁棒性强、能有效处理这些边界情况计 10 分；鲁棒性一般计 5 分；完全未处理异常计 0 分。

### Criterion 6: 创新功能 (key: c06_innovation, weight: 0.1)

采证方式：页面操作 + 代码。

评分锚点：检查代码是否包含提升体验的惊喜功能（如：1. 故障预测分析 2. 自动网络拓扑发现 3. 性能趋势可视化）。每实现一项实用创新加 3 分，上限 10 分。

### Criterion 7: 冗余功能检查 (key: c07_redundancy, weight: 0.1)

采证方式：代码为主。

评分锚点：严查三类冗余：1. 同类功能重复实现（如并存多套状态检测机制）2. 与网络监控无关的功能模块（如天气小组件）3. 影响性能的花哨特效（如过多动画）。每处冗余扣 3 分；冗余代码干扰核心功能直接计 0 分。

### Criterion 8: 工程质量 (key: c08_engineering, weight: 0.1)

采证方式：代码。

评分锚点：审查模块化设计（如监控逻辑／视图／数据分层）、单元测试覆盖和构建流程自动化。存在全局状态污染或未使用设计模式扣 5 分；代码重复率过高（超过 30%）扣 5 分；构建流程未自动化扣 5 分。满分 10 分。

### Criterion 9: 网络拓扑可视化 (key: c09_topology_visual, weight: 0.1)

采证方式：页面操作 + 截图。

采证动作：进入仪表盘拓扑图，拖动节点、缩放画布并点击设备，记录交互是否生效；截图记录不同设备类型与状态的颜色／形状区分是否清晰。

评分锚点：评估拓扑可视化是否符合专业设计原则：1）图形渲染可交互且布局算法合适 2）设备类型与状态的视觉区分清晰 3）支持自适应缩放与画布导航。可视化静态、不可交互扣 3 分；视觉层次差扣 4 分；无法承载复杂拓扑扣 3 分。满分 10 分。

### Criterion 10: 仪表盘 UI 与交互设计 (key: c10_dashboard_ui, weight: 0.1)

采证方式：截图 + 页面操作。

采证动作：桌面 1440×900 截仪表盘整页图，记录关键指标是否放在显眼位置；点击若干设备查看详情，记录选中与查看明细的路径是否顺手。

评分锚点：判断仪表盘设计是否达到专业水准：1）信息层级合理，关键指标突出展示 2）状态用色恰当 3）设备选择与详情查看直观。布局拥挤扣 3 分；配色表达状态无效扣 3 分；交互元素做得差、妨碍使用扣 4 分。满分 10 分。
