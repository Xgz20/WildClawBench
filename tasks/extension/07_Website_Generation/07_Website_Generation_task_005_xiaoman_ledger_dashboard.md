# 小满账簿

## Prompt

请在 /tmp_workspace 下从空目录创建一个可运行的中文个人记账网页项目。项目根目录需要提供 package.json，并支持 npm install、npm run build，以及 npm run start -- --host 127.0.0.1 --port 4173 启动网站。所有数据都保存在本地，刷新页面后仍然保留，不需要登录或连接网络服务。

请制作一个名为“小满账簿”的中文个人记账网页，帮助用户按月或按周查看 2026 年 6 月至 8 月的收支、分析账单，并在浏览器中完成新增、修改和删除记录。页面采用类似支付软件账单页的单栏应用布局，不要做左侧固定概览栏。

顶部显示品牌名“小满账簿”、标题、说明“把每一笔认真记下，也把生活慢慢看清。”和醒目的“记一笔”按钮。顶部控制区先提供“周期类型”切换，包含“按月”和“按周”，默认选中“按月”；旁边提供“具体周期”选择。“按月”时可选择 2026年6月、2026年7月、2026年8月，默认选中 2026年8月；“按周”时可选择当前数据范围内的具体账周，例如 2026年8月第2周（8/3-8/9），切到按周后默认选中 2026年8月第2周。控制区还提供“明细 / 分析”两个页签，默认选中“明细”。切换周期类型、具体周期或页签后，页面标题、统计、列表和分析内容都同步切换到当前周期。

“明细”页用于查看和处理账目。明细页顶部必须显示当前周期的整体收支统计，包括收入、支出、结余和记录数。默认按月查看 2026年8月时，统计应为收入 ¥11,000.00、支出 ¥3,044.00、结余 ¥7,956.00、记录数 6 笔；切换到按周查看 2026年8月第2周（8/3-8/9）时，统计应为收入 ¥1,200.00、支出 ¥2,976.00、结余 -¥1,776.00、记录数 4 笔。

明细页还提供搜索框、收支类型切换、分类筛选和排序控件。搜索框占位文字为“搜索名称或备注”，能够同时搜索记录名称和备注；收支类型包含“全部、支出、收入”；分类筛选包含“全部分类、餐饮、交通、居住、学习、娱乐、工资、奖金、其他”；排序包含“最新优先”和“金额从高到低”。这些条件可以组合使用，且只影响当前周期的明细列表，不改变整体收支统计和分析页统计。列表上方同步显示当前结果数量；没有符合条件的记录时显示明确的空状态和“清除筛选”按钮。

明细列表只显示当前周期内的记录，并按日期从新到旧排列。列表清楚显示日期、名称与备注、分类、收支类型、金额和查看入口；支出金额使用减号，收入金额使用加号。点击任意记录或它的“查看”入口，在页面右侧打开详情抽屉，完整显示名称、金额、收支类型、分类、日期和备注，并提供“编辑记录”“删除记录”和关闭入口。

“分析”页用于查看当前周期的收支结构和趋势。分析页顶部展示当前周期的收支概览，包括当前周期名称、收入、支出、结余、记录数和最大支出分类；这些数据要与明细页的整体收支统计一致。其下方分别展示“收入分类”和“支出分类”两个环形图：收入环形图只统计收入分类并显示图例和金额，支出环形图只统计支出分类并显示图例和金额，两者不能混在一个图里。默认 2026年8月的收入环形图应包含工资 ¥9,800.00、奖金 ¥1,200.00；支出环形图应包含居住 ¥2,600.00、餐饮 ¥394.00、交通 ¥50.00。

分析页中部展示趋势图。趋势图上方提供“趋势指标”单选，包含“收入”“支出”“结余”，默认选中“支出”；同一时间只显示被选中指标的一条曲线，不能把收入、支出、结余三条线同时放在图里。当顶部周期类型为“按月”时，趋势图展示 2026年6月、2026年7月、2026年8月三个月的所选指标变化；当顶部周期类型为“按周”时，趋势图展示当前所选账周所在月份内各周的所选指标变化。趋势图应有清楚的横轴标签、数值标注和当前周期强调。切换周期类型、具体周期或趋势指标后，趋势图立即同步更新。趋势图不受明细页搜索和筛选影响。

分析页最下方展示“收入 Top3”和“支出 Top3”两个排行榜，各自按当前周期内的单笔金额从高到低列出前三笔记录，并显示名称、日期、分类和金额；不足三笔时显示已有记录即可。默认 2026年8月的收入榜应显示工资 ¥9,800.00、项目奖金 ¥1,200.00；支出榜应显示房租 ¥2,600.00、超市采购 ¥326.00、咖啡豆 ¥68.00。切换到按周查看 2026年8月第2周时，收入榜只显示项目奖金 ¥1,200.00，支出榜显示房租 ¥2,600.00、超市采购 ¥326.00、地铁充值 ¥50.00。

点击“记一笔”打开新增记录弹窗。弹窗包含收支类型、名称、金额、分类、日期和备注字段，默认选择“支出”，日期默认填入 2026-08-11；底部提供“取消”和“保存记录”。名称不能为空，金额必须大于 0，日期不能为空；提交无效内容时弹窗保持打开，并在对应字段附近给出清楚的中文错误提示。保存有效记录后弹窗关闭，新记录加入对应周期列表，明细统计、分析概览、环形图、趋势图和 Top3 排行榜立即同步更新。

点击详情抽屉中的“编辑记录”打开同一风格的编辑弹窗，并预填该记录现有内容；保存后列表、详情、明细统计和分析页立即使用新内容。如果编辑时把日期改到另一个周期，该记录应从当前周期列表移到对应周期。点击“删除记录”时先显示确认层，写明“确定删除这笔记录吗？”并提供“取消”和“确认删除”；只有确认后才移除记录并更新列表、统计、环形图、趋势图和 Top3 排行榜。

用户新增、修改或删除的记录需要保存在浏览器本地；刷新页面后记录和统计保持不变，但周期类型、具体周期、页签、趋势指标、搜索、筛选和打开的弹窗不需要保留。

视觉上使用暖米色 #F4F0E8 作为页面背景，深色文字使用 #1F2A27，支出和主要操作使用珊瑚橙 #E96B4A，收入使用草木绿 #4B8B65，结余和图表辅助强调使用金色 #D8A638，深墨绿 #20352F 可用于品牌区或重点标题。整体像一页清楚、克制的现代账单，不要做营销页或左右双栏概览页；页签、选择器、表格、统计块、环形图、趋势图、排行榜、输入框和弹窗有统一的圆角、边框与间距。明细页中整体收支统计、筛选区和当前周期明细应清楚可见；分析页中收支概览、收入/支出环形图、单指标趋势图和底部 Top3 应形成清楚的上下结构。页面不要出现横向滚动，也不要使用需要联网才能显示的图片、字体或数据。

## Expected Behavior

Agent 应该从空目录生成完整前端项目，安装、构建、启动流程可用，首页能在浏览器中访问。页面应完整呈现“小满账簿”的账单和分析内容，包含周期切换、明细列表、筛选搜索、分析图表、排行榜、详情抽屉、增删改弹窗和本地持久化。

正确实现应避免外部网络依赖，所有视觉和交互都在本地页面内完成；周期切换、筛选、分析和记录管理都应有清楚反馈。
