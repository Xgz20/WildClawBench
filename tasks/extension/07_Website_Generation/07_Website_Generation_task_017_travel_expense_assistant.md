# 差旅核算助手

## Prompt

请在 /tmp_workspace 下从空目录创建一个可运行的中文行政办公/差旅报销核算工具网页项目。项目根目录需要提供 package.json，并支持 npm install、npm run build，以及 npm run start -- --host 127.0.0.1 --port 4173 启动网站。页面运行时不要依赖外部图片、字体、接口或其他网络资源；不要接入真实支付或发送真实请求。

我们部门交上去的差旅报销单十有八九要被财务打回来重填，说到底是大家对住宿限额、补贴天数这些细则不太清楚，填的时候心里没数。想做一个叫“差旅核算助手”的中文网页，提交之前先把行程和票据录进去自己核一遍，看清楚哪些能报、哪些超了要自己承担；出差之前也能拿它先估一估，把这趟的花销安排得合规一点。不用登录，打开就能用。

公司的差旅标准是这样的：住宿按目的地城市分三类，北京、上海、广州、深圳是一类，杭州、成都、南京、武汉、西安是二类，其余城市是三类。普通员工在一类、二类、三类城市的住宿限额分别是每晚 600 元、450 元、350 元，管理岗分别是 800 元、600 元、450 元。住宿超过限额的，超出部分由个人承担，限额之内的照常报销。另外每出差一天有 150 元差旅补贴。

出差天数按出发和返程的时间算：出发当天在中午 12 点及之前出发算一天，12 点之后算半天；返程当天在 12 点及之后回来算一天，12 点之前算半天；中间的每一天都算一天；当天去当天回的按一天算。半天的补贴也折半。

页面上方先填这趟出差的基本信息：目的地城市、出差人职级、出发时间和返程时间。这几项都要填，返程不能早于出发，填得不对就在旁边给出中文提示。填好之后能直接看到算出来的出差天数和补贴金额，也能看到这次适用的住宿限额是多少，这样出差前就知道酒店订到什么价位不会超。

下面是票据明细，可以一条条添加住宿费和交通费，每条填日期、说明和金额。住宿的每一条都要能看出申报了多少、按标准能报多少、超了多少。交通费实报实销，不过出租车票达到 100 元的，需要标明已经附上支付凭证，没有标明的这一条先不计入可报金额，页面上要能看出来是因为什么。另外有些花销本来就不该走公司账，比如顺路探亲、私人行程，这类可以在明细上标成个人事项，标了之后整条都不计入。

明细旁边一直显示这趟的汇总：申报合计、不可报合计和实际可报金额；实际可报要把差旅补贴也一并算进去，让人一眼看到这趟最后能拿回多少钱。任何一条明细改动，或者上面的城市、职级、时间改了，汇总都要立刻跟着重算。明细可以删除，删之前先确认一下，免得手滑。

这些内容希望关掉页面再打开还在，不用每次重新填。

视觉上想要一个清爽、可信的办公工具的样子：浅色背景、深色文字，主要操作用沉稳的蓝色，超标和不可报的金额用红色标出来，实际可报金额用绿色并且要足够醒目。手机上打开也要能正常填写和查看。

## Expected Behavior

Agent 应从空目录生成可运行的前端网站，按 Prompt 完成页面内容、交互和视觉要求；项目应能在本地 npm install、npm run build 并通过 npm run start 启动，且不依赖外部网络资源。

评分由 Playwright 运行时检查（内容与交互类评分点）和基于截图的视觉判分（视觉与布局类评分点）共同完成；每个评分点按“预设状态 → 操作 → 期望结果”独立判定。
