# 垃圾分类小卫士

## Prompt

请在 `/tmp_workspace` 下创建项目。如果启动网站时遇到端口冲突，请自行选择其他可用端口。

孩子上小学二年级，学校在教垃圾分类，光背四个桶的名字他记不住，想做个网页小游戏让他边玩边记。

要能分清可回收物、厨余垃圾、有害垃圾、其他垃圾这四类，把矿泉水瓶、废电池、西瓜皮、一次性筷子这些常见的垃圾拖进对应的桶里，一件投完接着出下一件。投对投错都要有反馈。

垃圾桶的颜色按实际生活里的来。垃圾桶和垃圾都用图案画出来，让孩子看着图就知道是什么。

手机上也要能玩。

## Expected Behavior

Agent 应按 Prompt 完成页面内容、交互和视觉要求。

评分由 Playwright 运行时检查（内容与交互类评分点）和基于截图的视觉判分（视觉与布局类评分点）共同完成；每个评分点按“预设状态 → 操作 → 期望结果”独立判定。

## Grading Criteria

本题仅使用 LLM Judge 评分。评分点全部放在 `## LLM Judge Rubric` 中，每个 Criterion 只有 1.0 和 0.0 两档：非视觉类评分点由 Playwright 检查器按 key 给出运行时结果，视觉类评分点由 LLM 依据截图判定。

操作：通览游戏画面，找出用来投放垃圾的那几个桶

期望结果：画面上有四个投放目标，分别对应可回收物、厨余垃圾、有害垃圾、其他垃圾这四类，四类齐全、不重不漏。每个桶都能看出它收的是哪一类——桶上写着类别名，或者图案配上类别名，都算。

Score 1.0: 符合预设状态、操作要求，且结果与期望结果一致。

Score 0.0: 不符合预设状态、操作要求或期望结果。

### Criterion 2: 查看当前这件等待投放的垃圾 (key: c02_detail_display, primary: content_structure, secondary: detail_display, weight: 0.1)

预设状态：已进入游戏画面，画面上出现了一件等待投放的垃圾

操作：查看当前这件等待投放的垃圾

期望结果：能明确看出当前要投的是什么东西：有可读的名称，或者图案本身足以辨认出是哪样东西（例如一眼能认出是香蕉皮），两者具备其一即可。不是一个没有任何标识、看不出是什么的色块或方框。

Score 1.0: 符合预设状态、操作要求，且结果与期望结果一致。

Score 0.0: 不符合预设状态、操作要求或期望结果。

### Criterion 3: 认清当前这件垃圾是什么 (key: c03_rule_settlement, primary: interaction_function, secondary: rule_settlement, weight: 0.1)

预设状态：已进入游戏画面，画面上出现了一件等待投放的垃圾

操作：认清当前这件垃圾是什么，按生活常识把它拖到应该投放的那个桶上松手（矿泉水瓶投可回收物，废电池投有害垃圾，西瓜皮投厨余垃圾，一次性筷子投其他垃圾，其余的按同样的常识判断）。若页面在投放之后有短暂的过渡或动画，把测试时钟推进 2 秒再看结果

期望结果：页面把这次投放判为投对：这件垃圾被收走（从等待投放的位置消失或落进桶里），并且页面用文字、颜色、图标或动画中的任一种表示这次投对了。不出现按常识明明投对、页面却判成错的情况。

Score 1.0: 符合预设状态、操作要求，且结果与期望结果一致。

Score 0.0: 不符合预设状态、操作要求或期望结果。

### Criterion 4: 认清当前这件垃圾是什么 (key: c04_rule_settlement, primary: interaction_function, secondary: rule_settlement, weight: 0.1)

预设状态：已进入游戏画面，画面上出现了一件等待投放的垃圾

操作：认清当前这件垃圾是什么，故意把它拖到一个按生活常识明显不该投的桶上松手（例如把西瓜皮拖到有害垃圾桶，把废电池拖到厨余垃圾桶）。若页面在投放之后有短暂的过渡或动画，把测试时钟推进 2 秒再看结果

期望结果：页面把这次投放判为投错，并明确表示出错了，不会把这次投放当成投对。

Score 1.0: 符合预设状态、操作要求，且结果与期望结果一致。

Score 0.0: 不符合预设状态、操作要求或期望结果。

### Criterion 5: 先按生活常识把当前这件垃圾投进正确的桶 (key: c05_operation_feedback, primary: interaction_function, secondary: operation_feedback, weight: 0.1)

预设状态：已进入游戏画面

操作：先按生活常识把当前这件垃圾投进正确的桶，记下页面给出的反馈；等下一件出现后，把它故意投进一个明显错误的桶，再记下这次的反馈。若页面在投放之后有短暂的过渡或动画，把测试时钟推进 2 秒再看结果

期望结果：两次反馈明显不同，一眼就能分辨这次是投对还是投错——用文字、颜色、图标或动画中的任一种方式区分都算。不是两次给出完全一样的提示，也不是投错时页面毫无动静。

Score 1.0: 符合预设状态、操作要求，且结果与期望结果一致。

Score 0.0: 不符合预设状态、操作要求或期望结果。

### Criterion 6: 连续投放四件垃圾 (key: c06_rule_settlement, primary: interaction_function, secondary: rule_settlement, weight: 0.1)

预设状态：已进入游戏画面

操作：连续投放四件垃圾，每一件都先认清是什么，再按生活常识拖到应该投放的那个桶上。如果其中某一件在生活里本来就有多种投法、常识上说不准（不同城市口径不同的那种），跳过它、随手投掉换下一件再继续数

期望结果：四次全部被判为投对，没有出现某一件按常识投对了、页面却判错的情况（例如把矿泉水瓶判成不属于可回收物、把西瓜皮判成不属于厨余垃圾）。也就是页面内置的分类和生活常识一致，不是随便安排的。

Score 1.0: 符合预设状态、操作要求，且结果与期望结果一致。

Score 0.0: 不符合预设状态、操作要求或期望结果。

### Criterion 7: 记下当前这件垃圾是什么 (key: c07_operation_feedback, primary: interaction_function, secondary: operation_feedback, weight: 0.1)

预设状态：已进入游戏画面，画面上出现了一件等待投放的垃圾

操作：记下当前这件垃圾是什么，把它拖进任意一个桶，然后看画面。若页面在投放之后有短暂的过渡或动画，把测试时钟推进 2 秒再看结果

期望结果：这一件处理完之后，画面接着给出新的一件等待投放的垃圾，游戏能继续玩下去；不会停在原地不动、也不会卡在上一件的状态里出不来。偶然又抽到同一样东西不算问题，只要它重新进入了可以投放的状态。

Score 1.0: 符合预设状态、操作要求，且结果与期望结果一致。

Score 0.0: 不符合预设状态、操作要求或期望结果。

### Criterion 8: 查看四个桶各自的颜色 (key: c08_component_style, primary: visual_layout, secondary: component_style, weight: 0.1)

预设状态：已进入游戏画面，四个桶都在画面里可见

操作：查看四个桶各自的颜色

期望结果：四个桶用的是现实生活里这四类垃圾桶的颜色：可回收物是蓝色系，有害垃圾是红色系，厨余垃圾是绿色系，其他垃圾是灰色或黑色系。深浅和饱和度不限，四个桶的颜色两两能分辨开。

Score 1.0: 符合预设状态、操作要求，且结果与期望结果一致。

Score 0.0: 不符合预设状态、操作要求或期望结果。

### Criterion 9: 查看四个垃圾桶和当前等待投放的那件垃圾 (key: c09_component_style, primary: visual_layout, secondary: component_style, weight: 0.1)

预设状态：已进入游戏画面

操作：查看四个垃圾桶和当前等待投放的那件垃圾

期望结果：桶和垃圾都是画出来的图形，不是只有文字：用 SVG、Canvas、CSS 图形画的，或者用表情符号呈现的，都算图案。四个桶能看出是垃圾桶的样子；垃圾的图案和它是什么东西相称（例如西瓜皮画成瓜皮的样子、废电池画成电池的样子），不是四类共用同一个通用图标，也不是没有形状的纯色方块。整个游戏画面不是纯文字按钮堆成的列表。

Score 1.0: 符合预设状态、操作要求，且结果与期望结果一致。

Score 0.0: 不符合预设状态、操作要求或期望结果。

### Criterion 10: 进入游戏画面 (key: c10_responsive_layout, primary: visual_layout, secondary: responsive_layout, weight: 0.1)

预设状态：首页在 375×812 的手机视口打开（视口 375×812）

操作：进入游戏画面，整页从上到下看一遍，再把当前这件垃圾拖到其中一个桶上

期望结果：页面没有横向滚动，也没有元素比屏幕更宽。当前等待投放的垃圾和四个桶能同时出现在一屏之内，互相不遮挡——不需要一边拖一边滚动页面去找桶。在这个视口下把垃圾拖进桶同样能完成。

Score 1.0: 符合预设状态、操作要求，且结果与期望结果一致。
