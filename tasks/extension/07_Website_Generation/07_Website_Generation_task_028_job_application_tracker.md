# 求职投递跟进看板与清单

## Prompt

请在 /tmp_workspace 下从空目录创建一个可运行的中文求职管理/投递跟进工具网页项目。项目根目录需要提供 package.json，并支持 npm install、npm run build，以及 npm run start -- --host 127.0.0.1 --port 4173 启动网站。页面运行时不要依赖外部图片、字体、接口或其他网络资源；不要接入真实支付或发送真实请求。

我最近在找工作，同时在投的公司有几十家，光靠聊天记录和收藏夹理不清哪家走到哪一步了，想做个网页专门管这件事。

打开先看一块统计看板：一共投了多少次，其中还在流程里的、已经拿到 offer 的、已经终止的各有多少。除了已 offer 和已终止，其余状态都算还在流程里。看板上再放两张图，一张环形图看投递都停在哪些状态上，一张条形图看每个岗位分别投了多少次。

另一块是投递清单，把所有投递按最近更新的排在前面列出来；同一天里动过好几条的，刚改完的那条也要排到更前面去。每条能看到公司名称、岗位名称、投递状态、base 地、投递日期、更新日期、优先级、投递链接和备注。投递状态就用这十种：已投递、已测评、已笔试、已一面、已二面、已三面、已四面、已谈薪、已offer、已终止，新加进来的默认是已投递。更新日期不用我自己填，新记一条的时候和以后每次改动，都自动记成当天。状态要用能区分开的标签样式标出来，一眼看出哪些拿到了 offer、哪些已经终止。

新增、修改、删除都要能做。录的时候不用一次填全，公司和岗位写上就能先存下来，别的想起来再补。公司、岗位、base 地和优先级这几项，前面填过的值要记住：后面再填时打上一两个字，就把匹配的旧值列在下面让我直接选；一个字都不打的时候，也能把填过的值都列出来供我选，省得每次重打。

## Expected Behavior

Agent 应从空目录生成可运行的前端网站，按 Prompt 完成页面内容、交互和视觉要求；项目应能在本地 npm install、npm run build 并通过 npm run start 启动，且不依赖外部网络资源。

评分由 Playwright 运行时检查（内容与交互类评分点）和基于截图的视觉判分（视觉与布局类评分点）共同完成；每个评分点按“预设状态 → 操作 → 期望结果”独立判定。

## Grading Criteria

本题仅使用 LLM Judge 评分。评分点全部放在 `## LLM Judge Rubric` 中，每个 Criterion 只有 1.0 和 0.0 两档：非视觉类评分点由 Playwright 检查器按 key 给出运行时结果，视觉类评分点由 LLM 依据截图判定。
