# 二次元萌王大赛淘汰赛

## Prompt

请在 /tmp_workspace 下从空目录创建一个可运行的中文休闲娱乐/角色人气淘汰赛工具网页项目。项目根目录需要提供 package.json，并支持 npm install、npm run build，以及 npm run start -- --host 127.0.0.1 --port 4173 启动网站。页面运行时不要依赖外部图片、字体、接口或其他网络资源；不要接入真实支付或发送真实请求。

题目提供的输入素材已经放在 /tmp_workspace/assets 目录中，请直接使用这些文件，不要用自行编造的数据替代。

我想做一个「二次元萌王大赛」的网页，自己一个人玩：从 64 个角色里一路选下去，最后选出我心目中的萌王。

参赛名单和头像都放在 `/tmp_workspace/assets` 目录里。名单是 `/tmp_workspace/assets/characters.json`，每个角色写了名字、所属作品，以及头像图片在同一个目录下的位置。请直接用这份名单，每位角色都要能看到名字、所属作品和头像。

赛制是这样的。先按名单里的顺序，每 8 个人分成一个小组，一共八个小组，依次叫 A 组到 H 组。每个小组我要从 8 个人里挑出 2 位晋级，八个小组一共选出 16 强。从 16 强开始改成一对一，每场我在两个人里点更喜欢的那位，赢的进下一轮，输的淘汰，一直打到只剩一个人，那位就是萌王。选够人数就直接进下一组、下一场，不用我再按一次确认。

比赛过程中我想随时知道自己打到哪儿了：现在是第几组、或者一对一打到第几场了。

打完之后要有一张树形的赛程图，从 16 强一路连到决赛，能看出每一轮是谁把谁淘汰的、最后谁夺冠。萌王要在页面上单独突出出来，配上名字、所属作品和头像。

中途关掉页面再打开，进度还在，不用从头再来。另外给一个重新开始的入口，点了就清空重来。

整体做成二次元应援活动的感觉，明快一点，手机上也要能正常玩。

## Expected Behavior

Agent 应从空目录生成可运行的前端网站，按 Prompt 完成页面内容、交互和视觉要求；项目应能在本地 npm install、npm run build 并通过 npm run start 启动，且不依赖外部网络资源。

题目素材位于 /tmp_workspace/assets，页面内容必须与素材一致，不得用编造数据替代。

评分由 Playwright 运行时检查（内容与交互类评分点）和基于截图的视觉判分（视觉与布局类评分点）共同完成；每个评分点按“预设状态 → 操作 → 期望结果”独立判定。

## Grading Criteria

本题仅使用 LLM Judge 评分。评分点全部放在 `## LLM Judge Rubric` 中，每个 Criterion 只有 1.0 和 0.0 两档：非视觉类评分点由 Playwright 检查器按 key 给出运行时结果，视觉类评分点由 LLM 依据截图判定。
