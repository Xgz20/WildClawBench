# 版本无责复盘议程

## Prompt

下周一，也就是2026年9月14日10:00～10:45（Asia/Shanghai），我们要开一次版本复盘。参加人是产品、前端、后端、QA、设计和项目经理。这个版本晚了3天，主要争议是接口定义临时变更、QA介入偏晚，但灰度发布本身很顺利。

帮我排一个45分钟议程，既要讨论做得好的地方，也要找到延误原因并落到后续动作，不要开成甩锅会。最后附一段160字以内、能直接发群里的邀请。直接回复议程和邀请即可，不需要解释写作思路。

## Expected Behavior

Agent应直接给出合计45分钟的分段议程，完整保留固定时间、参会角色、延期及争议背景，同时把顺利的灰度发布纳入成功经验。议程应采用无责复盘方式，明确行动项和确认机制。群邀请不超过160字，可直接发送。

## Grading Criteria

- [ ] 固定背景信息完整准确 — 25%
- [ ] 议程分段合计45分钟且顺序可执行 — 25%
- [ ] 同时覆盖成功经验、延误原因和后续动作，保持无责 — 30%
- [ ] 群邀请不超过160字且可直接发送 — 20%

## LLM Judge Rubric

Judge只评价以下四个检查点，不增加整体印象分。每项只能使用`1.0 / 0.75 / 0.5 / 0.25 / 0.0`。

### Criterion 1: 固定背景覆盖 (key: fixed_context_coverage, weight: 0.25)

判据：输出是否准确保留日期、时间、时区、参会角色、延期、两个争议点和灰度发布顺利这一正向事实。

**Score 1.0**: 日期、10:00～10:45、Asia/Shanghai、六类参会角色、延期3天、接口定义临时变更、QA介入偏晚和灰度发布顺利全部准确。

**Score 0.75**: 核心背景正确，仅遗漏一个参会角色或一个次要背景，未增加冲突事实。

**Score 0.5**: 至少一半固定背景正确，但遗漏一个争议点、正向事实或多类参会角色；会议仍可识别。

**Score 0.25**: 只说明版本复盘，固定时间或背景大多缺失，或出现一处实质性错误。

**Score 0.0**: 日期、时段或复盘目标错误，虚构关键背景，或没有可用内容。

### Criterion 2: 议程时间安排 (key: agenda_timing, weight: 0.25)

判据：议程是否逐段给出时长、合计45分钟、顺序合理，并以行动项收口。

**Score 1.0**: 每个环节均有时长，合计恰好45分钟，依次覆盖开场、成功点、问题分析、改进和行动项确认。

**Score 0.75**: 结构可执行，合计43～47分钟，或只有一个环节顺序略弱。

**Score 0.5**: 有明确分段，但总时长偏差不超过10分钟，或缺少行动项收口。

**Score 0.25**: 虽有议题列表但缺时长，或安排明显无法在45分钟内执行。

**Score 0.0**: 没有议程、总时长严重冲突，或完全偏离复盘目标。

### Criterion 3: 无责与行动导向 (key: blameless_action_orientation, weight: 0.30)

判据：是否平衡成功经验、系统性原因和改进动作，避免归责个人，并明确行动落实方式。

**Score 1.0**: 成功点、延误原因和改进动作均具体；使用事实和流程视角，不归责个人；行动包含负责人、确认方式或期限。

**Score 0.75**: 三类内容齐全且保持无责，仅有一类不够具体或行动落实方式略弱。

**Score 0.5**: 只完整覆盖其中两类，或动作缺少负责人和确认机制，但未明显指责个人。

**Score 0.25**: 内容主要是泛化讨论，行动不可执行，或有明显归责措辞。

**Score 0.0**: 以追责、批评个人为主，没有复盘逻辑，或没有后续动作。

### Criterion 4: 群邀请可用性 (key: invitation_quality, weight: 0.20)

判据：邀请是否在160字以内，包含时间、目的和必要准备，可直接发群。

**Score 1.0**: 单段邀请不超过160字，时间和时区明确，说明无责复盘目的及简短准备要求，可直接发送。

**Score 0.75**: 可直接发送，仅遗漏一个次要准备要素或长度为161～175字。

**Score 0.5**: 时间与目的可辨，但需明显压缩或补充准备说明。

**Score 0.25**: 关键时间或目的缺失，像写作说明而不是群邀请。

**Score 0.0**: 未提供邀请，或邀请包含错误时间、指责性要求。
