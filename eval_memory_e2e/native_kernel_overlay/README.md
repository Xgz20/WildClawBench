# AStudio 原生执行服务的诊断补丁

状态：**合成执行器验证通过；真实自动整理未准入**。不得据此启动正式记忆评测。

`controller.patch` 基于用户提供的 ACode 源码提交
`5c4f8cfd60d2a0574b814e80d86d79c7094937fb`。源码私有副本和工具链分别位于
worktree 的 `.kernel-source/acode`、`.kernel-tools`；原源码仓库与安装的 AStudio 均不修改。
补丁不含账号、配置、记忆或调试原件。

该执行器保留原生 SBPL 和参数绑定，在最后追加经过语法校验的控制端拒绝规则，
只安装一次组合策略。外部服务入口绑定应用进程及其内核后代的实际套接字身份；
所有候选文件数据访问和进程执行都必须进入组合策略的工作进程。
流式文件句柄由工作进程持有，控制服务本身不打开候选文件。
不得使用已发现符号链接泄漏反例的路径前缀求交代理替代此实现。

构建、测试与冻结使用 `python -m eval_memory_e2e.native_kernel`。
构建参数、原始日志、前后补丁和二进制摘要必须写入新的私有证据目录；
只有源补丁摘要与实际二进制版本信息一致时才可冻结制品。
Rust 测试通过源码仓库要求的 `just test` 执行。

v2 的真实试验发现了尚未修复的调用路径：自动整理的 `bash` 使用
`core/src/tools/runtimes/shell.rs` 的本地 `execute_env`，
即使文件系统已连接远端执行服务，仍在外层沙箱内再次安装原生沙箱。
21 项协议探针通过不能覆盖这个应用层缺口。保留该次 3/7 的 UI 操作，
不得重发或将后台 job 的 `done` 等同于整理正确。

后续 v3 诊断补丁已为经典 shell 增加远端分支，沿用 core 原有输出、超时和错误契约，
将原生权限交给执行服务编译；本地执行分支保持原样。完整 ARM 内核已构建并冻结，
仅通过已验证的后端 `ASTUDIO_ACODE_BIN` 入口接入，必须使用显式 v3 租约、
独立单元及冻结制品，不替换安装内核。合成准入通过不代表自动整理兼容性通过。
