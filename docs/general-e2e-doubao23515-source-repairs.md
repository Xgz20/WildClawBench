# DoubaoWork 2.35.15 十题验证的评分源码修复

本轮使用原冻结的十题和执行产物，执行与独立评分均配置三个槽位。QwenWork按用户要求暂停。控制会话不充当语义裁判。

| 用例 | 已确认问题 | 修复边界 |
| --- | --- | --- |
| Info001 | 需结构修复且内容未通过原等价比较的候选PDF，被归入未知版本复核，阻断整题 | 接受版本及等价签名仍优先通过；仅对同时不等价、需结构修复的候选标记交付未通过。结构完整的未知版本仍待复核。不替换或修复候选，不扩大原4分预算。 |
| Office010 | 原安全公式解释器不支持合法整列COUNTIF/SUMIF/COUNTIFS/SUMIFS | 在原100000个物理单元格预算内读取已用区域，保留整列1048576行的隐式空白语义。不同区域保持长度校验；外部工作簿及未实现数组运算仍拒绝。原原因复核和业务公式不变。 |
| Office015 | 证据分片的大小估计未使用最终JSON编码器已有的日期处理，遇到datetime抛异常 | 大小估计采用相同default=str；不修改实际日期、候选文件、原分数或证据预算。 |

三个修复直接落在题源Automated Checks，并由标准CLI及独立E2E评分共用精确原源码SHA修正。题面、预期行为、检查点、参考答案、语义Rubric和权重不变。

新E2E attempt明确冻结修复标记；无标记的历史attempt继续复放原源码。历史数据集通过原题源快照重建，原manifest摘要不改。旧60题和七维能力映射不修改。

旧失败只在契约、源码、Worker请求和错误完全匹配、未产生正式分数或独立裁判且Worker已退出后登记为未评分。原失败、输入和SHA保留。修复后从同一冻结执行建立新的独立单题评分，验分后显式选择纳入完整十题范围，不按分数择优。

同时修复MOA评分说明对旧Prompt协议的污染：Score低于0.10.70或旧协议不追加新说明，已冻结Score0.10.70/v8的Prompt字节保持。
