## 1. worktree 会不会影响通用和 Web E2E

**worktree 隔离文件修改，不隔离被复用的代码，也不隔离本机客户端状态。**

| 范围 | 本轮情况 | 影响边界 |
| --- | --- | --- |
| 主 checkout 的跟踪文件 | 没有改写、合并或提交 | 不会随本 worktree 的文件修改而变化 |
| 记忆专用代码 | `eval_memory_e2e/`、`tasks/memory-e2e/`、相关测试与文档 | 使用独立任务契约，不替换 General/Web 的评分入口 |

## 2. 用例格式能否扩展复杂评测

**可以扩展。v1 保持原有严格校验，新增 v2 用于可变规模的线性多会话任务。格式支持与真机 Adapter 已验收能力分别判断。** 原混合 20 题仍为 14 道 LongMemEval 作者原题适配、6 道自建，来源、原题及答案未改写。

| 维度 | v1 | 本轮新增 v2 |
| --- | --- | --- |
| 数据集规模 | 固定 MEM-01…20、固定维度及难度分布 | 可变题量、自定义用例 ID；不再固定 20 题或 6/8/6 分布 |
| 会话流程 | 学习、干扰、更新、遗忘、应用、探测 | 保留这些阶段，支持更长的线性任务链与多个探测点 |
| 作用域 | A/B | 声明更多工作区作用域；示例和离线闭环覆盖 A/B/C。它们不代表不同账号或真实租户 |
| 事实生成 | 固定的一组占位变量 | 新增 token、整数区间和 literal 变量；跨客户端和 C0/M+ 共享同次事实，重复使用新事实 |
| 学习条件 | 由 Profile 解释 | 显式声明主动、自动或淘汰实验，以及观察窗口或待接入的原生事件条件 |
| 材料 | 内置公开 fixture | 可引用数据集内公开材料及 SHA；路径逃逸、符号链接和摘要漂移拒绝 |
| 评分 | probe 的私有检查点及证据引用 | 继续使用检查点与现有指标注册表；存储快照作为独立证据，不自动冒充语义评分 |

主动组可以包含“请记住”；自动组使用不要求保存的业务输入，并采用中性的执行边界，不再额外注入“使用原生记忆机制保存本轮资料”的指令。两组都保留 Codex 排除、合成资料限定和禁止读取评测控制材料的约束；旧批次的 Prompt 不就地改写。

v2 学习条件示例：

```json
{
  "scopes": ["A", "B", "C"],
  "learning": {
    "mode": "automatic",
    "formation": {"kind": "elapsed_observation", "minimum_seconds": 120}
  }
}
```

这里的 120 秒只是显式观察条件，**不证明客户端已完成自动记忆整理**。`native_event` 可以在格式中声明，但当前没有已准入的执行适配，原生批次会在创建工作空间、发送提示词之前拒绝；不会用等待若干秒替代指定事件。

完整示例：[complex-memory-v2.json](../../../tasks/memory-e2e/examples/complex-memory-v2.json)。Schema：[scenario-v2.schema.json](../../../eval_memory_e2e/contracts/scenario-v2.schema.json)。验证命令：

```bash
python3 -m eval_memory_e2e validate-dataset --dataset tasks/memory-e2e/examples/complex-memory-v2.json
```

当前仍未实现条件分支/DAG、多账号切换、多智能体并行、多臂实验，以及任意人工/UI 操作步骤。`continue`、`restart_new` 即使格式允许，也须通过目标 Driver 的能力门禁；未验收不等于产品不支持。未来增加新的执行语义应升级契约或补齐对应 Adapter，不能靠增加 JSON 字段就算已经支持。

## 3. AStudio 指定配置的验证结果

采用了用户提供的六个字段：`features.memories=true`，`generate_memories/use_memories/dedicated_tools=true`，`extract_model/consolidation_model="spark-x2.5"`。仅修改两份已核验的 `.acode` 配置；原始文件私有备份为 0600，字段级合并保留其他参数和注释，没有改动 `.codex`。

| 层次 | 实际观察 | 判断 |
| --- | --- | --- |
| 配置解析 | 安装内核 feature 回读通过，源配置与桌面 overlay 的指定字段均生效于配置文件 | 配置字段被接受 |
| 进程应用 | 确认前台任务空闲后重启 AStudio | 没有以文件修改冒充运行中会话热应用 |
| 专用工具 | 新会话实际调用 `memories__list/read/search/add_ad_hoc_note` | 专用工具已在该条件下暴露、执行 |
| 真实存储 | 在 `.acode/.../memories/extensions/ad_hoc/notes/` 找到含本轮随机事实的文件 | 明确保存有独立文件证据；不只依赖“已记住”的回复 |
| 新会话使用 | C0 三字段未知；M+ 学习、独立会话干扰后，最终三个字段均正确回忆 | 一组主动记忆行为验证通过，未作为正式评测得分 |
| 自动抽取/整理 | 本轮窗口内存在成功抽取记录和全局整理完成记录，也存在 `expected value at line 1 column 1` 错误 | 部分链路可运行；JSON 输出/解析稳定性未验收，不能宣称网关所有记忆任务均兼容 |

工具轨迹中的结构化返回有信息有限的情况，因此本轮同时保留原始 rollout、文件快照及后台状态。不能从工具日志的空对象直接推断没有写入，也不能从模型自述“已整理”推断后台整理成功。

本轮是**显式启用、指定模型且启用专用工具**的条件，不代表 AStudio 出厂默认行为。摘要注入、专用工具与后台学习是不同路径；尚未做专用工具关闭条件下的独立摘要注入实验。

AStudio 在运行期间可能暂时隐藏模型控件。观察恢复允许沿用原发送前配置等待，终态必须从同一个原生 turn 的模型 ID、推理档位、cwd 和权限核验；`builtin/` 本地模型编码会按已观察格式解码，不能因此推断网关最终路由模型。后续新批次还会冻结两份配置中的指定记忆字段。

## 4. 自动化优化与当前收口

- **依赖冻结**：原生 Driver 按本地字面量引用递归冻结源码、原生 helper 和依赖锁文件，按指定 Harness 执行时不再校验其他端专用依赖。共享依赖、Python 运行时和冻结题目变化仍会阻断。旧批次保留原冻结范围，不能通过新规则静默缩减其边界。
- **零发送重试**：新增 `retry-pre-send`。目前只接入千问/豆包；要求原生发送数为 0、未进入原生发送意图/reservation/invoking/接受边界、原生空闲且原题与配置绑定一致。未知发送继续观察。豆包 prepare-only 恢复保持零发送，不会把准备占位文本发给模型。
- **阶段快照**：学习前、观察中、完成后记录已知本地存储的原件 SHA、时间及合成文本存在性；相同状态去重，快照私有保存。豆包云端存储等不可见层保留 `unobservable`。字符串命中不等于语义正确或完成记忆形成。
- **报告状态**：执行完成链数、Prompt 步骤完成数、需处理链数与语义得分分别展示；执行完成、未评分、能力失败和评测异常不再混为一个总分状态。
- **能力声明**：会话动作准入与记忆效果、操作员清理能力分开。移除未实现的清理/读回占位能力，定向清理继续明确为未验收；不以声明标签冒充环境重置证据。
- **跨端调度**：控制/UI 调用保持串行，按 Harness 轮询已经派发的原生任务，允许它们在客户端后台继续执行。同端仍须先完成 C0 再执行 M+；单端失败暂停该端，保留原操作并继续其他端。调度策略和轮询间隔写入 journal。四端后台重叠与故障隔离目前通过离线调度测试，尚未声称完成四端真机并发验收。
- **豆包新版兼容**：已完成 C0/M+ 四次原生请求和四次目录重新核验。最终代号、日期完整，联系人输出为 `-7FC4F4`，与学习时 `联系人-7FC4F4` 存在展示差异，留给独立语义判定，不预填 3/3 得分。设置入口兼容动态会话标题和两种原生 URL Scheme。
