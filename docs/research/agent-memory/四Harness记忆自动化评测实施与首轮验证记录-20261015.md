## 1. 已实现的流程与验证边界

记忆任务使用 `scenario / run / arm / episode / step / attempt` 协议，复用 General E2E 的四端原生控制、GUI 准入和轨迹读取。每次实际操作先冻结唯一意图、Prompt 摘要、账号指纹和目录，再接受原生 session / turn / cwd 证据；整个 episode 可以包含多个独立会话。

发送后控制器超时或点击结果不确定时，只恢复观察原操作。新增源码可通过 `repair-runtime` 留存原件和修复链，不能改写已经冻结的题目或借此重发。共享 UI 锁只在精确 owner 已退出、归属与主机核验通过后归档恢复；陈旧文件本身不构成再次发送的授权。

原生 Profile 固定 `purpose=immediate_automation_smoke`、`formal_scoring_allowed=false`。控制调用预算 180 秒用于 UI 准备和一次观察，不是模型执行期限；10 秒窗口也只用于即时行为观察。正式评分入口拒绝把这些批次作为长期记忆能力成绩。

新批次每条 Prompt 都带四端操作边界：不访问或改动 Codex 记忆、不让其他客户端代做、不清空日常账号、不修改无关记忆。最新边界还禁止读取评测控制目录、参考答案、Prompt 副本及其他 episode 工作区。旧批次不就地改题。这些提示约束不能代替文件系统隔离；正式评分仍需审计实际工具轨迹，发现评测材料泄漏时不能纳入有效能力样本。

## 3. 千问样本：写入后未留存目标事实

实验为原自建诊断集 `memory-diagnostic20-v1 / MEM-01`，不是 LongMemEval 原题。本轮随机合成项目为 `澄屿-8625FC2B126A`，三项事实为代号、联系人、计划日期。先运行没有历史输入的 C0，再运行 M+ 的学习、干扰、探测三个新会话。两组探测问题相同，探测不重述答案。新会话身份和目录均由原生证据绑定。

| 最终存储观察 | 日志仍保留学习会话的同一 `memory-chat` 锚点，但块内容变成容量满时如何转存的经验总结，已不含项目代号及三项事实 | 目标事实在最终文件中未留存，不能仅解释成“文件中仍有事实、检索没有找到” |

这是一组样本的描述性观察：C0 和 M+ 最终均有 3/3 字段未知，**不是正式得分、产品总体成功率或统计显著结论**。长期文件容量拒绝与 daily 内容变化分开记录，不能把前者写成所有记忆层都无法写入，也不能把后者直接归因于时间衰减或访问频率淘汰。

已核验安装包实现：daily 写入用 chat ID 锚定块，`replaceOrAppend` 对已有锚点替换整个块。这提供了“同一锚点后续维护可能覆盖原事实”的机制线索；尚未取得本次替换的后台写入事件，具体写入者和触发条件仍待核验。不能仅根据最终回答推断底层没有写入，或宣称所有自动整理都会覆盖主动记忆。

## 5. 数据集、指标和正式执行条件

正式候选集 [memory-mixed20-v1](../../../tasks/memory-e2e/memory-mixed20-v1/manifest.json) 为 **14 道 LongMemEval 作者原题适配 + 6 道自建补充，35 个检查点**；原题、答案、revision、许可与适配说明见 [ATTRIBUTION](../../../tasks/memory-e2e/memory-mixed20-v1/ATTRIBUTION.md)。使用 oracle 证据会话及较短历史选择，不能作为官方 LongMemEval 成绩或代表性随机抽样。原自建 20 题仍保留，短事实自动化冒烟单独使用该集，二者不混报。

20 个独立场景适合首轮问题诊断。正式计划为 20 场景 × 4 客户端 × C0/M+ × 3 次独立重复，合计 480 条任务链；同一场景的重复不能当作新增独立场景。10 题适合流程试跑，40–60 个独立场景更适合稳定比较。每个维度仅有 2–3 个场景时，百分比必须同时给出分子、分母及逐题证据，不据此作精细排名。

正式执行前仍须依次完成：

1. 四端原生链路和定向清理验收。清理后验证存储、索引、新会话和旧历史再生成，不以关闭记忆开关代替删除生效。
2. 冻结各端学习条件。AStudio 先验证实际启用、候选资格及两阶段完成；WorkBuddy 等待每晚整理或验证明确主动更新；千问验证写入与后续维护后的保留；豆包区分主动与周期更新。即时窗口不能替代这些条件。
3. 完成保持、更新、定向遗忘、经验应用四类调试场景，再冻结正式 20 题和重复策略。跨重启、continue 等尚未验收的能力不得仅靠 Profile 字段宣称支持。
4. 独立裁判按检查点评分，报告事实回忆、应用、新值遵循、旧值误用、遗忘遵循、非目标误删、作用域泄漏、合理拒答和经验增益。无法观察的内部检索分母不造 `Recall@k`；工具返回的原始结果数可以单独描述。

淘汰策略继续按频率、时间、容量、语义合并和用户主动清理分实验。当前账号不做填满容量或篡改系统时钟的压力实验。清空环境是评测可靠性的一部分；用户手动删除只是淘汰策略的一类。
