# 记忆评测准入门禁与渠道分层实施

本轮将 16 日的五项优化建议落实为独立 v3 契约、普通执行器的清理前门禁、渠道审核和分层清理报告。旧 v1/v2、混合 20 题和既有冻结批次保持原范围。本轮的协议验证不产生四端正式记忆能力成绩；实际客户端验证与离线模拟分开记载。

## 1. 变更对应的问题

| 16 日发现的问题 | 本轮实施 | 验收边界 |
| --- | --- | --- |
| 普通 `run` 不解释清理前回答，外部脚本负责暂停 | v3 `response_json_exact` 在后续步骤发送前检查冻结回复 | 只适用于明确 JSON 字符串字段，不能替代自然语言语义评分或后台形成事件 |
| 工作区文件容易被升格为账号画像 | v3 `channel_review` 独立审核存储位置、写入主体、读取机制和控制方式 | 代码核对绑定与引用，审核者负责判断证据是否支持机制解释 |

## 2. 新协议如何暂停与恢复

新数据集为 [scoped-forgetting-v3.json](../../../tasks/memory-e2e/canaries/scoped-forgetting-v3.json)，仍是自建准入 canary，不计入正式 20 题。它沿用上一版的六步 M+：写入、清理前查询、定向遗忘、清理后查询、中性会话、再次查询。仅 C0 查询范围由新版本显式选择为 `before`，因此每端由九次 Prompt 减至七次；四端共 28 次计划 Prompt。

`forget` 前有两道门禁：

1. `recall-before-forget`：读取 `before` 的冻结最终回答，要求 JSON 的 `target`、`keep` 完整准确。重复键、额外字段、仅包含答案子串、格式不确定或未完成均不通过。预期值只存在私有冻结场景中，不传给 Driver 或清理 Prompt。
2. `memory-channel`：从 `seed` 的冻结轨迹、binding、候选文件及已知本地文件快照生成私有审核模板。独立审核必须提交每项机制判断的引用，且绑定 manifest、episode、gate、来源 operation 和 receipt 摘要。本地／工作区渠道必须有对应位置的文件原件；仅凭工作区文件不能认定账号画像。

清理前回忆未通过时返回 `PREREQUISITE_FAILED`；渠道尚未审核时返回 `AWAITING_CHANNEL_REVIEW`。`run`、`advance` 和手工 `intent` 都阻止后续派发，保存暂停原因与计划分母，分数保持空值。缺审核不会影响其他 Harness 继续执行。审核入库后只继续下一步尚未发送的操作，已有请求的观察恢复和禁止重发规则保持不变。

渠道审核会核对原文片段和文件位置，但不能用机械引用校验替代解释判断。审核不充分或机制仍未知时，应提交不准入结论；不得为了继续自动运行而填写未经证实的“自动注入”。有效审核不可覆盖，修改实验条件须另建批次。

带 `experience_gain=true` 的新题仍要求 C0/M+ 使用全部相同 probe/checkpoint；不能用不同考点的均分计算经验增益。条件内评分模板仅生成实际计划的检查点。v3 继续只支持线性流程，未新增 DAG、多账号、多智能体或任意 UI 步骤。

操作入口与字段说明见 [README](../../../eval_memory_e2e/README.md)。
