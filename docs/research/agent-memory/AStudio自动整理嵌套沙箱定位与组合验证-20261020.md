## 验证目的与清空策略的关系

当前有两个独立的准入问题：

1. **跨用例、跨重复污染。** 按用户已确认的“用例 × 重复”建立新本地记忆单元，轮内各阶段、多会话持续保留记忆。此前显式记忆的 A/r01 → B/r01 → A/r02 共9次 UI Prompt 已通过；完整事实和边界见[前次验收](AStudio跨用例与跨重复记忆隔离验收-20261020.md)。
2. **自动整理执行异常。** 内核已经继承外层 Seatbelt，后台整理又调用原生 `sandbox-exec`，第二次安装沙箱失败。即使单元为空，这个错误仍然存在；不能将未执行成功的整理计作模型记忆能力失败。

在每个“用例 × 重复”开始前完整清空评测记忆，可以成为隔离方案，但必须验证所有可检索来源与再生成来源的重置，并先等待后台空闲。仅删除可见笔记，不能证明历史会话、原始抽取、摘要、索引或后台任务不会重新引入旧值。如果一轮包含多个用例，仅在第二整轮前清空，也无法满足跨用例隔离。

现有独立单元已经提供空状态、保留同账号登录、拒绝访问旧单元的机制，不必删除日常账号记忆。清空或换单元不能修复二次 `sandbox_apply`，也不能替代非目标客户端数据的 OS 访问隔离。本轮继续验证的目的，是让自动整理在这些边界内正常工作。

## 被否决的原生执行服务路径

安装内核实际支持 `exec-server`，也实际接受带 `permissions` 的 `process/start` 与原生文件 RPC。用独立控制进程处理执行，再由原生工作进程安装一次策略，可以避开二次安装的机制冲突。公开上游的[原生环境实现](https://github.com/openai/codex/blob/main/codex-rs/exec-server/src/environment.rs)仅作架构参考；本轮字段、结果与签名身份均以安装内核的实测为准。

最初仅用路径前缀树计算原生权限与外层权限的较小值，基础读写和拒绝测试能够通过。但这不足以构成安全边界：

- 在当前工作区内建立指向合成非目标目录的符号链接。
- 原生策略中显式授权该链接；词法求交仍将链接路径视为当前单元内路径。
- 原生编译器随后规范化授权路径，将授权移动到链接实际目标，导致原本应拒绝的目标重新可读。

独立新目录中复现 **4次预期拒绝、4次意外读取**，涵盖原生 read/write 两种授权和直接目标/链接两条访问路径。只访问合成文件，文件 SHA 未变。结果保留为 `FAIL_ISOLATION_PREFIX_INTERSECTION`，不改写成通过。另有前缀别名组合的 OS 查询与写正控不一致，`protocol-v2-ancestor`、`protocol-v3-guarded` 同样保持 `NOT_ADMITTED`。

因此没有将这个执行服务代理接入 AStudio、没有放宽原有 OS 门禁。原型现在明确要求 `synthetic_only=true`、精确诊断进程身份、`application_integration_allowed=false`，并拒绝应用租约；Python 变换入口也拒绝应用模式。知道正确随机 token、但套接字所属 PID 错误的客户端连接实测被拒绝。未知 API 和可能在命令沙箱外执行 shell 初始化的 snapshot 请求均拒绝。

最后的 `protocol-v4-final-guard` 另绑定诊断脚本的精确命令身份，拒绝 AStudio 应用执行进程；10项协议检查、12项文件操作、6项OS查询及错误PID负例通过，但由于上述反例仍明确保持 `security_admitted=false / NOT_ADMITTED`。基础检查通过不能覆盖已知的安全失败。

## 单次 SBPL 组合原理的合成验收

新增 `seatbelt_composition.py`：对两个冻结 SHA 的策略字节串进行验证，完整保留原生 SBPL，只追加外层策略的显式 deny 片段。外层 `(version 1)` 和 `(allow default)` 不进入组合结果，防止扩大原生授权。追加片段只允许当前控制器所需的 literal/subpath 与逻辑过滤器，拒绝 grant、宏、include、代码及摘要漂移。

`seatbelt_composition_probe.py` 使用明确标注的**合成 deny-default 原生策略**，没有假称拿到了 AStudio Phase 2 真实 SBPL。它与当前相同形式的单元隔离 deny 规则合成后，由系统 `sandbox-exec` 安装一次，工具子进程继承。最终独立目录 `composition-v3-final`：

| 检查 | 结果 |
|---|---|
| Python 与安装 Electron RunAsNode 两路基础文件操作、工具子进程继承 | 52/52 |
| 原生只读/私有区、越界写、网络拒绝、现有文件写正控、父目录元数据/枚举、旧用例/旧重复读/stat/枚举/写/链接访问 | 18/18 |
| 当前可读写与非目标、旧单元、原生只读区的实际 OS 策略查询 | 6/6 |
| 合成旧用例与旧重复的 memory.md | 保留，前后 SHA 一致 |
| 内层关闭沙箱、重签名、放开父目录读取 | 均未实施 |

总计 **76项合成检查通过**，状态 `PASS_SYNTHETIC_SBPL_COMPOSITION`。原生策略即使显式 grant 非目标路径，外层显式 deny 仍生效；原生网络与只读限制也保留。父目录可 stat，但仍不能枚举；没有以放宽读取换取 Node realpath 可用。

这验证了组合原理，**没有验收真实后台作业、自动形成或整理产物**，不能开启正式自动记忆评测。

## 真实接入阻断及下一步

当前内核的原生 JSON 路径权限接口不足以实现上述原生 SBPL 字节级组合；不能用已发现泄漏的词法求交代理替代。已询问这版 ACode 源码或可修改路径，目前没有取得源码或新的支持构建。

需要的内核接口应在原生策略生成完成后、安装 Seatbelt 前，附加由受控执行器冻结的 deny 片段，并在沙箱外的受信控制进程内创建原生工作进程、**只安装一次组合策略**。应用后端/主内核仍保持现有 OS 拒绝规则。所有命令、文件 API 和沙箱前 shell 初始化路径都须纳入，不允许无 sandbox 参数时直接走无约束文件访问；后台整理的原始策略、网络权限、cwd、环境、stdio、取消和退出语义必须保留。受信控制进程角色需由新租约和进程证明明确绑定，不能给现有 v1 增加宽泛的外部进程豁免。

取得相应源码或构建后，仍须新建批次，先通过符号链接/路径别名/后台/进程负例，再以同账号的新单元执行 UI canary，核对真实整理产物与新会话读取、旧值缺失和后台自然收尾。不能复用旧失败操作，也不能因合成组合通过就将 `automatic_generation_compatible` 改成 true。
