# AStudio 跨用例与跨重复记忆隔离

日期：2026-10-20，北京时间。仅在 `.agents/memory-e2e`、`feat/memory-e2e` 实现与本地验证；实现提交为`6c532910`，未推送远程。正式20题未启动。

## 边界与方案

采用同账号的独立本地记忆单元，不清空日常记忆。单元粒度为**一个用例 × 一次重复**；单元内 C0、学习与多会话查询共用记忆，期间不重置。切换用例或重复时创建新单元、退出旧实例、启动新实例。C0/M+仍按冻结顺序执行，不宣称记忆开关消融或条件内完全独立。

单元拥有独立的桌面 userdata、Electron 状态、ACode source-home、overlay、会话、SQLite、记忆目录与临时目录。只从普通 AStudio 导入当前原生登录 session 和白名单模型提供方配置，不导入源会话、笔记、摘要、索引、插件、用户指令或浏览器资料。保持同一原生 UID，以私有指纹核验；认证原件不进入Git或公开日志。

安装包支持 `ASTUDIO_HOME`；生产版桌面仍会把后端的 ACode home 指向普通 `.acode`，因此在原有精确后端 spawn 包装中，仅覆盖该后端的 `ASTUDIO_ACODE_HOME/ACODE_HOME/TMPDIR`。内核实际 `ACODE_HOME` 必须为本单元 overlay；产品会主动移除内核环境中的 `ASTUDIO_*` 变量。没有伪造整个OS用户HOME，没有修改客户端包、模型RPC或消息提交处理器。

继承原非目标目录 Seatbelt 拒绝策略，并增加：

- 后端、内核及其工具子进程不能读写普通 `.acode`。
- 不能读写其他测试单元、旧工作区、控制日志、私有答案和历史证据。当前单元 runtime 与本批 candidate 除外。
- 持久写入只允许当前 runtime、candidate 与合成正控目录，防止把测试事实另存到单元外。
- 为 Node `realpath` 放行精确父目录元数据，仍拒绝枚举这些父目录内容和写入；覆盖 `/System/Volumes/Data` 别名。

这属于当前安装版本的本地执行链文件访问隔离。主UI仍用产品原有Chromium沙箱，不宣称整机、全部XPC代理或云端账号状态穷举隔离。每次发送意图前、Driver入口与实际按下前核验当前单元、账号、环境、OS策略和主进程身份；旧实例租约不能复用。

## 接口与防误用

入口为 `python -m eval_memory_e2e.astudio_scope`：

1. `create --scope <新单元>/scope.json --case-id <用例ID> --repetition <序号> --batch-root <新批次>`，默认设置`generate_memories=false`，保留原生使用和显式笔记；不能由该配置推断全局后台不运行。
2. `python -m eval_memory_e2e.os_boundary selftest --lease-dir <新租约> --astudio-scope <scope.json>`。
3. 先确认没有其他AStudio执行实例，再 `os_boundary launch --lease-dir <租约>`；固定模型、推理与权限，核验当前账号。
4. `native-profiles --astudio-boundary-lease <租约>/lease.json`，再普通 `prepare/run`。prepare必须选精确绑定的单个用例、`--repeats 1`和绑定批次目录；跨用例/重复另建单元，不能改旧manifest。
5. `astudio_scope close --scope <scope.json> --boundary-lease <lease.json>` 核验本单元原生会话与 `memories_N.sqlite` 的作业状态/租约空闲，正常退出自有实例并检查执行根消失，保留全部文件。下一单元不能继承旧实例或旧租约。

当前是显式逐单元编排，尚无已验收的一键正式20题多单元外层调度。旧未隔离Profile只保留历史语义，不能标为独立重复或完整重置。配置恢复不等于删记忆；这里通过全新空单元和OS拒绝访问旧单元实现隔离，未调用 `memory/reset` 或删除普通AStudio数据。

采集器的SQLite临时副本也在各操作私有控制目录中，客户端自己的TMPDIR则仍在本单元runtime，防止控制器异常退出遗留副本成为旁路。三个通过批次均登记仅采集侧的`runtime-repairs/0001.json`，保留修复前后源码；最后一条已完成操作沿原session/turn只读复查成功，未新增INTENT或发送。新增Node回归使用真实合成SQLite，验证副本确实落在私有目录。

## 保留的失败与修复

- 最初策略拒绝所有父目录元数据，导致后端在realpath userdata时报EPERM；发生在任何Prompt之前，放行精确父目录元数据后重建单元，枚举仍拒绝。
- 首次环境核验错误要求内核保留ASTUDIO变量；实际内核只保留ACODE_HOME/TMPDIR。按实际源代码与进程环境修正，未发送Prompt。
- 本机3.5.0的renderer与旧机同版本资源不同，连接状态门禁在UI准备之前拒绝；旧意图保留，新单元采用源码核验后的适配。
- 新单元回执曾遗漏顶层launch_identity；发送前门禁抛错，DOM click/submit均0、原生会话0。保留旧意图/草稿，补回执与测试后新建单元。
- 首个已接受C0遇到采集器旧home限定；通过 `runtime-repairs/0001.json` 保存修复前后源码，沿同一原生session/turn补收，未重发。自动生成条件随后因上述嵌套沙箱问题未准入。
