# General E2E 证据修复与有效结果交付

以下命令使用同一份已校验的 General Skill 解包目录。旧批次继续引用原发行，修复后的运行时另行冻结；不要覆盖运行中的 Skill、旧执行或旧评分。

```bash
export GENERAL_SKILLS_ROOT=/absolute/path/to/general-e2e-skills
export GENERAL_WORKSPACE=/absolute/path/to/evaluation-workspace
export GENERAL_UNIT_ROOT=/absolute/path/to/execution-unit
export GENERAL_BATCH_ROOT=/absolute/path/to/batch
```

## 执行阶段修复

先看队列、journal、正式回执和活进程。有活worker时观察该进程。已发送的任务只能沿绑定attempt观察；发现原生身份、路由和终态一致后收口，不能为了修复框架而再次点击发送。

QwenWork和DoubaoWork支持在暂停队列上显式登记运行时修复。修复清单需要原队列文件SHA、原/新源码摘要、原queue/unit范围和原因。恢复使用原参数，不能同时改并发、题序或身份。

```bash
node "$GENERAL_SKILLS_ROOT/execute-general-e2e/drivers/doubaowork/batch.mjs" \
  --unit-root "$GENERAL_UNIT_ROOT" --queue-id QUEUE_ID \
  --expected-permission '全部允许' --run-slots 3 --resume \
  --source-repair-manifest /absolute/path/to/source-repair.json
```

DoubaoWork清单字段：`schema_version=1`、`queue_id`、`unit_root`、`original_queue_sha256`、`original_source_sha256`、`patched_source_sha256`、`preserve_attempts=true`、`reason`。`batch.mjs`导出`sourceDigest()`用于计算当前源码摘要。只有`NEEDS_ATTENTION`状态且旧队列字节完全一致时才能登记，旧文件另存备份。

QwenWork的对应选项同为`--source-repair-manifest`，并要求`--resume`及原probe/config参数。其清单使用`original_queue_state_sha256`、`original_driver_sha256`、`patched_driver_sha256`、`anchor_task_id`、`anchor_journal_path`、`anchor_journal_sha256`和`reason`。anchor须为该队列内一个一次发送、身份已验证且已完成的任务；修复升级另绑定前一清单和源码SHA。它不会改任何任务的发送次数。

保护确认默认人工处理。QwenWork仅在当前任务得到明确授权后，可在冻结配置中设置`sensitive_output_policy=allow-original-on-this-task`，同时填写授权文件路径及SHA。授权文件绑定`task_id`、`unit_root`和同名确认策略。实际点击才增加人工介入次数；未知弹窗不适用。

## AstronStudio 项目别名

已正式收口、无执行worker且新鲜probe通过后运行。省略`--task-id`表示manifest中的全部任务；也可重复指定准确task_id。

```bash
node "$GENERAL_SKILLS_ROOT/execute-general-e2e/scripts/rename_astronstudio_projects.mjs" \
  --unit-root "$GENERAL_UNIT_ROOT" \
  --frozen-config /absolute/path/to/frozen-run-config.json \
  --task-id TASK_ID
```

别名回执写入`.general-e2e/project-aliases/`。该操作不移动Workspace、不改Prompt和冻结包。

## 评分后修复资源统计

先确认是框架漏采/适配问题，还是客户端没有暴露字段。框架漏采应从同一原生身份补齐；缺字段不能填0。仅有输出文件也不能反推工具调用、Token或请求数。

如果AstronStudio原始归档缺失，但原生数据仍在，使用同一attempt的已验证状态归档。源数据库、线程、turn和Workspace须精确绑定。

```bash
node "$GENERAL_SKILLS_ROOT/collect-general-e2e/scripts/archive_astronstudio_trace.mjs" \
  --state-file /absolute/path/to/original-automation-state.json \
  --state-db /absolute/path/to/state.sqlite \
  --output-dir /absolute/path/to/new-bound-trace
```

然后创建独立补充层。支持AstronStudio与DoubaoWork；WorkBuddy继续使用其已有`supplement-resources.mjs`和`supplement-timing.mjs`。

```bash
node "$GENERAL_SKILLS_ROOT/collect-general-e2e/scripts/supplement_resources.mjs" create \
  --unit-root "$GENERAL_UNIT_ROOT" \
  --execution-record /absolute/path/to/frozen-execution-record.json \
  --state-file /absolute/path/to/original-automation-state.json \
  --trace-index /absolute/path/to/bound-trace/trace-index.json

node "$GENERAL_SKILLS_ROOT/collect-general-e2e/scripts/supplement_resources.mjs" verify \
  --unit-root "$GENERAL_UNIT_ROOT" --task-id TASK_ID \
  --execution-record /absolute/path/to/frozen-execution-record.json
```

输出为`unit/evidence/resource-supplements/<task-id>/`。已有补充层拒绝覆盖；原执行、候选和评分保持原字节。补充层随新回传包发布后，报告端会重新核对原件SHA、原生身份、全部补充文件并复算资源值。工具计数和工具参数/结果/顺序的完整性分别解释。

## 普通报告与显示配置

`report-config.json`可在`report.display_overrides.unit_model_labels`中给单元设置显示名，每项必须有`label`和`reason`。这只改变展示，不改原始模型ID、验证状态或评分。例如已人工确认的QwenWork UI选项可显示“高级”。新的QwenWork记录会直接保留经回读验证的客户端选项。

```bash
python "$GENERAL_SKILLS_ROOT/report-general-e2e/scripts/report_general_e2e.py" generate \
  --batch-root "$GENERAL_BATCH_ROOT" \
  --output-dir "$GENERAL_BATCH_ROOT/reports/REPORT_ID" \
  --target-unit TARGET_UNIT_ID \
  --node /absolute/path/to/node \
  --node-modules /absolute/path/to/node_modules
```

Excel名称带秒级时间戳。所有单元都进入对比表，`--target-unit`指定各章总结的主体。生成器同时输出`developer-source-index.json`和`developer-task-index.json`，供交付工具使用。

## 不同批次或补评范围的逐题选择

如果有效结果来自不同冻结批次，保留每条原执行/评分身份，用显式来源及逐题索引汇总，不能伪造一份完整的单源采集回执。

来源索引的`imports`按目标unit_id列出`target`包目录、`package_id`、`package_manifest_sha256`。逐题索引必须包含`source_index_sha256`和`selected_tasks`；每条写明`unit_id`、`task_id`、准确的`execution_record`和`score_file`。未评分明确设空，不得挑选高分或缩小冻结分母。每个单元必须覆盖目标batch的完整task_ids，重复或遗漏会被拒绝。

```bash
python "$GENERAL_SKILLS_ROOT/report-general-e2e/scripts/selected_report.py" \
  --workspace-root "$GENERAL_WORKSPACE" \
  --batch-root "$GENERAL_BATCH_ROOT" \
  --source-index /absolute/path/to/source-index.json \
  --task-index /absolute/path/to/selected-task-index.json \
  --target-unit TARGET_UNIT_ID
```

默认只读校验与汇总。需要发布时追加`--output-dir "$GENERAL_BATCH_ROOT/reports/REPORT_ID" --node /absolute/path/to/node --node-modules /absolute/path/to/node_modules`。可用`--display-config`传入带理由的显示设置。

历史独立资源补采可通过`--resource-root /absolute/path/to/supplement-root`导入。该目录的`supplement-manifest.json`必须绑定逐题选择SHA和所有补采原件；每个统计值会重新计算。这个兼容入口不接受仅手填的总量。

## 打包研发数据

最终评分选择完备后，根据报告目录中生成的两个索引打包。历史报告可以显式传`--source-index`和`--task-index`。只打包所选来源包和唯一采用的执行/评分，不扫描整个控制工作空间。

```bash
python "$GENERAL_SKILLS_ROOT/run-general-e2e/scripts/build_developer_bundle.py" \
  --workspace-root "$GENERAL_WORKSPACE" \
  --report-dir "$GENERAL_BATCH_ROOT/reports/REPORT_ID" \
  --output-root "$GENERAL_WORKSPACE/deliverables"
```

如果报告引用历史独立资源补充层，还需传同一个`--resource-root`。输出包括带时间戳的展开目录、ZIP、SHA-256文件和校验回执。`INDEX.html`支持按单元/用例筛选；`TASK_INDEX.json/csv`列出执行、产物、轨迹、评分与资源入口。

```bash
python /absolute/path/to/extracted-bundle/VERIFY.py
python /absolute/path/to/extracted-bundle/VERIFY.py /absolute/path/to/bundle.zip
```

原件中的本机路径仅作溯源，跨机器定位使用包内相对路径和来源映射。数据包用于研发审阅；不将原始会话、截图、候选或凭据提交Git。
## 稳定轮次目录与归档迁移

评测根目录默认为控制 Harness 会话项目的当前工作目录，显式 `--round-root` 覆盖。新执行使用稳定 Harness/execution/tasks，评分通过 prepare-score 创建同一 Harness 下独立且带完整 trace 的工作空间。框架修复不自动新建整批目录。操作步骤见[轮次目录与轨迹交接操作](轮次目录与轨迹交接操作.md)，身份、SHA和清理边界见[统一轮次工作空间与轨迹交接](../../design/general-e2e/统一轮次工作空间与轨迹交接.md)。

已完成轮次先用 archive_round.py import-final/verify/replay 迁移和独立复算，再清理旧控制目录。原评分证据与后补轨迹分别保留，禁止把补采的 rollout 标为原裁判已经读取。
