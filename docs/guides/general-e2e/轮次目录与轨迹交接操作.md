# 轮次目录与轨迹交接操作

## 根目录规则

未指定评测根目录时，使用当前控制 Harness 会话项目的工作目录；指定 `--round-root` 时使用用户给出的路径。以下命令应在控制会话项目中执行，Skill 脚本使用绝对路径。不要先切换到 Skill 安装目录。

## 接收单端执行包

将 execution ZIP 放入控制会话项目后运行；无需提前提供私有评分包：

```bash
python "$HOME/.agents/skills/run-general-e2e/scripts/run_general_e2e.py" install-unit \
  --execution-package /absolute/received/unit__execution.zip
```

将根据清单创建 AstronStudio、WorkBuddy、QwenWork 或 DoubaoWork 子目录。被评客户端只绑定 `execution/tasks/<task_id>/workspace`，并发送该题冻结的 PROMPT.md。需要其他根目录时追加 `--round-root /absolute/evaluation-root`。

若管理员已提供整个冻结批次，可一次安装批次内全部单元：

```bash
python "$HOME/.agents/skills/run-general-e2e/scripts/run_general_e2e.py" init-round \
  --batch-root /absolute/prepared-batch
```

已有目录冲突会拒绝，不重新覆盖或创建 rerun/repair 顶层工作区。

## 执行结束后交接评分

collect 已正式收口后，将 scoring ZIP 和报告/裁判配置交给控制 Harness：

```bash
python "$HOME/.agents/skills/run-general-e2e/scripts/run_general_e2e.py" prepare-score \
  --harness AstronStudio --orchestration-id score-001 \
  --scoring-package /absolute/received/unit__scoring.zip \
  --report-config /absolute/received/report-config.json
```

只准备工作空间与编排状态，不替裁判评分。随后按返回 orchestration_root 使用 orchestrate-general-e2e 的推荐动作调度、等待和 verify-score。

在 `AstronStudio/score/tasks/<task_id>/current/` 可查看该题候选、私有评分材料、标准 transcript 和 trace/raw 原件。trace 包的复制与 SHA 校验由评分准备入口完成，不能只复制产物或仅留下指向旧执行目录的绝对路径。

单题重试和重评分使用新的 attempt/编排 ID，保留旧记录和选择；不因框架修复重新准备整批题目。默认三槽评分，客户端执行槽位仍按该客户端已验证配置。

## 整理已完成轮次

先输出到一个新的暂存目录，禁止直接覆盖原控制项目：

```bash
python "$HOME/.agents/skills/run-general-e2e/scripts/archive_round.py" import-final \
  --archive /absolute/final-bundle.zip \
  --batch-root /absolute/original-batch \
  --output-root /absolute/new-staging-directory

python "$HOME/.agents/skills/run-general-e2e/scripts/archive_round.py" verify \
  --round-root /absolute/new-staging-directory

python "$HOME/.agents/skills/run-general-e2e/scripts/archive_round.py" replay \
  --round-root /absolute/new-staging-directory \
  --report-skill "$HOME/.agents/skills/report-general-e2e" \
  --node /absolute/node
```

verify/replay 的 round-root 同样可省略，默认当前会话项目目录。迁移后的 execution 是最终候选归档，score 保留当时裁判采用的原件；后补轨迹放 supplemental，不改写历史分数。

研发归档不保留可重建的 runtime/，但候选、私有材料和正式证据中已被哈希锁定的文件必须完整保留，包括其中的 __pycache__ 与 .pyc。单题归档评分校验使用 `score_general_e2e.py verify-score --attempt-root ABS --archived`：校验候选、轨迹、评分与审计 SHA，跳过临时运行目录的存在性；审核证据按当前规则复核全部字段，保留原回执中由 manifest 锁定的历史策略标识。正常评分仍检查当前策略版本。归档不会被当成正在运行的评分任务。

确认执行/评分身份、所有原件 SHA、240条或本批次实际数量的分数/资源复算一致后，才发布稳定目录并按明确清单清理旧副本。保留必需审计和冻结输入，更新根 README、当前 Skill 链接；不要直接 `rm -rf` 整个历史根。
