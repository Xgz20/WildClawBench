# 通用场景自建评测集说明

本文统一维护三套自建通用场景评测集的名称、定位、用途、版本和仓库位置。三套集合共用 General E2E 的准备、执行、采集、评分编排、独立评分、回传和报告体系，分别选题、建批、冻结和报告。

核对日期：2026-11-20（Asia/Shanghai）。下文路径均相对所述 checkout 的仓库根目录。

## 集合名称、定位与用途

| 正式名称 | 简称 | 定位 | 主要作用与选题依据 |
| --- | --- | --- | --- |
| 通用场景基础回归评测集 | 基础回归集（基础题） | 固定基础能力样本 | AStudio 版本、模型或 Harness 迭代后检查已有能力是否退化；保留固定样本作为历史对照。 |
| 通用场景真实工作评测集 | 真实工作集（拔高题） | 常规工作效果评价 | 按真实任务类型、频率、规模和复杂度维护工作样本，衡量模型与 Harness 组合相对竞品的实际效果。当前由产品团队维护，线上代表性应结合来源和抽样记录判断。 |
| 通用场景挑战评测集 | 通用挑战集（竞赛题） | 复杂机制与能力边界 | 汇集复杂真实任务、典型缺陷复现场景及业界代表性挑战题，检查复杂约束、多工具协作和可靠交付能力，验证同类问题在迭代后是否改善。 |

挑战集系列 ID 为 `general-challenge`。题号采用 `<编号分类>_task_<三位序号>_<slug>`，例如 `01_Office_Documents_task_001_policy_crosswalk`。标签包含 `custom`、`general-challenge`，首批题保留历史检索标签 `general-hard`。具体题目范围由冻结版本确定。

挑战集后续可吸纳鹈鹕测试、业界标杆测试及典型挑战题，新增时登记原始出处、版本、改编说明和评分依据。这里记录的是扩展方向，不表示首批60题已收录上述题目。

三套按评测用途划分，具体难度和区分度通过实测校准。当前不能据“基础／拔高／竞赛”称谓推定每题或整套难度严格递增；样本构成、评分权重与能力映射也应分别说明。

## 版本与当前可用状态

| 所属集合 | 冻结版本ID | 题量与范围 | 当前用途与状态 |
| --- | --- | --- | --- |
| 基础回归集 | `general-custom60-v1` | 60题，原六类各10题 | 基础回归冻结版本，通过 `general-regression` 或历史版本 ID 选择。 |
| 真实工作集 | `general-custom70-v5`、`general-custom70-v6` | 70题：检索20、办公30、数据分析001—020 | 已登记的后续冻结版。系列默认选择 v6，可指定本轮采用的冻结版本。 |
| 真实工作集 | `general-custom70-v2`、`general-custom70-v3`、`general-custom70-v4` | 同一70题范围，各版锁定不同题源／参考修订 | 历史冻结版；通过各自快照、覆盖范围和manifest重现。 |
| 真实工作集 | `general-custom116-v1` | 116题：检索20、办公30、数据分析66 | 历史冻结版本；通过原始快照及绑定的素材规则重现，不能直接把当前修订题源作为旧版原件。 |
| 通用挑战集 | `general-challenge-v3` | 首批60题、7类，含6道必须理解视觉信息的题目 | 当前唯一登记版本，采用编号目录。12题实测校准待开展。 |

这是三套业务集合。真实工作集的70题各修订版与116题历史版属于同一集合，评测时明确选用其中一个冻结版本。Info004单题参考版本另有独立ID，不因注册而并入整套选题。

已登记的基础回归和真实工作历史版本由原始 ID、manifest 和摘要定位。目录迁移后，可通过仓库内登记的迁移前 Git 源码重建，也可使用已保存的原始 dataset bundle。浅克隆如缺少所需提交，需要先获取其历史。挑战集的两个开发快照 `general-hard-v1` 和 `general-challenge-v2` 已退出当前目录和版本注册，可通过 Git 历史查阅。

### 构建制品与评测产物

数据集包的默认构建位置为 `report-workspace/general-e2e/datasets/<dataset-id>/<dataset-id>.dataset.zip`。其中包含私有GT，用于管理员准备隔离执行包和评分包；被测端只接收执行包。ZIP及校验摘要作为构建制品维护，源码库保留定义、任务、素材和manifest。

Skill发行位于 `report-workspace/general-e2e/releases/<release-id>/`。实际批次工作目录、执行证据、评分回传和报告位置由本轮配置指定，通过批次及回执中的 dataset ID、digest、任务范围和Skill身份追溯，不能仅按目录名判断所属集合。

CLI显式选题时，冻结 Workspace 缓存位于 `<OUTPUT_DIR>/.dataset-sources/<backend>/layout-v1/<dataset-id>/<digest>/<task_id>/`；实际输出根按配置确定。缓存从已验证的冻结材料生成，按原字节与声明路径复验，归档题面与GT不会混用当前源目录中的不同版本。该缓存保留输入与私有评分材料，候选只接收对应的执行输入。

## CLI 选题

| 现有用法 | 调整后的行为 |
| --- | --- |
| `--task tasks/extension/<分类>/<ID>.md` | 通过登记的路径映射读取新目录中的同一任务。也可直接传新路径或任务 ID。 |
| `--category 01_Productivity_Flow` 或 `--category all` | 延续原生题和原扩展题的分类范围。自建 Web 仍由旧分类选取，ArtifactsBench 沿用 Web E2E 的专项评分入口。归档题退出默认选题。 |
| `--category general/work/data-analysis` 或 `--category ppt/custom` | 根据新目录显式选取分类或题池。分类模式继续支持原有模态筛选和标签的并集、排除规则。 |
| `--dataset general-custom60-v1` 或 `--dataset general-custom70-v6` | 按旧清单选足60题或70题，并同时装配该版本的执行输入和私有 GT。 |
| `--category general/challenge/01_Office_Documents` 或 `--task 01_Office_Documents_task_001_policy_crosswalk` | 选择当前挑战分类或单题。旧分类路径、旧题面路径和旧题号可解析为当前题源。 |
| `--dataset-id general-regression`、`--dataset-id general-work --release-id general-custom70-v6` 或 `--dataset-id general-challenge` | 通过系列选择冻结版本。也可用 `--dataset-id general-challenge-v3` 显式选择挑战集当前版本。 |

固定版本的范围由 manifest 决定。需要按标签选子集时使用分类模式。中文译本可供阅读，默认选题排除译本。

## 选用与维护规则

1. **先选用途，再选冻结版本。** 能力退化回归选基础集，常规工作效果和竞品对比选真实工作集，复杂机制与同类问题改善选挑战集。正式评测按manifest选题，批次与单元的task_ids遵循该清单顺序；标签用于检索，不能代替冻结清单。
2. **三套分别建批和报告。** 真实工作集五维与基础／挑战七维分别统计覆盖率，不做直接折算；比较总分时说明题目范围、模型、Harness、配置和有效结果口径。
3. **保持冻结身份。** 新增题目、修改题意或评分契约、修复素材时，发布新的冻结版本，保留旧manifest、原始素材、评分和报告。题目 ID 跨系列唯一。同一任务通常跨版本沿用 ID。挑战集 v3 的编号迁移关系登记在 `datasets/layout.json`。
4. **记录选题依据。** 基础集保留回归目的；真实工作集保留任务类型、频率、规模、复杂度及抽样依据；挑战集保留来源、复杂机制、badcase／失败点和评分依据。模型复核、人工专家复核、静态校验与实际运行验证分别记录。
5. **发布前核验范围和依赖。** 检查题号唯一、清单与素材摘要、输入／GT隔离、评分契约和对应客户端／评分环境依赖。静态通过不代替真实Harness、语义裁判或难度与稳定性校准；评测基础设施异常与候选能力失分分开记录。
6. **同步维护本说明。** 系列名称、用途、版本、题量、根目录或集成状态变化时更新本文；详细题目设计、执行操作和构建步骤在各自文档维护，通过下列入口关联。
