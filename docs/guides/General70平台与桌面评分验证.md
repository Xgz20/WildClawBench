# General70 平台与桌面评分验证

平台和桌面对照必须读取相同执行回执、候选字节、原始轨迹、数据集摘要和 Rubric；分别建立独立评分 attempt，不把另一侧的评分响应提供给裁判。自动规则、语义判断、聚合和验分分别核对，不能仅凭总分相同宣称准确。

十题覆盖应包含三类任务、L1–L4、五项能力映射、混合评分和零权重取证的纯语义评分，并至少包含一项真实文档视觉检查。能力映射覆盖不代表所有项均已取得可判定证据，报告仍披露未知及有效样本数。

## 运行条件

- General70 的非线性聚合要求 Score CLI 本身使用冻结受管 Python 3.11；仅给规则 Worker 指定正确解释器不够。新桌面编排可显式传 `pipeline init-orchestration --score-python`，已有编排解释器不可替换。
- 无头评分直接复用随批次封存的编排器提示和路由，包括规则复核、零权重取证、聚合预检与 HTML 环境预检。原生 Office 规则需真实 LibreOffice Writer/Calc/Impress 和字体；镜像单独建新标签并核验真实读写、保存及渲染。
- 修复历史批次的评分 Skill 时，在新评分配置中显式指定 `score_skill_dir` 和完整 `score_skill_inventory_sha256`。只替换新评分作业内未使用的副本，保留原批次 Skill、旧失败和原 Prompt。平台使用受保护配置 `WCB_E2E_SCORING_SKILL_DIR`；路径和包摘要进入内部冻结配置，不暴露为产品输入项。
- macOS 上复制的冻结 Office 文件在关闭写描述符前设置 user-immutable，防止宿主元数据软件替换文件。已漂移原件不改写；从已校验的备份生成新的恢复目录。已开始同题 Judge 时禁止切换恢复源。

## 故障与对照口径

新客户端的 64 字节 MCP 工具缩写只按原五段身份 SHA1 精确重放，仍核对原参数及完整调用配对；未知缩写拒绝。v6 的已审核取证模式另有精确目录，旧目录不改。

框架问题影响实际作答时只重执行受影响题；仅采集或评分问题则保留同一执行、修复受影响阶段。失联沙箱无法收回证据时，不能补造成功回执、按模型零分或静默删除原会话。

交付应包含逐题规则分、语义分、总分与检查点差异、有效/异常/未知状态、平均绝对差及最大差；同时说明模型服务、CLI/桌面版本、Office 版本和证据覆盖差异。Skill 回传与报告另按正式 package-return、import-return、报告入口核验，保留原始失败及明确的最终尝试选择。
