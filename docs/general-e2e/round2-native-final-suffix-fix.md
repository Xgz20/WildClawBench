# 原生终稿后缀残缺的证据交接

本轮只读归档发现：同一完成回合、同一最终消息ID的原生回复投影为SDK终稿的严格后缀，缺少开头988个字符。原短回复与SDK全文均是原件。该事实不证明客户端实际屏幕显示了哪些内容，也不证明答案正确。

资源组件1.3.16新增`bound-native-final-suffix-divergence/v1`，独立于原前缀Profile。它重验一次发送、完整Prompt、session/turn/cwd、唯一SDK结束事件及同ID的最终助手消息、原生完成消息和原短回复SHA；只允许严格非空后缀，任意中间片段、异文、错消息、活动回合和额外发送均拒绝。原短回复不替换，完整SDK继续作为预选规范轨迹，索引保留partial及明确缺失原因。

评分仍须显式逐题授权，绑定原执行、原契约、索引、差异证明和SDK全文SHA，并由独立裁判按原Rubric区分内容证据与实际展示/交付。Run0.7.30透传授权，Orchestrate0.11.88要求授权集合恰等于差异题集合；普通完成题不接收该准入。Score0.10.110、Collect0.12.18及Report0.8.62独立发行，沿用已验证的Python运行时锁。候选、Rubric、权重、旧发行和失败归档不改，不重跑Harness。

验证覆盖原前缀回放、后缀正例与异文/身份/额外发送反例，完整archive→resource→finalize→verify-only链路、SDK授权SHA漂移拒绝、完整范围仅向差异题传权、普通编排和外置评分模式。源码Collector补齐其已声明资源组件的两个未落盘入口，内容与canonical源一致；独立ZIP仍由构建器按组件清单分发完整依赖，不修改生产运行依赖版本。
