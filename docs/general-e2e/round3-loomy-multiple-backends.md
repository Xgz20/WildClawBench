# round3 Loomy 多后台归属修复

round3 首题在公开 UI 完成目录选择及 Prompt 回读后、发送意图之前，以
`LOOMY_RUNTIME_PROCESS_AMBIGUOUS` 停止。原 journal 的发送数为 0，未生成原生
session，全部旧状态及 UI 准备原件保留。

本机 Loomy 0.9.39 在同一时点启动三个随包 OpenCode 1.14.22 服务，均由精确
GUI 主进程持有，均打开相同数据库。主进程的已建立 TCP 连接只指向其中一个
loopback 监听端口，因此单纯按子进程个数拒绝会阻断真实冷启动。

共享组件 0.1.13 逐个核对所有候选的父进程、启动时间、随包二进制 SHA、数据库
持有关系、唯一 loopback 监听及 health。多候选时仅接受主进程已建立连接的唯一
候选；任何无连接、多连接或重复端口均拒绝。未选后台必须在默认实例和全部原生
已登记目录返回空闲；选择前后再次核对同一连接归属。进程集合随原生 runtime
绑定归档，后台变化继续走已有精确重新绑定和终态门禁。

执行发布为 0.15.18，采集发布为 0.12.26。关键 UI 与 Swift 源码逐字不变。
生产接续必须使用新冻结发行及显式 source-repair manifest，保存原队列、配置、
manifest、状态、journal、组件 SHA 和零发送任务范围。仅对原零发送题使用既有
显式恢复参数，旧发送计数不改，不重启或结束任何客户端/后台，不更改权限、题面、
候选、Rubric、权重及 70 题范围。

回归包含主进程单连接选择、多连接、无连接、非 loopback 连接、重复候选拒绝，
并沿用全部原 Loomy 绑定、终态、资源、队列和修复闭包测试。本机只读实测确认
主进程连接端口与选中服务一致，另两个服务在全部已登记目录空闲。
