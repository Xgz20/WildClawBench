# AStudio 三并发取证与归档

## 框架行为

- 保持后台并发三和 UI 派发单槽。同一观察轮用一份校验过的 SQLite 副本完成原生状态探针、已绑定会话观察与按消息 ID 提取终稿。发送前仍从独立新鲜观测验证原生活动、焦点和模型。
- 每次 Worker 启动独立监听器跟踪原生日志旋转。队列 `native-logs/<运行ID>/index.json` 记录保留片段、inode、字节范围、SHA-256 和淘汰情况。原始字节在本机私有目录留证。取证时按索引筛选脱敏后再对外共享。
- Collect 的在线轨迹归档入口验证单元执行阶段已关闭、无 owner 锁，且 AStudio 原生全局空闲。通过后在框架日记写入 `archive.native-idle-verified`。原生故障时可以马上保存轻量证据，轨迹大库归档等候空闲。
- 相同零发送预备阻塞或等待处理的任务再次普通恢复时返回退出码 5。按既有的精确零发送恢复或原回合观察入口核验状态变化后恢复。

## 真机抽样顺序

使用独立执行批次，固定同一版本 AStudio、Spark-X2.6、High 和并发三。首选 Data012、Data013、Data014。三题均在两轮执行异常名单中，且在 Round2 同一波 shutdown 中同时在途。核验以 SDK 原生起止区间为准。另两道重合题为 Data007 和 Office013，适合后续验证工具桥故障与启动门禁。

## AStudio 研发

- 在 shutdown 入口记录来源、触发原因、请求 ID、后端代次和 PID。覆盖桌面 IPC、服务作用域释放、看门狗及其前置探测。
- 看门狗区分已证实父进程消失与查询失败。记录 `ps` 状态、耗时、重新核验结果、信号意图和结果。已验证 3.6.4.127 的现有代码在模拟父进程 `ps` 超时时会进入 TERM 和 KILL 路径。
- 记录 SQLite 写事务等待、执行和提交耗时，以及 WAL checkpoint、`BUSY/LOCKED` 和 I/O 错误。关联后端代次及回合 ID。

## 宿主机和 IT

- 通过已批准的 Endpoint Security 信号和退出采集记录发送者、目标、信号及丢失序列。在独立测试子进程上验证链路，采集端需要相应的管理员和隐私授权。
- 保留同窗 macOS I/O、内存压力、系统诊断和 ManageEngine 应用控制记录。以进程身份与 UTC 时序对齐，保留证据缺口。
