# 采购对账混合金额汇总抽取修复

正式70题round1的AStudio Office015原冻结评分在受管Worker中抛出原规则的`EvaluationError`，未创建裁判、未产生规则组件或有效分。原错误、Worker、输入和SHA保留；被测执行无需重跑。

原汇总表用“类别／笔数／金额差额或金额合计／核对口径”并列陈述计数与金额。旧抽取器只读取四类异常的笔数，并把“两类未匹配金额合计”整行留作未知。新`procurement-date-and-section-extraction/v4`严格要求唯一计数列、唯一混合金额列和明确口径说明：差额按候选差额列汇总，未入库按候选订单金额汇总，无对应订单入库按候选入库金额汇总，显式加法按两侧金额相加。合计笔数独立核验。

修复保留原单元格、隐藏状态、来源位置、数值、容差、计分分母算法及80/20权重；不将未决口径、净额或未知列猜成合计。上游候选明细不完整时，金额依据继续为null，不从参考答案补齐。历史v3及更早Profile保存原附加源码，并复现原SHA；冻结数据集和非规则题面不变。

原件只读对比确认四项原计数的业务字段保持，新增六项取证分别绑定汇总B8、C4—C8。该对比只验证抽取，不发布能力分。新Score0.10.77／Orchestrate0.11.60／Core0.2.6须另行构建、校验、安装，以相同冻结执行建立独立评分attempt，通过独立裁判和verify-score后显式合入完整70题选择。旧attempt不覆盖，不按高分择优。
