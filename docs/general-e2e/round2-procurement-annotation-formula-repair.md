# 采购说明公式错误的原样取证

Office015原Worker在已完整导出四份材料后因未识别数量合计及10个未解析公式退出。原工作簿把以等号开头的描述写为Excel公式，位置在明确的“核对说明”列；相邻业务数值为字面量。独立LibreOffice Calc只读API观察确认这些原单元格实际返回错误码，打开前后候选SHA不变，未保存或修正公式。

Score0.10.115新增精确v6契约/源码及既有有效源码SHA绑定的Profile。每次正式取证使用锁定的评分Python、原生Office/JDK/UNO和新Helper，在独立Profile及只读副本中重算指定单元格，宏和链接更新禁用。只在明确说明列、相邻数值为字面量且原生确认错误时，将原公式文本、数据类型、原生错误码/显示和完整来源保留在`overview.json`；不补计算结果，不授公式正确性或候选验收分。其它未知公式和原生环境失败仍是提取阻断，不能计候选零分。

对于明确指向数量差异表数量差额之和的原数量合计，使用同一提交记录的完整ID集合和原数值取值函数计算预期；缺明细保持未知。原规则的汇总比较、重大错误、分母公式、80/20权重和语义Rubric不改。原始行保留，投影仅供原比较函数消费；公式质量及是否实际验收仍由独立裁判按原C6/C7等检查点评价，评分端观察不冒充候选行为。

旧Manifest没有新marker时按原源码回放，旧失败Worker、四份部分取证和审计保留。使用现有声明EvaluationError收口协议留为未评分，再从同一原执行建立新的独立评分，不重跑Harness、不导入控制器判定或覆盖旧分。

新原生Helper先用合成的正确与错误单元格自测，锁定Java源码、Helper、既有Office配置、JDK/JAR及解释器。实际观察保留原生命令、原始日志、单元格回执、输入SHA及精确自有进程收尾；不按cwd清理共享应用或后端。旧Writer运行时与其已用源码保持不变。
