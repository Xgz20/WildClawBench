# AStudio 环境标题折叠卡片回读失败

## 故障与根因

服务器批次 9：`platform-e2e-3a8551e4333143d986c3d68b189a65da`，用例 `01_Productivity_Flow_task_001_expense_policy_check`，执行尝试 `exec-5960ecf6452c4899806ad92b0231cfd1`。

实际框架发行为 `244218b803bf1ba7ab23a2c0f11e94374ba39f42`，与排查时服务器最新发行相同。目录别名和 Python 验证均通过。日志显示在 `set_prompt` 两次回读失败，没有进入 `send_task`，未产生业务执行轨迹。

失败前截图显示两张标题为 `[执行环境]` 的粘贴文本卡片：906 字输入已经粘贴，但 AStudio 将正文折叠，Edit 的回读是占位提示。实际沙箱的 `_prompt_accepted` 会接受至少 12 个字符的可见前缀，6 个字符的环境标题不满足条件，重试又追加了一张相同卡片。

这是前一轮路径适配新增的短标题与 AStudio 折叠输入回读规则不兼容。此前路径检查未覆盖真实粘贴回读，本轮补齐这条验证链。

另外，模板 `winarena-pc-20261125-a` 预装 AStudio 3.7.1，但批次运行配置显式固定为 3.6.3；原始回执确认安装后为 3.6.3，产品版本 3.6.3.159，登录源为模板。这个版本固定配置未在本轮更改。修复在相同 3.6.3 环境验证通过。

## 修复边界

- 只处理 AStudio 中由框架生成、声明 `workspace-paths/v1`、首行为 `[执行环境]` 的输入。将实际发送标题改为内容 SHA256 前 32 位加环境标签，让原生卡片标题可读且与输入绑定；正文、插件引用和基准 Prompt 文件不变。
- 实际输入和 `prompt_transport` 版本进入现有不可变 Prompt 锁、原生轨迹绑定及导出回执。保持原生回读检查，不跳过验证、不降低最短前缀门槛。
- 旧锁定/已派发尝试保留原字节；新尝试生成兼容标题。新尝试丢失锁文件时停止，不回退到基准输入。插件配置变更、原文或锁漂移仍被拒绝。
- General 评分交接同时保留基准与实际输入，`sent_sha256` 与实际执行记录一致；同步修正公开 AGENTS.md 上下文位置。General/Web 导出保留 Prompt 锁和传输版本，避免后续 `MAPPED_PROMPT_DRIFT`。
- 普通 Prompt、WorkBuddy、ChatGPT Desktop 与 CLI 不应用此标题适配。
