## 结论

当前故障已经恢复：之前失败的 031、033、035 三个独立会话均通过公开 CUA API 实际创建自己的 iab about:blank，并核验 metadata.codexSessionId；原 task_score.json SHA 保持不变。这是浏览器运行时健康证据，不能替代三槽五题评分及生产准入。

直接失效机制定位在 Browser 发现/通信层：正确会话的原生 Browser 后端存在，也能返回 getInfo，但失败期间多次在 CUA 已返回空清单或“不可用”之后才处理对应会话的请求。Browser Service 的后端信息等待上限为 5000 毫秒；未在此窗口取得后端信息就不进入可用 Browser 清单，上层因此报 Browser is not available: iab。

此前将 No ChatGPT browser route 和 unsupported placement format version 2 并列为主要原因的判断需要收窄：正确后端的路由和信息答复实际存在；无路由日志大量来自发现器扫描其他会话时的正常身份拒绝。版本格式错误属于同时存在的会话读取故障，没有证据证明它直接导致本次 Browser 发现失败。

## 源码调用链与边界

`cua.getState()` 的发现器 `bL` 枚举本机管道，并通过 `Ite/kte` 请求后端信息。等待包装 `Y_` 的默认 `_te` 是5000毫秒。失败候选被排除；`Cte` 还要求 session 型后端的 metadata.codexSessionId 和 buildFlavor 匹配当前会话。空清单随后表现为 iab 不可用。

Native Pipe 经受信任 Node REPL 的 `createNativePipeBridge` 中转 connect/write/data。桌面 `BrowserSessionRegistry.canServeSession/ensureSessionRoute` 检查确切会话与存活窗口，`zDe.getInfo` 返回本会话 metadata。每个后端拒绝其他会话的 getInfo 是正常隔离；扫描目录时会出现大量无路由日志，即使其中一个正确后端成功。

读取的已发布 JavaScript 保存在调试目录；extraction-provenance.json 记录来源、文件长度和 SHA。这解释当前安装版本，不代表开源 Codex checkout 的任意版本。

只读环境检查排除了当时进程禁用 iab、限定错误管道路径及 buildFlavor 不一致：成功对照与失败 CUA 进程均为 prod，允许 chrome/iab/mcpapps，未设置 BROWSER_USE_BACKEND_PATHS 或禁用能力。

全局 legacy node_repl 配置指向插件缓存，但实际 CUA 进程使用 @oai/browser-desktop/service。两个服务文件确有不同 SHA，当前证据不支持把 legacy 配置当作此次 CUA 故障来源。后续检查只保存非敏感配置字段，不复制认证信息。

另一次私有管道 getInfo 直连诊断未取得合法响应，已停止；它不构成 Browser 健康或评分证据，未通过它操作网页或绕过身份隔离。
