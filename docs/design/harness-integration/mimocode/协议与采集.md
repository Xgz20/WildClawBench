# 协议与采集

## 配置与模型

源码事实：`packages/opencode/src/config/provider.ts:85` 允许 npm SDK、baseURL、apiKey 与自定义 models。`provider.ts:237` 打包三类 SDK；`provider.ts:320` 为 OpenAI provider 注册 Responses model loader；`provider.ts:1790` 的 `getLanguage` 选择 loader 或 `sdk.languageModel`。适配器按显式 API 选择 provider，不以请求失败作为协议回退依据。

配置生成在容器独立 `MIMOCODE_HOME/config`，执行 workspace 不含认证配置。被评测模型与裁判的凭据注入分开。只启用指定 provider，禁止自动分享与升级；不通过上游源码补丁改变工具行为。

源码限制：`provider.ts:1136` 的 `isMimoOrSmartModel` 存在 MiMo 系模型强制 Chat 的特殊路由。不能因 Harness 三类 SDK 均存在，就承诺任意 MiMo 模型均支持 Responses。

## 事件与终态

源码事实：`cli/cmd/run.ts:440` 的 `emit` 产生 JSON 行；`run.ts:480` 只转发当前 session 的已完成工具、step、文本等事件；推理输出受 `--thinking` 控制。它并无原生 `mimocode.completed`。

因此原生 stdout 保持原样；runner 将进程退出码和最后 `step_finish.reason`、native error 合并为独立终态描述，写入 manifest。0 退出码不单独证明任务完成。124 记超时，137 保留 force-killed 错误而不猜测 OOM/超时原因。超时允许最后一行被截断，但中间损坏、混会话、同 part ID 内容冲突失败关闭。

数据库通过 SQLite backup API 归档，包含 WAL 中已经提交的记录；不使用仅拷贝 `.db` 主文件的方式。主会话评分 JSONL 是投影，数据库才保留其他会话及更多原生元数据；二者都不是 HTTP wire recorder。

## Token 口径

`session/session.ts:384` 的 `getUsage` 先从 SDK input 中减掉 cache read/write，再从 output 中减 reasoning。转换回 WildClawBench 时，input 保持未缓存部分，output 恢复 `native output + reasoning`，reasoning 另外作为子集记录。

总量为 `uncached input + cache read + cache write + inclusive output`；provider total 直接读取 `tokens.total`，缺失为 null。按 part ID 去重，避免重复 `step_finish` 增加请求数。

当前 usage 按数据库 session.parent_id 追踪主会话及其后代，只汇总唯一 step-finish part，不再叠加 message.tokens，以免重复计费。自动 checkpoint-writer 纳入统计；主会话 stdout 单独用于评分投影，不把子会话最终回答冒充为用户答案。

会话树外辅助调用和未持久化请求仍不在统计内；manifest/usage 明确声明范围。失败/超时、未闭合步骤和 pending 工具标记 partial usage。费用留给报告定价层。
