# E2E 客户端能力配置与管理员可视化评估

更新日期为 2026-11-24。本评估依据 astudio-eval-framework 的能力发布、执行预检、
桌面评分，以及 astudio-eval-platform 的模板管理和评分入口。

## 结论与本轮改动

平台适合提供客户端启停、模板版本选择、模型及推理档位启停、执行和评分默认值的管理界面。
能力来源应随客户端适配代码和沙箱模板发布，并保留模型菜单的运行时观测。
管理员负责选择对用户开放的范围，框架负责执行协议与真实运行结果的验证。

本轮将 ChatGPT 加入框架默认能力列表。默认快照包含 AStudio、WorkBuddy 和 ChatGPT，
ChatGPT 绑定已登记的 Pro v5 模板及其 WindowsAgentArena 修订、客户端版本、10 个模型、
Low/High、通用和 Web 执行与评分、完全访问权限及订阅评分方式。直接新建的 ChatGPT
计划省略模板时，采用该独立默认模板。显式保存的模板和权限保留其输入值。

管理员界面和模板能力快照已按下文第一期方案实施。外部能力文件继续沿用 v1 全量替换
行为，旧文件及已有批次保持原有语义。可视化策略独立保存在平台数据库。

## 实施前的配置成本

| 现有入口 | 已有功能 | 当前缺口 |
|---|---|---|
| 框架 `describe/profiles` | 发布驱动、模板、模型、推理档、执行与评分场景 | 候选快照更新依赖代码或完整 JSON 发布 |
| `WCB_E2E_CAPABILITIES_FILE` | 选择独立能力文件，允许指定模板和版本 | 整体替换 `profiles`，遗漏一个客户端会使其从发布结果消失 |
| 平台“镜像与模板” | 登记模板、Namespace、镜像摘要和 WAA 修订，启停模板，设置执行/评分默认模板 | 缺少客户端级总开关、模型和推理档控制、每个模板的独立能力快照 |
| 执行预检 | 验证 profile、模型候选、推理档、场景和模板绑定 | 主要读取客户端级 profile，多版本并存时需更准确地选择模板对应的 profile |
| 桌面评分 | 校验评分模板、模型、权限、鉴权和控制器修订 | ChatGPT 精确匹配模板，AStudio 仍存在沿用客户端首个 profile 的兼容路径 |

实施前的平台 `available_profiles()` 按 Harness 保留第一条 profile。`effective_description()`
可用管理员选择的模板名替换该 profile 的模板名，模型及推理档仍沿用原 profile。
后续支持同一客户端的多个版本时，需要按模板绑定定位其能力快照，避免把新版本模型集合
带到旧模板。仅扩展 JSON 合并规则无法解决这个版本对应问题。

当前模板的停用与客户端总停用也有差异。删除模板默认值会恢复执行器默认模板，
因此客户端总开关需要明确的发布策略字段，不能通过清除默认模板间接实现。

上述缺口在本次平台实施中通过模板独立快照、客户端策略表和发布时校验处理。
以下分工和版本绑定原则用于本次实现及后续能力发现扩展。

## 能力如何分工

| 信息 | 合适的维护来源 | 管理员可做的操作 |
|---|---|---|
| 客户端驱动、执行请求、任务完成识别、轨迹采集、清理与恢复 | 适配代码和框架发行 | 查看适配版本及状态，启停已适配客户端 |
| 沙箱模板、镜像摘要、控制器修订、客户端版本 | 镜像构建和模板注册时生成的能力清单 | 导入或登记版本，启停模板，选择默认版本 |
| 模型 ID、显示名、每个模型的推理档位 | 对应版本控制层的候选清单，加上客户端菜单的运行时观测 | 选择开放模型和推理档，选择默认值，提交新候选验证 |
| General/Web 执行、评分方式和场景 | 已适配代码与模板验收记录 | 分别开启执行和评分，限制开放场景 |
| 网关地址、凭据和订阅登录方式 | 服务器密钥配置及模板对应的认证方式 | 查看就绪状态，选择已支持的认证方式 |
| 并发、超时、资源上限 | 执行器支持范围与运维容量 | 设置部署或租户范围内的上限 |

客户端具备某模型名称的输入能力，并不能单独证明当前账号或菜单已经提供该模型。
模型列表既可能随客户端版本变化，也可能由在线服务或登录账号决定。能力快照应同时记录
来源、观测时间和验证状态，产品页面可展示“已验证”“待验证”“当前不可用”。
新增输入方式、推理档语义、认证方式或证据采集流程时，需要更新驱动实现。

平台已有“模型管理”维护的模型服务连接用于 API 调用及 CLI 裁判。桌面客户端内部菜单的
模型与推理档应在所属客户端及模板下展示，并关联其能力来源。两种目录的 ID、权限和
凭据生命周期各自维护，界面可以共享候选筛选组件。

## 推荐的数据绑定

为每个模板版本保存一份能力快照，记录以下信息。

- 客户端 Harness、客户端版本、执行器适配版本和公开协议版本。
- 模板名称、Namespace、镜像 digest 和 WindowsAgentArena 完整修订。
- 模型列表，以及每个模型自己的推理档集合与已验证范围。
- 执行场景、评分场景、权限要求、支持的认证方式。
- 清单来源、生成时间、摘要，以及必要的实机验收记录引用。

模板记录引用能力快照版本。默认执行模板与默认评分模板分别选择，各自使用所绑定快照。
同一个 Harness 允许保留多套模板能力，变更默认值后新批次选择新版本。

每次新建批次与评分操作，保存实际生效的能力摘要、策略版本、选定模板、模型、推理档和
认证方式。历史恢复按已冻结的配置和发行路径执行。管理员的停用策略可以阻止新任务，
运行中任务的取消通过现有取消流程单独管理。

管理员选择的集合应受驱动、模板及实际运行能力约束。生效结果由以下范围共同决定。

```text
执行器已适配范围
  ∩ 该模板版本声明的能力
  ∩ 管理员开放的客户端、模型、推理档和场景
  ∩ 本次账号及客户端运行时可用范围
```

当运行时探测尚未完成时保留“待验证”，正式发题前由预检及菜单/原生轨迹回读确认。
探测不能仅凭健康端点通过就标记全部模型就绪。

## 可视化管理建议

优先扩展现有“镜像与模板”页面，增加以下内容。

1. 客户端列表显示已适配的 AStudio、WorkBuddy、ChatGPT，分别提供执行和评分开关。
2. 模板详情显示客户端版本、镜像和控制器修订、能力来源、验证时间及差异。
3. 模型配置从模板快照加载候选，每个模型分别提供启停、默认值和允许的推理档。
4. 执行和评分分别选择默认模板，选择后立即回读该模板的模型与场景。
5. 发布前展示变更影响，检查默认模型仍在开放集合内，并保存操作者和策略版本。

模型和推理档可以随产品菜单变化，因此页面可提供“重新发现能力”和“提交候选验证”。
运行时观察到的新模型先作为候选，验证成功后管理员可发布。对于 AStudio、WorkBuddy
当前支持透传并严格回读未列出模型的行为，可以保留为明确的候选验证流程。
ChatGPT 当前严格使用已发布模型集合，新增候选应遵循对应控制器的模型选择实现。
管理员限制某模板的模型范围时，后端也要据此约束当前的未列出模型透传路径，
使表单候选、预检和任务启动采用一致的允许集合。

现有管理员权限可以用于全局客户端和模板发布。租户有差异化需求时，再在全局允许范围内
增加租户级选择，避免首期引入多套相互覆盖的授权来源。

## 外部文件的改进方向

常规操作由可视化策略覆盖完成后，外部文件可保留给离线部署、自动导入和环境定制。

后续新版格式可以显式支持按 profile ID 的增量更新，并提供明确的停用表达。
更新应定位到具体模板版本。同一 profile 中的模型数组采用明确的替换规则，
避免递归合并产生重复模型或把旧版本参数混入新版本。

已有 v1 文件继续执行全量替换。新增合并模式应有显式版本或模式标记，发布前校验
重复 ID、未知 Harness、默认模型缺失、无可用推理档和模板版本不匹配。
启停开关及模型列表不能引入执行器尚未适配的客户端或请求字段。

## 实施顺序与验收

以下为设计时的实施顺序，第一至第三步已完成。第四步的运行时能力发现继续按需扩展。

第一步已在本轮完成，默认发布 ChatGPT，并保留其独立模板版本与原有外部文件语义。

第二步建议补齐每个模板的能力快照引用及按模板查找能力的路径，覆盖执行预检、评分、
模板切换和历史恢复。该步骤应先于允许管理员编辑多版本模型列表。

第三步在现有管理员页面加入客户端开关、模型/推理档筛选和默认值发布，后端统一生成
生效能力。前端下拉选项、预检与正式执行使用同一策略版本。

第四步按实际更新频率增加菜单能力发现和受控刷新。已有模板清单可自动导入平台，
逐步减少手工维护完整能力 JSON 的需求。

验收应覆盖以下场景。

- 旧模板只显示其自身版本支持的模型及推理档。
- 新模板增加模型后，旧批次和评分读取器继续使用原能力快照。
- 停用客户端或某模型后，新任务无法绕过 API 发起该配置。
- 模型的 High 可关闭而 Low 保留，默认值冲突会在发布时显示。
- 切换评分模板后，执行模板保持原绑定，评分按新模板校验。
- 外部 v1 文件、无外部文件和历史冻结批次均能按各自契约运行。

## 第一期实施结果

平台新增客户端执行/评分开关、模板能力详情、单模板能力清单导入、模型/推理档及
场景筛选、执行/评分默认模型、发布预览和配置修订记录。现有“AgentCube 模板”页面
提供这些管理操作。首次选择默认模板时，会保存控制器修订匹配的能力快照。

模型候选按模板快照定位，控制器修订不匹配时需要导入对应版本清单。导入一个模板的
能力不会替换其他客户端。元数据状态与实机验证分开展示，后续能力发现功能继续按需扩展。

预览和正式创建都在后端校验开放范围。已管理模板的未列出模型透传路径也受此范围约束。
发布使用版本号和来源摘要防止覆盖并发变更，新批次创建时锁定所用配置版本。

批次执行器和评分读取器保存完整生效 profile。子进程通过独立文件加载冻结能力，
复用执行器原有 `WCB_E2E_CAPABILITIES_FILE` 接口。历史操作按保存的能力继续运行，
原来未保存此字段的操作继续使用其原读取路径。

数据库迁移为平台 `2f6d8b9a710c`。上线时先由 CICD 发布新版 backend，再发布
eval-web，框架默认能力来自 `817f570c` 及后续发行。
页面操作验证使用隔离测试数据库和执行器元数据夹具，覆盖开关、模型关闭、推理档移除、
发布预览、保存结果和审计记录。真实沙箱验收由部署后的执行预检和正式用例另行确认。
