## 1. 阅读和更新规则

新会话先读接续入口，仅按当前事项查本文的验收项和对应 Skill。状态使用 `TODO / IN_PROGRESS / BLOCKED / DONE / DEFERRED`；技术验收使用 `NOT_RUN / PASS / FAIL / BLOCKED / NA`。代码实现、离线测试、真机闭环和生产范围分别记录，不能由一个 DONE 推导全部平台 PASS。

每项证据保留验收 ID、日期、源码与包身份、batch/unit/task/attempt、结论和本地产物位置。修复后追加记录，保留失败与原 revision；大型轨迹不入 Git。新客户端先单槽完成执行至报告，未声明的并发和 Windows 不阻塞当前范围准入。

开发串行不取消评测运行期的 UI/attempt 锁、进程隔离和候选冻结。题目 `timeout_seconds` 不限制 Harness 总执行时长，也不参与评分；基础设施和评分控制 deadline 独立保留。

新增或继续 G7 等 Harness 接入任务，必须按[统一接入契约 0.2 第 1.9/1.10 节](../e2e/端到端自动化评测Harness接入契约.md#hardening-matrix)纳入加固实现和验收。每个客户端在自己的现有记录中覆盖 CV01–CV17 与 GV01–GV08；基础安全项必做，并发/无人值守按声明层级触发，自动化结果与真机结果分开。不得把 AstronStudio 的 MAC PASS 复制给其它 Harness，不得因正常小批跑通而遗漏故障验证。当前文档由人工审核完成条件，没有统一自动符合性校验器。
