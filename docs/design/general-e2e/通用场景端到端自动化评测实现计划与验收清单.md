## 1. 阅读和更新规则

Windows 验证人员先读顶部状态、任务清单、平台矩阵及“Windows 接手清单”，再选择已有发行包执行。恢复已有批次时必须先查本地运行状态，不重新初始化任务。

任务状态统一使用 `TODO / IN_PROGRESS / BLOCKED / DONE / DEFERRED`；平台验收统一使用 `NOT_RUN / PASS / FAIL / BLOCKED / NA`。`DONE` 要有任务本身的交付物和验收证据；代码 DONE 不自动令任何真机单元 PASS。`NA` 必须写依据，不能用于跳过失败。

每条更新至少保留：任务/验收 ID、时间和时区、执行人或控制任务 ID、代码 revision、Skill/组件版本与 SHA、batch/unit/task/attempt、结论、证据位置、未完成项和下一步。修复后新增验证记录，保留失败历史；版本升级后说明哪些旧证据仍有效、哪些需要重验。

不要只写“已跑通”。文档中的当前快照可以更新，底部验证日志按时间追加。多机修改按不同任务 ID 更新，合并时不能用一台机器较新的时间戳覆盖另一台机器的失败记录。本文保存小型结论和相对证据索引，大型原始轨迹保留在结果包/制品库中。
