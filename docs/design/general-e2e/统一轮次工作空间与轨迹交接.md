# 统一轮次工作空间与轨迹交接

## 根目录与身份

评测根目录是运行参数，不是源码常量。未传 `--round-root` 时，使用控制 Harness 会话项目的当前工作目录；显式传入时，使用该路径。调用 Skill 使用绝对脚本路径，不先 cd 到 Skill 安装目录。路径可包含空格。

轮次、批次、发行和 attempt 是不同身份。目录以一轮和 Harness 为稳定边界；框架修复、单题重试或补评分不新建一套四端批次。新 attempt 保留来源版本、旧 attempt 和显式选择，不能覆盖发送不明的原 attempt。数据集、题目或被评配置真正变化时才建立新的评测轮次。

```text
<round-root>/
  AstronStudio/                 # WorkBuddy、QwenWork、DoubaoWork 同构
    execution/tasks/<task_id>/  # PROMPT.md + workspace/
    score/tasks/<task_id>/
      workspace/               # 当前评分运行副本；历史归档指向冻结候选
      private-scoring/         # 当前评分的私有标准入口
      trace/                   # 标准轨迹、原始日志和索引
      attempts/<attempt_id>/   # 稳定入口，指向本单元内部的完整评分 attempt
      current                  # 相对入口；不会自动覆盖旧选择
    score/.orchestrations/     # 编排状态及实际独立评分目录
    .general-e2e/              # 队列、回执、版本修复与状态
  reports/
  deliverables/
  .general-e2e/               # 清单、原包缓存、审计、运行时缓存
```

工作空间准备不清空控制项目。已接收的 ZIP 和用户 README 保留；输出目录冲突会拒绝覆盖。单独接收 execution ZIP 时可逐端 `install-unit`，评分 ZIP 与报告配置可在执行结束后再提供。

## 新评分任务的证据闭包

`score-general-e2e/scripts/trace_handoff.py` 在 prepare 阶段读取正式执行记录绑定的 trace-index，校验 identity/session、每个原件的 SHA/大小和标准轨迹路径，然后将标准轨迹、原始会话、绑定证据及 trace-index 复制进本题 attempt 的 `trace/`。macOS 使用文件系统克隆复制；不链接回原执行目录，不复制整个客户端数据库。

`attempt-manifest.json.trace_bundle` 固定交接清单的 SHA。`verify` 检查全部原件，以及评分实际读取的 `private/transcript.jsonl` 与 trace 中标准轨迹的一致性。`prepare-rescore` 传递同一冻结 trace 包。评分规则继续消费标准 transcript；语义目录增加 `raw_trace` 和 `trace_index` 条目，可通过 catalog + file 分页读取原件。API Judge 只纳入有明确节选标记的有界文本，不将未读部分当成不存在。

新轮次由 `.general-e2e/round-unit.json` 标记，编排 prepare 必须有 trace 包。旧单元显式沿用 legacy 模式，以便验证历史证据；经审核的失败产物契约可保留“原评分没有 transcript”的事实，不伪造轨迹或把后补材料标为原裁判已读取。

## 已完成轮次迁移

`archive_round.py import-final` 首先验证最终 ZIP 的成员、类型和 SHA，再按最终逐题索引映射到四个 Harness。原候选进入 execution/tasks；原评分 attempt 保持字节不变并进入 score/tasks；执行轨迹与后补轨迹分别进入 `trace/as-executed`、`trace/supplemental`。每题 `evidence-selection.json` 明确原评分轨迹和后来有效轨迹。

迁移清单保存每个原归档路径、新路径、大小与 SHA。`verify` 核对全部映射及执行/评分身份。`replay` 使用保留的最终 ZIP 和冻结批次配置，在内部临时目录重建报告输入，调用报告 Skill 重新计算，再比较所有分数、资源、工具明细及 attempt 身份；不读取被删除的历史控制目录。

评分候选的只读权限在归档视图恢复，原始ZIP与所有文件字节保持不变。case 下的 workspace、private-scoring、current 为内部相对入口，不产生额外副本；新评分实际 attempt 自带 trace，可独立交接。历史 trace/as-scored 与 supplemental 分开标识。

归档视图的 kind 为 archived，不能通过 prepare-score 恢复成执行中的轮次。需要重新评分时创建明确的新 attempt，并记录新证据选择，不能改写原 score.json。

回传包过滤缓存时必须区分运行副本与冻结输入。candidate-original、private 和正式 evidence 下已被哈希锁定的文件完整保留，不按 __pycache__/.pyc 名称过滤。历史回传若遗漏这些文件，只能从原 attempt 中按原 manifest/候选清单逐文件匹配补回，保留独立补回回执；不能改写原哈希或分数来通过校验。

## 清理边界

先验证迁移、离线复算及当前 Skill 入口，再清理明确列出的旧根目录。保留最终 ZIP、迁移后的四端数据、同源报告、有效来源的冻结输入包、必要诊断与代码归并证据。旧队列只留审计，不恢复。新发现运行进程、未知目录、变化中的文件或 Git 工作树时停止相应清理；不跟随符号链接删除外部目标。

清理回执记录前后 du/df、保留项、删除项及验证结果。APFS 克隆副本可能共享物理块，目录占用之差不能直接当成实际释放空间。活动 Skill 目录必须先迁移并原子更新发现链接，不能随旧临时目录删除。
