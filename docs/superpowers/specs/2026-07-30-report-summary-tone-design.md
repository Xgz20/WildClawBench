# 领导版报告控制变量总结文风设计

## 目标

领导版报告的控制变量总结应帮助读者快速理解整体格局、已有基础、差距集中位置和下一步方向，不把表格数字改写成逐项排名，也不使用过硬的贬低性表达。

## 适用范围

调整以下内容：

- 分类、Agent 能力、难度等级、模态四个维度的总判断；
- 每个维度下“固定目标 Harness：模型对比”的总结；
- 每个维度下“固定目标模型：Harness 对比”的总结；
- 总览和评测结论中与目标模型、目标 Harness 定位有关的同类表达。

不调整指标、表格结构、有效性门禁、典型案例证据和责任边界。

## 总结结构

每个控制变量视图最多两句话：

1. 先说明已有优势、接近项或相对稳定项，再指出差距集中在哪些场景或能力。
2. 给出模型侧或 Harness 侧的优先方向；没有直接根因证据时使用“优先排查”。

固定目标 Harness 时，先判断目标模型在哪些维度与参照模型接近、已具优势或已有基础，再说明主要提升空间。固定目标模型时，先判断不同 Harness 在哪些维度表现接近，再指出对 Harness 选择较敏感的维度。

## 数字使用

- 数字用于支撑判断，不承担整段叙述。
- 每个总结保留 0–2 个关键数字，只有确有必要时使用第 3 个。
- 优先使用分差、区间或“分差在 5 分以内”等概括，避免逐项复述表格。
- 单样本结果必须提示样本限制，不能据此判断稳定优势。

## 语气

优先使用：

- 已有一定基础；
- 与参照模型处于同一水平区间；
- 整体较为接近；
- 差距主要集中在；
- 仍处于追赶阶段；
- 有较明确的提升空间；
- 对模型或 Harness 选择较敏感；
- 可优先补充或优先排查。

避免使用：

- 排名末位；
- 全面落后；
- 均未达到；
- 整体偏弱；
- 明显落后；
- 短板覆盖全部场景；
- 不具竞争力。

有效性门禁和已确认故障仍需准确、直接表述，不进行语气弱化。

## 示例

固定 AstronCode 的分类总结：

> Spark-X2-300B 在安全对齐任务上与参照模型处于同一水平区间，并形成一定优势；当前差距主要集中在通用任务，社交互动与头部模型的距离最明显。模型侧可优先补充多轮意图理解、角色约束保持和交互结果校验。

固定 Spark-X2-300B 的分类总结：

> 除社交互动外，两个 Harness 在生产力、代码、检索、创意和安全任务上的分差均在 5 分以内，整体较为接近；社交互动对 Harness 选择较敏感。AstronCode 可优先排查多轮状态保持、工具调用续接和回合收尾策略。

## 验证

- Skill 和模板包含“先格局与亮点、后集中差距”的明确规则；
- 当前领导版报告的四个维度均按该结构改写；
- 每个控制变量总结不超过两句话，不逐项报分；
- 禁用硬评价不出现在能力结论中；
- 所有判断仍能由对应控制变量表或根因案例支撑。
