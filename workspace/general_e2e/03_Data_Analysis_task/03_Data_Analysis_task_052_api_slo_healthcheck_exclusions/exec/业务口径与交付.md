# API服务可用性与延迟SLO核验：业务口径与交付

## 1. 资料与范围
这是一套可复现的模拟数据，用于评测，不代表真实个人、企业、政策或科学结论。所有主记录均在处理范围内。
`主记录.xlsx`的第一批、第二批均有有效数据，标题、分页说明、空行和重复表头不是明细。`关联资料.xlsx`的版本记录给出关联对象的版本历史，资料说明为范围解释。
所有计数、金额、比率和日号均为数值；记录ID、关联ID、分组是文本。
- 主记录第1项：请求总数。
- 主记录第2项：失败请求数。
- 主记录第3项：P95延迟_ms。
- 主记录第4项：健康检查请求数。
- 关联字段第1项：健康检查失败数。
- 关联字段第2项：允许失败比例。
- 关联字段第3项：延迟门槛_ms。
- 关联字段第4项：服务序号。
序号、类别和标记仅按说明使用，不按名称模糊匹配。标记字段1表示是、0表示否。主记录ID定义一个分析单位；同ID字段完全一致的重复导出仅算一次，所有重复源位置都保留。不同ID即使数值相同也不能合并。

## 2. 关联、版本和缺失
主记录按关联ID准确关联。只考虑录入日≤90的关联版本，取版本号最大的一版；同版重复行合并来源。若采用版已撤回，状态为关联已撤回，不回退旧版；找不到截止前版本为缺关联。两者均不能猜填，指标留空。
任一主记录业务数值字段为空时状态为字段缺失，指标均留空。
本题分组指标采用完整资料记录口径。缺关联、关联撤回或关键字段缺失的记录保留在明细中，但不纳入本轮核定指标；这里的留空表示未核定，不是在断言所有可独立计算的中间量都不可知。可在分析中补充已知中间量，但不能将其混入完整资料口径的汇总。
判定优先级依次为缺关联、关联已撤回、字段缺失、本题特殊状态、可计算。缺失、不适用和确认零要区分；没有完成读取不等于输入没有记录。关联ID缺失而名称相似时也不得强配。

## 3. 计算与解释
每条为服务一个独立观测窗口，P95为源系统全部请求（含健康检查）的延迟分位数。业务请求=总请求−健康检查，业务失败=总失败−健康检查失败；可用率=1−业务失败/业务请求；失败预算剩余=业务请求×允许失败比例−业务失败（可为负，不取整）。业务请求0时可用率未知而预算剩余0。分组可用率是窗口均值，不称请求加权可用率；分析还须依据原始P95及门槛讨论至少一个延迟超标窗口，不能把错误率和延迟混为同一指标。
两项指标按上述顺序交付：`业务请求可用率`、`失败预算剩余额度`。公式要求金额到分的，在每条记录最后一步四舍五入（半入）；其他结果到小数点后6位。分组汇总基于已经按上述精度保存的逐条结果，分别采用非空值算术均值、求和，再到6位。空分母输出未知，不用0替代；全部未知的分组汇总也未知。有效数分别统计各指标非空条数，不等于可计算状态条数。
状态不是可计算的记录两项指标均为空。状态可计算但个别指标不适用或观察不足时，只留空该项；对应缺口原因依本题规则填写。缺口清单每个空指标一行，本题可能出现的原因包括：关联已撤回、字段缺失、缺关联、零业务请求分母。非空指标不进入缺口清单。

## 4. 交付
在`/tmp_workspace/results/`交付`分析结果.xlsx`与`分析说明.md`。
工作簿包含三张工作表，字段如下（允许行列重排，表头使用所列字段名；同一主键只能有一行）：
- `计算明细`：记录ID、分组、关联ID、采用版本、状态、业务请求可用率、失败预算剩余额度、主记录来源、关联来源。
- `分组汇总`：分组、主记录数、可计算记录数、非可计算记录数、业务请求可用率有效数、业务请求可用率汇总、失败预算剩余额度有效数、失败预算剩余额度汇总。
- `缺口清单`：记录ID、指标、原因、主记录来源、关联来源。
主记录来源写作`主记录.xlsx!工作表!R行号`；关联来源写作`关联资料.xlsx!版本记录!R行号`，仅列采用版本的全部来源，找不到关联时留空。多个位置用英文分号连接，顺序不限。采用版本为选中的版本号，找不到时为空。
分析说明分别对两个指标给出一项有数字、有分组和结果字段定位的比较结论；各提出一条由该结论支持的复核或处理建议。说明至少一种实际存在的数据缺口的数量和影响，以及本题统计不能支持的结论。另指出至少一个P95延迟超过门槛的原始窗口及其来源，延迟和失败预算分开解释。
这些是结果要求，不限定工具、算法、解题步骤或唯一实现路线。
