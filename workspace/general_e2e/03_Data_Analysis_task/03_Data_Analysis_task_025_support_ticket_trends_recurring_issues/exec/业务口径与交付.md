## 2. 计算与判定口径


1. Q2为2026-04-01至06-30，Q3为07-01至09-30，截止2026-10-01 00:00，统一北京时间。全量工单和补录均在范围，工单ID相同的重复导出只计一次。等级按创建时最新生效的客户等级绑定。工单总量含未解决工单，不能仅按有满意度工单计数。

2. 月度产品×问题类型统计工单数，产品占比以当季度全部工单为分母，Q3环比=(Q3-Q2)/Q2。提交频率=Q3等级工单数/该等级Q3在服客户日数×1000，单位为每千客户日；不能用提交过工单的客户数代替。

3. 首次响应和最终解决时长均为自然经过小时；仅最终解决时间存在、状态已解决且时序合法者进入解决时长统计。未解决不记0。用双侧Welch t检验比较企业与非企业的已解决时长，报告样本量、均值、t、自由度、p。为统一复核，统计量采用样本方差ddof=1，p保留至少6位有效数字；显著不等于有业务因果。

4. 满意度相关用Q3已解决且评分、两种时长均有效的同一成对样本，计算Spearman相关，分别报告响应时长和解决时长的系数、p及n。缺评分不得补均值或0。顽疾定义为Q3同客户ID+产品+问题类型的独立工单数>3，列工单ID集合、数量及已解决数量；重复提交提示需要调查，不能单凭计数断言既有方案无效。

5. 发布关联按每次发布前7天（不含当日）和自发布日起7天分别统计该产品的工单数与日均差，两窗口均为7天，不把月总量直接对比日窗口。报告主要问题的月度变化、可能关联的版本、统计限制与改善优先级。


## 3. 结果工作簿


将完整结果保存为 `/tmp_workspace/results/客服工单分析.xlsx`。下列sheet与表头作为复核接口；允许增加字段、说明或图表，行列顺序不影响验收。可用数值或带有效缓存的公式，数值显示精度不能改变底层含义。


- **季度概况**：产品、Q2工单数、Q3工单数、环比、Q2占比、Q3占比。

- **月度趋势**：月份、全部工单、协作台、数据云、移动端。

- **月度交叉**：月份、产品、问题类型、工单数。

- **客户分层**：等级、问题类型、工单数、等级工单数、客户日数、每千客户日工单数、类型占比。

- **时长检验**：比较、企业样本数、其他样本数、企业均值、其他均值、t、自由度、p。

- **满意度相关**：因素、样本数、Spearman、p。

- **顽疾清单**：客户ID、产品、问题类型、工单数、已解决数、工单集合。

- **发布窗口**：发布ID、产品、版本、前7天工单数、后7天工单数、日均差。

- **工单明细**：工单ID、客户ID、产品、问题类型、月份、季度、等级、响应小时、解决小时、满意度、来源。


缺失数值留空或明确标“未知”，不得以0代替。来源使用“文件名|sheet名|A起始行:末列结束行”，多个实际来源以分号分隔，顺序不限。来源应指向输入中的真实行；分析明细可追加复核所需字段。数值容差：人民币金额0.01元，其余指标1e-5（记录数、ID及状态须精确）；统计结果建议保留6位有效数字。若自选统计表达或复杂公式无法自动提取，应保留可读数值供复核，评测提取故障不等于业务错误。


## 4. 分析报告


报告应覆盖整体和产品趋势、发布窗口关联、客户提交频率、企业处理时长检验、满意度相关及顽疾清单。工作簿包含Q2至Q3逐月总量与产品线的趋势曲线，曲线与月度趋势表一致。区分统计关联与原因判断。

报告保存在 `/tmp_workspace/results/分析报告.md`，引用具体业务对象和数据依据，交代缺口对结论的影响。
