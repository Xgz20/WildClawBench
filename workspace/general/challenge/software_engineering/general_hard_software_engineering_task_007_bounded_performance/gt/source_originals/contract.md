# Matching contract

Implement `match_records(queries, catalog)` in `project/matcher.py`. Only that file may change. All other inputs are immutable; new reports belong under `results/`.

The arguments are finite read-only sequences supporting len, iteration, indexing and slicing. A query/record has `.id` (its query_id/record_id) and `.key(kind)` for `email`, `phone`, or `name_region`. Keys are normalized, immutable opaque hashable/equality-comparable values; absent keys are None. Key hash values may collide and are not identities. Do not access private storage, introspect objects, reset counters or substitute raw fixtures.

Email/name/region normalization trims ASCII whitespace and lowers ASCII A-Z only. Non-ASCII case is preserved. Phone removes ASCII space, + - ( ) . and ASCII whitespace; the remaining nonempty string must contain ASCII digits only. Leading zeros remain. A name_region key exists only when both components are nonempty. The trusted instrumentation implementation is readable and protected.

For each query, try email then phone then name_region. A nonempty criterion with no matches falls through. The first criterion with any matches wins; return all its catalog record IDs in catalog order, including duplicates. Preserve every query and query order even when query IDs repeat. Unmatched rows use matched_by="unmatched" and row_ids=[]. Output is a JSON-equivalent list/tuple of objects with exactly query_id, matched_by and row_ids. Row IDs are strings. Do not mutate inputs or carry cached views across calls.

The work profile counts actual catalog_visits, query_visits, key_probes, key_hashes, key_equalities and id_reads owned by the trusted side. Copying sequences retains opaque keys; comparisons inside list.index/count still invoke Key equality. Work is their sum. Dataset preparation/normalization and serialization are outside this matching-core measure. This is a bounded logical-work measure, not a complete CPU, memory or native-operation model.

For equivalent-output workload cases, total_work must be at most 32*(n+q)+4*m+128, where n and q are input lengths and m is the independently computed number of output record IDs. It is a broad linear allowance, not an exact reference count. Elapsed time is information only and never a capability threshold. No threads are required. An independent generous infrastructure timeout/stop-work ceiling protects replay and cannot be presented as a measured elapsed-time failure.

Pure replay profile: module functions, helper functions, imports from collections/itertools/functools (and future annotations), immutable literal module constants and function-local data structures. No classes/decorators/global or nonlocal state, mutable/dynamic defaults, private/reflection attributes, dynamic string format field traversal, IO/network/process/interpreter operations. A legitimate implementation outside this declared supported profile produces a typed unassessed result, not invented candidate zero. The profile is not an OS security sandbox.

Run public tests with `python -B -m unittest discover -s tests_public`. Produce the actual before/after report with `python -B benchmark.py --matcher project/matcher.py --output results/benchmark.json`. The command reloads a fresh function and fresh views per case. `baseline_matcher.py` is the immutable original. Report case and JSON field order, UTF-8 BOM, uppercase hex and equivalent integer notation are allowed; fixed required public case IDs are not diluted by padding. Preserve actual equivalent true/false and error status; do not fabricate counts or timings.

Write `results/review.md` with free-form tradeoffs and limitations, plus one fenced JSON summary containing algorithm_family (descriptive nonempty text), before_source_sha256, after_source_sha256, public_case_ids, work_measure="h047-counted-keys/v1", wall_time_is_gate=false and threads_required=false. Benchmark counters/output/source/fixture hashes are independently replayed. This schema does not prove the prose reasoning or a real Harness action trace.
